Accept files from users without opening security holes, send them back as downloads or images, and send real-looking emails with attachments – tested for free with Mailpit.

1. Why this matters

Almost every real application handles files and emails:

  • Uploads: profile pictures, product photos, CVs in a job portal, scanned KYC documents in a bank, CSV imports of price lists.
  • Downloads: invoices, reports, exported Excel/CSV files, images in a product page.
  • Emails: "Confirm your email address", "Reset your password", "Your order has shipped", "Here is your invoice (PDF attached)".

File upload is also one of the most attacked features on the web. A careless upload endpoint lets an attacker overwrite your files, read secret files from the server, fill the disk, or host malware on your domain. In this lesson you will build it the safe way from the start – the same way senior developers do it at work.

2. Real-life analogy

🧳 The hotel luggage room You hand your bag to the hotel's luggage room.
  • The staff do not store it under the name you wrote on your tag ("put it in the manager's office!"). They give it their own numbered ticket and put it on their own shelf → we never use the client's filename as a path; we create our own safe, unique name.
  • They check what's inside: no fuel cans, no animals → whitelist of allowed file types.
  • There is a weight limit → maximum upload size.
  • Bags are kept in the back room, not displayed in the lobby → files are stored outside the public web folder.
  • When you come back, you show the ticket and get your bag → download by stored name.
📮 Email is the post office. Your app writes a letter (the message), puts it in an envelope with an address (headers), maybe adds a parcel (attachment), and hands it to the post office (an SMTP server) which delivers it. Mailpit is a toy post office in your own room: it accepts every letter and pins it on a board for you to read – nothing ever leaves the house. Perfect for practising.

3. Concepts step by step

3.1 How a file travels: multipart/form-data

JSON is great for text, but not for files. To send files, browsers use the content type multipart/form-data: the request body is split into parts, separated by a random "boundary" line. Each part has its own little headers. This is what one upload looks like on the wire:

POST /api/files HTTP/1.1
Content-Type: multipart/form-data; boundary=CourseBoundary

--CourseBoundary
Content-Disposition: form-data; name="file"; filename="hello.txt"
Content-Type: text/plain

Hello from Topic 54!
--CourseBoundary--
  • name="file" – the name of the form field. Your controller asks for this name.
  • filename="hello.txt" – the name on the user's computer. The user controls this text – never trust it.
  • Content-Type: text/plain – also set by the client. It can lie too.

In HTML, a form must say enctype="multipart/form-data" for this to happen:

<form action="/api/files" method="post" enctype="multipart/form-data">
    <input type="file" name="file">
    <button type="submit">Upload</button>
</form>

Spring Boot's web starter already includes multipart support. Tomcat reads the parts and Spring hands each file to you as a MultipartFile.

3.3 Uploading one file

web/FileController.java@PostMapping(consumes = MediaType.MULTIPART_FORM_DATA_VALUE)
public ResponseEntity<StoredFile> upload(@RequestParam("file") MultipartFile file) {
    StoredFile stored = storageService.store(file);
    return ResponseEntity.status(HttpStatus.CREATED).body(stored);
}
  • consumes = MULTIPART_FORM_DATA_VALUE – this endpoint only accepts multipart requests.
  • @RequestParam("file") – take the part named file. If it is missing, Spring answers 400.
  • The controller stays thin; the service does the careful work.

With curl, -F builds a multipart request for you (@ means "read this file"):

curl -F "file=@sample-files/hello.txt" http://localhost:8080/api/files
ℹ️ File + JSON in one requestSometimes you need a file plus data (e.g. a product JSON and its photo). Use @RequestPart: create(@RequestPart("product") ProductDto product, @RequestPart("image") MultipartFile image). The JSON part must be sent with Content-Type: application/json.

3.4 Uploading many files

The client sends several parts with the same name. Spring collects them into a list (or array):

@PostMapping(path = "/batch", consumes = MediaType.MULTIPART_FORM_DATA_VALUE)
public ResponseEntity<List<StoredFile>> uploadMany(@RequestParam("files") List<MultipartFile> files) {
    return ResponseEntity.status(HttpStatus.CREATED).body(storageService.storeAll(files));
}
curl -F "files=@sample-files/hello.txt" -F "files=@sample-files/prices.csv" http://localhost:8080/api/files/batch

In HTML: <input type="file" name="files" multiple>.

3.5 Size limits

Without limits, someone can upload a 50 GB file and fill your disk or memory. Spring Boot has sensible defaults (1 MB per file, 10 MB per request). Set your own:

application.propertiesspring.servlet.multipart.max-file-size=5MB        # one file
spring.servlet.multipart.max-request-size=20MB    # all files + fields together
spring.servlet.multipart.file-size-threshold=512KB # bigger files go to a temp file instead of memory
server.tomcat.max-swallow-size=50MB               # see the warning below

Too big → Spring throws MaxUploadSizeExceededException. We turn it into a clean 413 Payload Too Large:

web/GlobalExceptionHandler.java@ExceptionHandler(MaxUploadSizeExceededException.class)
public ProblemDetail tooLarge(MaxUploadSizeExceededException ex) {
    ProblemDetail problem = ProblemDetail.forStatusAndDetail(HttpStatus.PAYLOAD_TOO_LARGE,
            "File too large. Maximum size per file is 5 MB, per request 20 MB.");
    problem.setTitle("Upload too large");
    return problem;
}
⚠️ "Connection reset" instead of 413?When an upload is too large, Tomcat stops reading it. If more than max-swallow-size (2 MB by default) is still unread, Tomcat may close the connection, and the client sees "connection reset" instead of your nice 413 JSON. Raising server.tomcat.max-swallow-size fixes this. (Behind a proxy like Nginx, also check its own limit, e.g. client_max_body_size.)

3.6 Storing files safely – the threats

Here is what can go wrong when you store uploads naïvely, e.g. file.transferTo(Path.of("uploads/" + file.getOriginalFilename())):

ThreatExampleDefence
Path traversalfilename ../../app/config/application.properties overwrites your configStrip folders from the name; after resolving, check the path is still inside the upload folder
Overwriting other users' filesTwo users upload photo.jpgUnique names (random prefix / UUID)
Dangerous typesevil.html or evil.svg with JavaScript, .exe, .jspWhitelist of extensions; never serve uploads as HTML; X-Content-Type-Options: nosniff
Lying content typeA script sent as Content-Type: image/pngDecide the type yourself (from the extension, or better from the file's first bytes)

Strange characters<script>.txt, very long names, names like CON on WindowsAllow only [a-zA-Z0-9._-], limit length

MalwareAn infected PDF passed on to other usersIn serious systems: virus scanning (e.g. ClamAV) before accepting

Path traversal, explained simply

.. means "the parent folder". If your upload folder is D:\app\uploads and you blindly join it with the name ..\..\Windows\win.ini, the result D:\app\uploads\..\..\Windows\win.ini really means D:\Windows\win.ini. An attacker escapes your folder. The same trick works on downloads to read secret files.

uploads+ "../../Windows/win.ini" → uploads/../../Windows/win.ininormalize() → /Windows/win.ini 😱 outside!

The guard: build the path, normalize() it (which resolves the .. parts), and check that its parent is exactly the upload folder:

storage/FileStorageService.javaprivate Path resolveSafely(String filename) {
    Path target = rootLocation.resolve(filename).normalize();
    if (!target.getParent().equals(rootLocation)) {
        throw new StorageException("Invalid file name (outside the upload folder): " + filename);
    }
    return target;
}

Sanitizing the filename

static String sanitizeFilename(String originalName) {
    String cleaned = StringUtils.cleanPath(originalName);   // "\" -> "/", resolves "a/../b"
    String nameOnly = StringUtils.getFilename(cleaned);     // keep only the part after the last "/"
    String safe = nameOnly.replaceAll("[^a-zA-Z0-9._-]", "_"); // anything unusual -> "_"
    safe = safe.replaceAll("^\\.+", "");                   // no ".hidden" files
    ...
}

Then: check the extension against the whitelist, add a unique prefix, resolve safely, and copy the stream:

3.7 Where should files live?

OptionProsConsWhen
Local disk (this lesson)Simple, fast, freeLost if the server/container is replaced; not shared between several instancesLearning, single server, with a mounted volume
Database (BLOB column)Backed up with the data, transactionalDB grows fast, slower, expensiveSmall files, few of them
Object storage (Amazon S3, Azure Blob, Google Cloud Storage, MinIO)Unlimited, cheap, durable, shared, CDN-friendlyExtra service and SDKMost production systems

A common pattern: store the file in object storage and keep only its metadata (stored name, original name, size, owner, upload date) in a database table. Because our FileStorageService hides where files go, switching to S3 later only changes that one class.

3.8 Downloading files

To send a file back, return a ResponseEntity<Resource>. A Resource is Spring's abstraction for "something you can read" – a file, a classpath entry, a URL. Spring streams it to the client in chunks, so even a 1 GB file does not fill your memory.

web/FileController.java@GetMapping("/{filename}")
public ResponseEntity<Resource> download(@PathVariable String filename) {
    Resource resource = storageService.loadAsResource(filename);
    ContentDisposition disposition = ContentDisposition.attachment()
            .filename(FileStorageService.originalNameOf(filename), StandardCharsets.UTF_8)
            .build();
    return ResponseEntity.ok()
            .contentType(storageService.mediaTypeOf(filename))
            .header(HttpHeaders.CONTENT_DISPOSITION, disposition.toString())
            .body(resource);
}

The Content-Disposition header tells the browser what to do:

HeaderBrowser behaviour
attachment; filename="invoice.pdf"Shows "Save as…" / downloads the file with that name
inline; filename="photo.png"Tries to show it in the tab (images, PDFs)

Real header from our app:

Content-Disposition: attachment; filename="=?UTF-8?Q?hello.txt?="; filename*=UTF-8''hello.txt
Content-Type: text/plain

The filename*=UTF-8''… form (RFC 6266) allows names like résumé.pdf or चालान.pdf; Spring builds it for you when you pass a charset.

Content type: we decide it ourselves from the extension with MediaTypeFactory.getMediaType(filename), falling back to application/octet-stream ("unknown binary – just download it").

3.9 Serving images

For an <img src="..."> tag, the browser needs the bytes with the correct Content-Type (e.g. image/png) and inline disposition:

web/FileController.java@GetMapping("/{filename}/view")
public ResponseEntity<Resource> view(@PathVariable String filename) {
    MediaType type = storageService.mediaTypeOf(filename);
    if (!INLINE_TYPES.contains(type)) {
        return download(filename);              // only images/PDF may be shown inline
    }
    return ResponseEntity.ok()
            .contentType(type)
            .header(HttpHeaders.CONTENT_DISPOSITION, ContentDisposition.inline()...build().toString())
            .header("X-Content-Type-Options", "nosniff")
            .header(HttpHeaders.CACHE_CONTROL, "max-age=3600")
            .body(storageService.loadAsResource(filename));
}
  • Whitelist of inline types: an uploaded .html shown inline would run its JavaScript on your domain (stored XSS).
  • X-Content-Type-Options: nosniff stops browsers from "guessing" a different type than the one you sent.
  • Cache-Control lets the browser reuse the image for an hour.
ℹ️ What about src/main/resources/static?Files in static/ (like our index.html) are served automatically at / – perfect for your own CSS, JS and logo, which are packed into the jar at build time. User uploads must never go there: the folder is inside the jar (read-only) and anything in it is public without checks.

3.10 Email basics

Email is sent with SMTP (Simple Mail Transfer Protocol). Your app connects to an SMTP server and hands over the message; the server delivers it. Common ports: 25 (server-to-server), 587 (submission with STARTTLS – the usual one for apps), 465 (SMTP over TLS). Mailpit uses 1025.

An email is a MIME message: headers (From, To, Subject) and a body that can contain several parts – plain text, HTML, attachments, inline images.

pom.xml<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-mail</artifactId>
</dependency>
application.propertiesspring.mail.host=localhost
spring.mail.port=1025
spring.mail.default-encoding=UTF-8
spring.mail.properties.mail.smtp.connectiontimeout=3000
spring.mail.properties.mail.smtp.timeout=3000
spring.mail.properties.mail.smtp.writetimeout=3000

When spring.mail.host is set, Spring Boot auto-configures a JavaMailSender bean. Inject it and send. Without spring.mail.host, there is no JavaMailSender bean, and any class that needs one fails at startup.

⚠️ Always set mail timeoutsBy default JavaMail waits forever for a slow mail server, blocking your request thread. The three mail.smtp.*timeout properties make it fail after 3 seconds.

3.12 HTML and attachments: MimeMessage + MimeMessageHelper

SimpleMailMessage cannot do HTML or attachments. For that, create a MimeMessage and fill it with the friendly MimeMessageHelper:

mail/EmailService.javaMimeMessage message = mailSender.createMimeMessage();
MimeMessageHelper helper = new MimeMessageHelper(message, true, "UTF-8");   // true = multipart
helper.setFrom(from);
helper.setTo(to);
helper.setSubject(subject);
helper.setText("Please open this email in an HTML-capable mail client.", html);  // plain fallback + HTML

Path file = storageService.pathOf(storedFileName);
helper.addAttachment(FileStorageService.originalNameOf(storedFileName), new FileSystemResource(file));

mailSender.send(message);
Helper methodPurpose
setText(html, true)HTML body only
setText(plain, html)Both versions; the mail client picks one (best practice)
addAttachment(name, resource)A file the user can download
addInline("logo", resource)An image shown inside the HTML with <img src="cid:logo">

The true in the constructor means "multipart" – required as soon as you add attachments or inline images. "UTF-8" keeps names like "Zoë" or "₹" intact.

3.13 Mailpit – a free fake mail server

You do not want to send real emails while developing (spam, accidental mails to customers, provider limits). Mailpit pretends to be an SMTP server, accepts everything, and shows the emails in a web inbox.

docker-compose.ymlservices:
  mailpit:
    image: axllent/mailpit:latest
    container_name: course-mailpit
    ports:
      - "1025:1025"   # SMTP  - the Spring Boot app sends here
      - "8025:8025"   # Web UI - open in your browser

(MailHog is an older tool that works the same way; Mailpit is its maintained successor.)

3.14 Sending real email in production

Use a provider: Amazon SES, SendGrid, Mailgun, Postmark, Brevo, or your company's SMTP relay (Gmail works for tests with an "app password"). Only the properties change:

spring.mail.host=smtp.sendgrid.net
spring.mail.port=587
spring.mail.username=${MAIL_USERNAME}
spring.mail.password=${MAIL_PASSWORD}          # from an environment variable - never commit secrets!
spring.mail.properties.mail.smtp.auth=true
spring.mail.properties.mail.smtp.starttls.enable=true

Two more production habits:

  • Send asynchronously – an SMTP call can take seconds. Combine with topic 52: publish a UserRegisteredEvent and send the mail from an @Async @TransactionalEventListener. For must-not-lose emails, use a queue (topic 57).
  • Use templates – build the HTML with Thymeleaf (topic 36) instead of string concatenation, and escape user data to avoid HTML injection.

4.1 FileStorageService – the safe store method

storage/FileStorageService.javapublic StoredFile store(MultipartFile file) {
    if (file == null || file.isEmpty()) {                                   // 1. something to store?
        throw new StorageException("Please choose a non-empty file");
    }
    String originalName = file.getOriginalFilename() == null ? "file" : file.getOriginalFilename();
    String safeName = sanitizeFilename(originalName);                       // 2. harmless name

    String extension = StringUtils.getFilenameExtension(safeName);          // 3. allowed type?
    if (extension == null || !allowedExtensions.contains(extension.toLowerCase(Locale.ROOT))) {
        throw new StorageException("File type not allowed: '" + originalName + "'. Allowed: " + allowedExtensions);
    }

    String storedName = UUID.randomUUID().toString().replace("-", "").substring(0, 12) + "_" + safeName; // 4. unique
    Path target = resolveSafely(storedName);                                // 5. still inside uploads/?

    try (InputStream in = file.getInputStream()) {                          // 6. stream to disk
        Files.copy(in, target, StandardCopyOption.REPLACE_EXISTING);
    } catch (IOException e) {
        throw new StorageException("Failed to store " + originalName, e);
    }
    return toStoredFile(target);
}

The constructor turns app.storage.location=uploads into an absolute, normalized path and creates the folder with Files.createDirectories. loadAsResource and delete also go through resolveSafely, so the traversal check protects downloads too.

6. Common mistakes

🛑 Mistake: using getOriginalFilename() as the path 
file.transferTo(Path.of("uploads/" + file.getOriginalFilename()));   // path traversal + overwrite!
Fix: sanitize, add a unique prefix, resolve + normalize() + check the parent folder.
⚠️ Mistake: Required part 'file' is not present (400)The form field name does not match @RequestParam("file"), or the form is missing enctype="multipart/form-data".
Fix: same name on both sides; in Postman choose Body → form-data, key type "File".
⚠️ Mistake: setting Content-Type: multipart/form-data by hand in JavaScriptWith fetch + FormData, the browser must add the header itself, including the boundary.
Fix: do not set the header; just pass body: new FormData(form) (see index.html).
⚠️ Mistake: "Maximum upload size exceeded" at 1 MBThe default limit is 1 MB per file.
Fix: spring.servlet.multipart.max-file-size / max-request-size, and handle MaxUploadSizeExceededException.
⚠️ Mistake: file.getBytes() for big filesA 500 MB video in a byte[] = 500 MB of heap per upload.
Fix: stream with getInputStream() + Files.copy, and return downloads as a Resource.
⚠️ Mistake: saving uploads into src/main/resources/staticIt works on your laptop by accident, but in a jar the folder is read-only, and uploads become public with no checks.
Fix: a configurable folder outside the app (or object storage).
⚠️ Mistake: No qualifying bean of type 'JavaMailSender'spring.mail.host is missing, so Spring Boot did not create the bean.
Fix: set spring.mail.host (and port) – e.g. Mailpit on localhost:1025.
⚠️ Mistake: MailSendException: Couldn't connect to host, port: localhost, 1025Mailpit is not running.
Fix: docker compose up -d and check with docker ps.
🛑 Mistake: committing the SMTP passwordspring.mail.password=MySecret123 in git is a leaked credential.
Fix: ${MAIL_PASSWORD} from an environment variable or a secret manager.
ℹ️ A surprise we hit while building this project: illegal unicode escape A comment in FileStorageService.java contained a Windows path like D:\Java-SpringBoot\...\uploads. The compiler failed with "illegal unicode escape"! Java processes \u followed by four hex digits as a Unicode character before anything else – even inside comments – and \uploads is not valid hex.
Fix: write paths with forward slashes in comments (D:/Java-SpringBoot/...), and use \\ in Java strings (or better, Path.of("D:", "folder")).

7. Best practices

  • Never trust the client: not the filename, not the content type, not the size it claims.
  • Whitelist allowed extensions (and ideally check the file's "magic bytes", e.g. with Apache Tika). Never allow .html, .svg, .js, .exe, .jsp unless you really must.
  • Generate your own stored names and keep the original name only as metadata for display.
  • Always check the resolved path stays inside the upload folder – for uploads, downloads and deletes.
  • Set size limits in Spring, Tomcat and any proxy in front; return 413 with a clear message.
  • Stream large files in both directions; don't load them into memory.
  • Store outside the application: a mounted volume or, in most production systems, object storage (S3 and friends). Keep metadata in the database.
  • Check authorization on downloads: user A must not download user B's invoice just by guessing a name (store the owner and check it – topic 48).
  • Serve user content carefully: attachment by default, inline only for safe types, X-Content-Type-Options: nosniff.
  • Emails: set timeouts, send asynchronously, send both HTML and plain text, use templates with escaping, keep credentials in environment variables, and use Mailpit in development.

8. Key takeaways

  • Files are uploaded as multipart/form-data; Spring gives each file part to you as a MultipartFile.
  • Single upload: @RequestParam("file") MultipartFile; multiple: @RequestParam("files") List<MultipartFile>.
  • Limit sizes with spring.servlet.multipart.max-file-size/max-request-size; map MaxUploadSizeExceededException to 413.
  • Store safely: sanitize names, whitelist extensions, unique stored names, normalize() + parent check against path traversal.
  • Download with ResponseEntity<Resource> and Content-Disposition: attachment; show images with inline + correct content type + nosniff.
  • spring-boot-starter-mail + spring.mail.host → an auto-configured JavaMailSender.
  • SimpleMailMessage for plain text; MimeMessage + MimeMessageHelper(msg, true, "UTF-8") for HTML, attachments and inline images.
  • Use Mailpit (SMTP 1025, UI 8025) to test emails for free; use a real provider with env-var credentials in production.

Challenge

Check the real file type. Someone renames evil.exe to photo.png. Reject PNG uploads whose first bytes are not the PNG signature (89 50 4E 47).

Hint / solution
private static final byte[] PNG_MAGIC = {(byte) 0x89, 0x50, 0x4E, 0x47};

private void checkMagicBytes(MultipartFile file, String extension) throws IOException {
    if (!"png".equalsIgnoreCase(extension)) {
        return;
    }
    try (InputStream in = file.getInputStream()) {
        byte[] head = in.readNBytes(4);
        if (!Arrays.equals(head, PNG_MAGIC)) {
            throw new StorageException("File content is not a real PNG image");
        }
    }
}

Call it in store() after the extension check. For many types, a library like Apache Tika (tika.detect(inputStream)) does this for you.

Challenge

Email the uploader. Combine with topic 52: after a successful upload, publish a FileUploadedEvent, and send "We received your file" from an @Async listener so the upload response is not slowed down by SMTP.

Hint / solution
public record FileUploadedEvent(String storedName, String uploaderEmail) { }

// FileController (inject ApplicationEventPublisher)
StoredFile stored = storageService.store(file);
events.publishEvent(new FileUploadedEvent(stored.storedName(), email));   // email from a @RequestParam

// listener
@Component
public class UploadMailListener {
    private final EmailService emailService;
    public UploadMailListener(EmailService emailService) { this.emailService = emailService; }

    @Async
    @EventListener
    public void onUpload(FileUploadedEvent event) {
        emailService.sendSimpleEmail(event.uploaderEmail(), "We received your file",
                "Thanks! Stored as " + event.storedName());
    }
}

Remember @EnableAsync on a configuration class. There is no transaction here, so a plain @EventListener is right (a @TransactionalEventListener would never fire).

10. Interview questions

Q1. How do you upload a file in Spring Boot?

Send a multipart/form-data request; in the controller accept @RequestParam("file") MultipartFile file (or List<MultipartFile> for many, or @RequestPart for mixed JSON + file). Validate it, then store it via getInputStream()/transferTo. Multipart support is auto-configured by the web starter.

Q2. How do you limit the upload size?

spring.servlet.multipart.max-file-size and max-request-size. Exceeding them throws MaxUploadSizeExceededException, which you map to 413 in a @RestControllerAdvice. Also consider server.tomcat.max-swallow-size and limits in reverse proxies.

Q3. What is path traversal and how do you prevent it?

An attack where a filename or path parameter contains ../ sequences to escape the intended folder and read or overwrite other files. Prevent it by never using client names as paths, sanitizing names (strip directories, whitelist characters), generating your own names, and after resolve(...).normalize() verifying the result is inside the base directory.

Q4. Why shouldn't you trust getOriginalFilename() and getContentType()?

Both are sent by the client and can contain anything: paths, special characters, a fake type such as image/png for a script. Determine the type yourself (extension whitelist, magic bytes, Tika) and generate your own stored name.

Q5. How do you return a file for download?

Return ResponseEntity<Resource> (e.g. UrlResource/FileSystemResource) with the correct Content-Type and Content-Disposition: attachment; filename="..." (built with ContentDisposition, using filename* for UTF-8). Spring streams the resource without loading it fully into memory.

Q6. Difference between Content-Disposition inline and attachment?

inline asks the browser to display the content (images, PDFs) in the page/tab; attachment asks it to download/save the file with the given filename. For user-uploaded content, default to attachment and only allow inline for safe types, plus X-Content-Type-Options: nosniff.

Q7. Where would you store uploaded files in production?

Usually in object storage (Amazon S3, Azure Blob, GCS, MinIO) with metadata (owner, original name, size, type, key) in the database. Local disk only with a persistent, shared volume; database BLOBs only for small, few files. Avoid the application folder or static/.

Q8. How do you send an email with an attachment in Spring Boot?

Add spring-boot-starter-mail, configure spring.mail.*, inject JavaMailSender, create a MimeMessage, wrap it in new MimeMessageHelper(message, true, "UTF-8"), set from/to/subject/text (HTML with setText(plain, html)), call addAttachment(name, resource), then mailSender.send(message).

Q9. SimpleMailMessage vs MimeMessage?

SimpleMailMessage is a simple value object for plain-text emails (from, to, cc, subject, text). MimeMessage is the full JavaMail message supporting HTML, multiple parts, attachments, inline images and custom headers; MimeMessageHelper makes it easy to build.

Q10. How do you test email sending without sending real emails?

Use a local fake SMTP server such as Mailpit or MailHog (Docker), or GreenMail in automated tests; in unit tests, mock JavaMailSender with Mockito and verify send(...) was called. Never point development environments at a real provider with real customer addresses.
