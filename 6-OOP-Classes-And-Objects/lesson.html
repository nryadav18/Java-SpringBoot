1. Why this matters

Until now, our programs were a list of steps inside main with some helper methods. That works for small programs. But imagine writing an online shop with customers, products, carts, orders, payments and deliveries using only loose variables like customerName1, customerName2, productPrice7 … it becomes a mess very quickly.

Object-Oriented Programming (OOP) is a way of organizing code around things (objects) instead of steps. Each thing keeps its own data together with the actions that make sense for it:

  • A Customer object knows its name and email, and can updateEmail().
  • A Cart object knows its items, and can addItem() and calculateTotal().
  • An Order object knows its status, and can cancel().

Java is an object-oriented language — everything you build at work is classes and objects. In Spring Boot, your controllers, services, repositories and entities (like a Product saved in a database) are all classes. Spring itself creates and manages objects for you (they are called beans, Topic 22). So this topic is the foundation of everything ahead.

ℹ️ The 4 pillars of OOP (you will learn them over the next topics) Encapsulation (hide data, Topic 7) · Inheritance (reuse, Topic 7) · Polymorphism (one interface, many forms, Topic 8) · Abstraction (show only what matters, Topic 8). This topic teaches the basic building blocks they all rely on: classes and objects.

2. Real-life analogy

🏠 Blueprint vs house An architect draws a blueprint of a house: it says every house has rooms, a door colour, and a number of floors. The blueprint itself is not a house — you can't live in it.

From one blueprint, a builder can build many houses. Each house is real, takes up land, and has its own values: house #1 has a blue door, house #2 has a red door. Painting house #1's door doesn't change house #2.

In Java: the class is the blueprint, each object is a house, new is the builder, the constructor is the "move-in checklist" that runs once when the house is built, and the reference variable is the house's address written on a piece of paper — not the house itself.

3. Concepts step by step

3.1 Procedural vs object-oriented — a tiny comparison

Procedural style (data and actions are separate):

String carBrand = "Tata";
int carSpeed = 0;
carSpeed = accelerate(carSpeed, 30);   // we must pass the data around ourselves

Object-oriented style (data and actions live together):

Car car = new Car();
car.brand = "Tata";
car.accelerate(30);                    // the car changes its own speed

With 1 car, the difference is small. With 1,000 cars of 10 types, OOP is much easier to read, change and test.

3.2 Class vs object

An object is also called an instance of the class. "Creating an object" = "instantiating the class".

3.3 Anatomy of a class: fields and methods

Example01_ClassAndObject.java (part)class Car {
    // FIELDS = what a car KNOWS (state)
    String brand;
    String color;
    int speed;
    boolean isElectric;

    // METHODS = what a car can DO (behaviour)
    void accelerate(int amount) {
        speed = speed + amount;
    }

    void describe() {
        System.out.println("This is a " + color + " " + brand + " going at " + speed + " km/h");
    }
}
  • Fields (also called instance variables, attributes or properties) are variables declared inside the class but outside any method. Every object gets its own copy.
  • Methods (instance methods) can read and change the fields of the object they are called on.
  • Class names use PascalCase (BankAccount), fields and methods use camelCase (accountNumber, getBalance()).

3.4 Creating and using objects

Car myCar = new Car();      // 1. declare a variable  2. new builds the object  3. = stores its address
myCar.brand = "Tata";       // the DOT operator: "go to this object, then its field"
myCar.accelerate(30);       // "go to this object, then call its method"
Car myCar= new→ Car()→ object on heap

3.5 Constructors

Setting every field by hand after new is boring and risky (you might forget one). A constructor is a special block that runs automatically, exactly once, when the object is created. Its job: put the new object into a valid starting state.

Rules:

  • Same name as the class (including capital letter).
  • No return type — not even void. (If you write void Student(), it becomes a normal method by mistake!)
  • Called with new ClassName(arguments).

a) The default constructor

If you write no constructor at all, Java secretly adds an empty one with no parameters: Course() { }. This is called the default constructor. That is why new Car() worked in Example01.

⚠️ The disappearing default constructor As soon as you write any constructor yourself, Java no longer adds the default one. If you write only Student(String name), then new Student() will not compile. Add a no-argument constructor yourself if you need it.

b) Parameterized constructor and this

class Student {
    String name;
    int age;

    Student(String name, int age) {
        this.name = name;   // this.name = the FIELD of this object, name = the PARAMETER
        this.age = age;
    }
}

Student meera = new Student("Meera", 21);   // values go straight in

Inside the constructor there are two things called name: the parameter and the field. The parameter "hides" (shadows) the field. this means "the current object" — the one being built or the one whose method is running. So this.name is the field.

❌ Classic bug name = name; (without this.) assigns the parameter to itself. The field stays null. No error, just a silent bug!

c) Constructor overloading

Like method overloading (Topic 4), a class can have several constructors with different parameter lists. This gives callers convenient options:

new Student();                              // nothing known yet
new Student("Arjun");                       // only the name
new Student("Meera", 21, "Computer Science"); // everything

d) Constructor chaining with this(...)

To avoid repeating the same assignments in every constructor, one constructor can call another using this(...). The "biggest" constructor does the real work; the others just supply default values.

Example02_Constructors.java (part)Student() {
    this("Unknown", 18, "Not assigned");     // MUST be the first statement
}

Student(String name) {
    this(name, 18, "Not assigned");
}

Student(String name, int age, String department) {
    this.name = name;
    this.age = age;
    this.department = department;
}
new Student("Arjun")→ Student(String)→ this(...) → Student(String, int, String)

Two uses of this — don't mix them up:

SyntaxMeaningWhere allowed
this.field / this.method()The current object's field / methodAny instance method or constructor
this(...)Call another constructor of the same classOnly as the first line of a constructor

You can also pass this as an argument — e.g. target.receiveFrom(this) — to hand "myself" to another object.

3.6 References and memory: stack vs heap

Java uses two main memory areas while your program runs:

StackHeap
What lives thereLocal variables and method parameters (primitives and references)All objects (created with new) and their fields
LifetimeUntil the method returnsUntil no one references the object, then the garbage collector removes it
Size / speedSmall, very fastBig, managed by the JVM
AnalogySticky notes on your desk (thrown away when the task ends)A big warehouse of boxes

Look at this code and the picture:

int count = 5;
Person p1 = new Person("Kiran", 25);
Person p2 = p1;          // copies the ADDRESS, not the object

Consequence: changing the object through p2 is visible through p1: p2.age = 30; → p1.age is also 30. This is called aliasing — two names for one object.

Passing objects to methods (pass-by-value, again)

Remember from Topic 4: Java always passes a copy of the variable. For an object variable, the copy is a copy of the address. So:

  • The method can change the object's fields (it follows the address to the same object). → haveBirthday(p1) changes p1.age.
  • The method cannot make the caller's variable point to a new object (it only changes its own copy of the address). → tryToReplace(p1) has no effect outside.

null

null means "this reference points to no object". It is like an empty address slip. Calling a method or reading a field on null throws a NullPointerException (the most common Java error). Check with if (obj != null) when a value may be missing.

3.7 toString() — how an object describes itself

Every class automatically inherits a few methods from Java's built-in class Object (the parent of all classes — details in Topic 7). One of them is toString(), which System.out.println(obj) calls for you. The default version prints something like PlainBook@5ca881b5 — class name + a hex number. Not useful! So we override it (write our own version):

@Override
public String toString() {
    return "Book{isbn='" + isbn + "', title='" + title + "'}";
}

@Override is an annotation (a label for the compiler). It says "I am replacing an inherited method — please complain if I made a typo". public means "anyone can call this" (access modifiers come in Topic 9). Now println(book) prints readable text — very helpful for debugging and logging.

3.8 equals() and hashCode() — an introduction

The inherited equals() behaves exactly like ==: "is it the very same object?". Often we want business equality: "two books are the same book if they have the same ISBN", even if they are different objects in memory.

Example05_ToStringEqualsHashCode.java (part)@Override
public boolean equals(Object other) {
    if (this == other) return true;                          // same object
    if (other == null || getClass() != other.getClass()) {   // null or different type
        return false;
    }
    Book that = (Book) other;                                // cast to Book (Topic 8)
    return Objects.equals(isbn, that.isbn);                  // compare what matters
}

@Override
public int hashCode() {
    return Objects.hash(isbn);                               // SAME fields as equals
}

Why hashCode too? A hashCode is a number computed from the object's data. Collections like HashSet and HashMap (Topic 11) use it like a locker number: first they jump to the locker with that number, then they use equals to find the exact item. If two equal books had different hash codes, they would land in different lockers, and the set would think they are different.

💡 The golden rule (the "contract") If a.equals(b) is true, then a.hashCode() == b.hashCode() must be true. So: always override both together, using the same fields. (The reverse is not required — two different objects may share a hash code; that's just a "collision".) VS Code can generate both for you: right-click in the class → Source Action… → Generate hashCode() and equals().
ℹ️ Coming later In Topic 15 you'll meet records, which generate toString, equals and hashCode automatically. In Spring Boot we use records a lot for DTOs (data transfer objects).

3.9 The life of an object and garbage collection

Created (new)→ In use (reachable)→ Unreachable→ Garbage collected (memory freed)

In languages like C, the programmer must free memory by hand — forget it and memory "leaks"; free it twice and the program crashes. Java has a Garbage Collector (GC): a background helper in the JVM that finds objects nobody can reach anymore and frees their memory.

An object becomes unreachable (eligible for GC) when no live variable can lead to it. Three common ways:

Ticket t1 = new Ticket(1);
t1 = null;                 // a) reference set to null

Ticket t2 = new Ticket(2);
t2 = new Ticket(3);        // b) reference re-pointed; Ticket #2 is orphaned

void book() {
    Ticket temp = new Ticket(99);
}                          // c) method ends; local variable 'temp' is gone
  • System.gc() only suggests a clean-up; the JVM decides when. Real applications almost never call it.
  • You don't need to (and can't) delete objects yourself in Java.
  • The old finalize() method is deprecated — never rely on it. For cleaning up files and connections you will use try-with-resources (Topic 10).
  • A "memory leak" in Java usually means you still hold references you no longer need (for example, objects kept forever in a big list).

6. Common mistakes

❌ Mistake: name = name; in a constructor The parameter is assigned to itself and the field stays null.
Fix: this.name = name;
⚠️ Mistake: giving a constructor a return type void Student(String name) { ... } is a method named Student, not a constructor. new Student("A") then fails to compile.
Fix: constructors have no return type at all.
⚠️ Mistake: expecting the default constructor after writing your own "constructor Student in class Student cannot be applied to given types" when calling new Student().
Fix: write a no-argument constructor yourself (and chain it with this(...)).
⚠️ Mistake: this(...) not on the first line "call to this must be first statement in constructor".
Fix: move this(...) to the very first line.
⚠️ Mistake: thinking b = a copies an object It copies only the reference. Changing b's fields changes a's object too.
Fix: if you need a real copy, create a new object: new Person(a.name, a.age) (a "copy constructor" is a nice pattern for this).
⚠️ Mistake: using an object before creating it Car car; car.brand = "Kia"; → compile error (not initialized), or a field Car car; left null → NullPointerException at runtime.
Fix: Car car = new Car(); first.
⚠️ Mistake: overriding equals but not hashCode Your objects look equal, but HashSet keeps duplicates and HashMap.get can't find keys.
Fix: always override both, using the same fields.
⚠️ Mistake: comparing objects with == book1 == book2 checks "same object", not "same data" — just like Strings in Topic 5.
Fix: use book1.equals(book2) (after overriding equals).

7. Best practices

  • One class = one clear responsibility. A BankAccount manages a balance; it shouldn't also send emails.
  • Name classes as nouns (Order, Invoice) and methods as verbs (placeOrder(), calculateTotal()).
  • Use constructors to create valid objects. Pass required values in the constructor so no object exists in a half-finished state.
  • Keep one "main" constructor and chain the others to it with this(...) — no duplicated code.
  • Always override toString() for domain classes — your logs and debugging will thank you.
  • Override equals and hashCode together, based on the fields that define identity (e.g. an id or ISBN). Let VS Code generate them.
  • Don't call System.gc() in real code; trust the JVM. Instead, avoid holding references you no longer need.
  • In real projects put each class in its own file (we bundle them only to make examples one-command runnable).
  • Next topic: make fields private and expose methods — this is how every professional Java class (and every Spring bean) is written.

8. Key takeaways

  • OOP organizes code around objects that combine data (fields) and behaviour (methods).
  • A class is a blueprint; an object is an instance created with new. Each object has its own field values.
  • Fields get default values (0, false, null); local variables do not.
  • A constructor has the class name and no return type; it runs once when the object is created.
  • Java adds a default no-arg constructor only if you write none.
  • this.x = this object's field; this(...) = call another constructor (first line only).
  • Object variables hold references. Objects live on the heap; local variables on the stack.
  • Override toString for readable output; override equals + hashCode together for value equality.
  • Unreachable objects are removed automatically by the garbage collector.

Hint / solution 
import java.util.HashSet;
import java.util.Objects;
import java.util.Set;

public class Practice05 {
    public static void main(String[] args) {
        Set<Student> students = new HashSet<>();
        students.add(new Student(1, "Asha"));
        students.add(new Student(2, "Vikram"));
        students.add(new Student(1, "Asha K."));   // same roll number -> duplicate
        System.out.println(students.size());        // 2
    }
}

class Student {
    int rollNumber;
    String name;

    Student(int rollNumber, String name) {
        this.rollNumber = rollNumber;
        this.name = name;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        Student other = (Student) o;
        return rollNumber == other.rollNumber;
    }

    @Override
    public int hashCode() {
        return Objects.hash(rollNumber);
    }

    @Override
    public String toString() {
        return "Student{" + rollNumber + ", " + name + "}";
    }
}

class Author {
    String name;
    String country;

    Author(String name, String country) {
        this.name = name;
        this.country = country;
    }

class LibraryBook {
    String title;
    Author author;      // reference to another object
    boolean issued;     // default false

    LibraryBook(String title, Author author) {
        this.title = title;
        this.author = author;
    }

    void issue() {
        if (issued) {
            System.out.println("Sorry, " + title + " is already issued");
            return;
        }
        issued = true;
        System.out.println("Issued: " + title + " by " + author.name);

        issued = false;
        System.out.println("Returned: " + title);
    }

10. Interview questions

Q1. What is the difference between a class and an object?

A class is a blueprint that defines fields and methods; it is written once. An object is a concrete instance of that class created at runtime with new; it occupies heap memory and has its own field values. One class can have many objects.

Q2. What is a constructor? How is it different from a method?

A constructor initializes a new object. It has the same name as the class, no return type, is called automatically by new, and runs once per object. A method has a return type (or void), any name, and can be called any number of times on an existing object. Constructors are not inherited; methods are.

Q3. What is the default constructor? When does Java provide it?

A no-argument, empty constructor that the compiler adds automatically only if the class declares no constructors at all. Once you write any constructor, it is not added.

Q4. What are the uses of the this keyword?

(1) Refer to the current object's fields when a parameter has the same name (this.name = name); (2) call another constructor of the same class (this(...), first line only); (3) pass the current object as an argument (register(this)); (4) return the current object (used in builder/fluent APIs: return this;).

Q5. What is constructor chaining?

Calling one constructor from another using this(...) (within the same class) or super(...) (parent class, Topic 7), so that initialization logic lives in one place and isn't duplicated.

Q6. Explain stack vs heap memory in Java.

The stack stores method call frames: local variables, parameters and references; each thread has its own stack and frames disappear when the method returns. The heap stores all objects and is shared by all threads; objects stay there until they become unreachable and the garbage collector reclaims them.

Q7. Is Java pass-by-value or pass-by-reference?

Always pass-by-value. For objects, the value passed is a copy of the reference. So a method can modify the object's state through that copy, but reassigning the parameter to a new object does not affect the caller's variable.

Q8. Why must you override hashCode() when you override equals()?

The contract says equal objects must have equal hash codes. Hash-based collections (HashMap, HashSet) first use the hash code to pick a bucket, then equals inside it. If equal objects have different hash codes, they land in different buckets: duplicates appear in sets and lookups in maps fail.

Q9. When does an object become eligible for garbage collection? Can you force GC?

When it is no longer reachable from any live reference — e.g. its reference is set to null, reassigned, or went out of scope. You cannot force GC; System.gc() is only a hint that the JVM may ignore.

Q10. What does the default toString() print and why override it?

It prints ClassName@hexHashCode (e.g. Book@5ca881b5), which tells you nothing about the data. Overriding it gives readable output for logging, debugging and error messages.
