1. Why this matters

Look at any app you use: a shopping site, a banking app, WhatsApp. Almost everything you see is text. Names, email addresses, passwords, product titles, addresses, chat messages, error messages. In Java, text is stored in a String.

As a backend developer you will work with Strings all day:

  • Checking if a user typed a valid email (contains("@"), isBlank()).
  • Reading a CSV line like Laptop,55000,Electronics and cutting it into pieces (split).
  • Building log messages and error messages (String.format).
  • Writing SQL queries and JSON samples (text blocks).
  • Comparing a user's role: "ADMIN".equals(role). Using == here instead is a famous bug!

Later, in Spring Boot, every URL path, every request parameter, every JSON field arrives as text first. If you are comfortable with Strings, the rest becomes much easier. And Strings are the number one interview topic for Java freshers.

2. Real-life analogy

🪨 A String is like text carved in stone Imagine a name carved on a stone plate: "RAVI". You cannot change the letters on that stone. If you want "ravi" in small letters, you must carve a new stone. The old stone is still there, unchanged. That is immutability: a String object never changes; every "change" gives you a new String.

A StringBuilder is like a whiteboard. You can write, erase and add words on the same board again and again — much cheaper than carving a new stone for every small change. When you are happy with the text, you "take a photo" of the board (toString()) and get a normal String.

The String Pool is like the library's shared copy of a popular book. If 100 students ask for "Harry Potter", the library does not print 100 copies; they all read the same copy. Java does the same with identical string literals.

3. Concepts step by step

3.1 What is a String?

A String is a sequence of characters — letters, digits, spaces, symbols — written inside double quotes.

String name = "Priya";           // 5 characters
String empty = "";               // 0 characters - still a valid String
String sentence = "I have 2 cats!";

Important facts for beginners:

  • String starts with a capital S. It is a class (a type defined in Java's library), not a primitive like int. You will learn properly what a class is in Topic 6; for now think of it as "a type of thing that has data and useful methods".
  • Because it is a class, a String variable holds a reference (an "address" or arrow) that points to the actual text object in memory.
  • Java gives Strings special treatment: you can write "Priya" directly instead of new String("Priya"), and you can join them with +.
  • Each character has a position called an index. Indexes start at 0, just like arrays.
Index01234
CharacterPriya

So "Priya".length() is 5, but the last index is 4 (always length() - 1).

3.2 Three ways to create a String

String city = "Hyderabad";                // 1. literal (most common, uses the String Pool)
String country = new String("India");     // 2. with 'new' (always a brand-new object - rarely needed)
char[] letters = {'J', 'a', 'v', 'a'};
String language = new String(letters);    // 3. from a char array -> "Java"
💡 TipIn real code, use literals: String s = "text";. Writing new String("text") just wastes memory.

3.3 Immutability — Strings never change

Immutable means "cannot be changed after it is created". Every String method that seems to "change" the text actually returns a new String and leaves the original alone.

String name = "ravi";
name.toUpperCase();              // creates "RAVI" ... and throws it away!
System.out.println(name);        // ravi   (unchanged)

name = name.toUpperCase();       // keep the new String by assigning it
System.out.println(name);        // RAVI

What happens in memory on the last line? The variable name now points to a new object "RAVI". The old object "ravi" was not modified; it just has nobody pointing at it now.

Why did Java's designers make Strings immutable?

  • Safety: Strings are used for passwords, file names, database URLs. If someone could change the text after it was checked, that would be a security hole.
  • Sharing (String Pool): because nobody can change a String, Java can safely let many variables share one object.
  • Thread-safety: many threads (Topic 17) can read the same String at the same time with no risk.
  • Caching the hash code: Strings are great as keys in a HashMap (Topic 11) because their hash never changes.

3.4 The String Pool

The String Pool is a special area inside the heap memory where Java keeps one copy of each string literal. When you write the same literal twice, Java gives you the same object.

String a = "java";              // Java puts "java" in the pool
String b = "java";              // same literal -> Java re-uses the SAME pooled object
String c = new String("java");  // 'new' forces a NEW object outside the pool
String d = c.intern();          // intern() = "give me the pooled copy of this text"

3.5 == versus equals() — the most famous String trap

==equals()
Question it asks"Are these two arrows pointing to the same object?""Is the text the same, character by character?"
a == b / a.equals(b)true (same pooled object)true
a == c / a.equals(c)false (different objects)true (same text)
When to usePrimitives (int, char …) and checking for nullAlways for comparing String content

Analogy: two people each holding a printed copy of the same book. equals asks "is it the same story?" — yes. == asks "is it the very same physical book?" — no.

String role = getRoleFromDatabase();   // imagine this returns "ADMIN" built at runtime
if (role == "ADMIN") { ... }           // ❌ may be false even when the text is ADMIN!
if ("ADMIN".equals(role)) { ... }      // ✅ correct, and safe even if role is null

More comparison helpers:

  • equalsIgnoreCase("JAVA") — same text, ignoring capital/small letters.
  • compareTo(other) — dictionary order. Negative number = comes before, 0 = equal, positive = comes after. "apple".compareTo("banana") is -1. Used for sorting.
ℹ️ Why put the literal first? "yes".equals(answer) can never crash: a literal is never null. But answer.equals("yes") throws a NullPointerException if answer is null (calling a method on "nothing"). This little habit avoids many crashes.

Understanding substring (start included, end excluded)

Think of the indexes as fences between letters. substring(0, 3) takes everything between fence 0 and fence 3:

//  | J | a | v | a |
//  0   1   2   3   4      <- fences
"Java".substring(0, 3)   // "Jav"
"Java".substring(1, 3)   // "av"
"Java".substring(2)      // "va"
// Length of the result is always (end - start).

Real use: cut an email into user name and domain

String email = "priya.sharma@shop.com";
int at = email.indexOf('@');                 // 12
String userName = email.substring(0, at);    // "priya.sharma"
String domain   = email.substring(at + 1);   // "shop.com"

Real use: read one line of a CSV file

String csvLine = "Laptop,55000,Electronics";
String[] parts = csvLine.split(",");          // ["Laptop", "55000", "Electronics"]
String name = parts[0];
int price = Integer.parseInt(parts[1]);       // text "55000" -> number 55000
⚠️ split takes a regular expression The argument of split is a regex (a pattern language). Some characters have special meaning: . | * + ? and more. So "a.b.c".split(".") returns an empty array! Use split("\\.") to mean a real dot, and split("\\|") for a pipe. split("\\s+") means "one or more spaces" — very handy.

3.7 Joining strings with +

+ joins (concatenates) text. But be careful: Java reads + from left to right. As soon as a String appears, everything after it is joined as text.

System.out.println(1 + 2 + " apples");   // "3 apples"   (1+2 is math first)
System.out.println("apples: " + 1 + 2);   // "apples: 12" (text, then text)
System.out.println("apples: " + (1 + 2)); // "apples: 3"  (brackets force math first)

3.8 Formatting text: String.format, formatted, printf

Joining many pieces with + gets messy. Formatting lets you write a template with placeholders and fill them in.

String msg = String.format("Hi %s, you bought %d items. Total: Rs. %.2f", "Anita", 3, 1249.5);
// Hi Anita, you bought 3 items. Total: Rs. 1249.50

String same = "Hi %s, total %.2f".formatted("Anita", 1249.5);   // Java 15+, same idea

System.out.printf("Discount: %d%%%n", 10);   // printf = format + print. Prints: Discount: 10%

3.9 Text blocks (""") — multi-line text made easy (Java 15+)

Before Java 15, writing JSON or SQL inside Java meant lots of \n, \" and +. Text blocks fix this.

// Old way - hard to read, easy to break
String oldJson = "{\n" +
                 "  \"name\": \"Laptop\"\n" +
                 "}";

// Text block - looks exactly like the real JSON
String json = """
        {
          "name": "Laptop",
          "price": 55000
        }
        """;

Rules to remember:

  • Open with """ and then a new line (text cannot start on the same line).
  • Java removes the common indentation on the left automatically (the spaces before { disappear).
  • If the closing """ is on its own line, the text ends with a new line. Put it right after the last word to avoid that.
  • You do not need to escape double quotes inside.
  • Combine with .formatted(...) to make templates (see the SQL example in Example03).
ℹ️ Where you will use this later In Spring Boot you will write SQL queries (@Query), JSON for tests, and long messages. Text blocks make them readable.

3.10 StringBuilder — a changeable string

Because Strings are immutable, this loop creates 20,000 new String objects, each one a copy of the last plus one letter:

String slow = "";
for (int i = 0; i < 20_000; i++) {
    slow = slow + "x";      // copy everything so far + 1 char, into a NEW object, every time
}

Copying gets longer each time (1 char, 2 chars, 3 chars … 20,000 chars), so the total work grows very fast. A StringBuilder keeps one growing buffer and just adds to it:

StringBuilder fast = new StringBuilder();
for (int i = 0; i < 20_000; i++) {
    fast.append("x");       // add 1 char to the same buffer
}
String result = fast.toString();   // turn it into a normal String at the end

On the trainer's laptop: + took about 230 ms, StringBuilder about 1 ms. With bigger loops the gap becomes huge.

💡 Do I always need StringBuilder? No! For a single line like "Hello " + name + "!", plain + is perfect — the compiler optimizes it for you. Use StringBuilder when you build text inside a loop or piece by piece across many steps.

3.12 Working with single characters (char)

A char is a primitive type holding one character, in single quotes: 'A'. "A" (double quotes) is a String. They are different types!

Inside the computer, every char is stored as a number (its Unicode code). That is why you can do math with chars:

(int) 'A'           // 65
'A' + 1             // 66   (int math)
(char) ('A' + 1)    // 'B'
'7' - '0'           // 7    (classic trick: digit character -> its number value)
'c' - 'a'           // 2    (position of a letter in the alphabet, starting at 0)

The Character class has helpers to ask questions about a char:

MethodTrue for
Character.isLetter(ch)'a', 'Z'
Character.isDigit(ch)'0' … '9'
Character.isLetterOrDigit(ch)letters and digits
Character.isUpperCase(ch) / isLowerCase'Z' / 'a'
Character.isWhitespace(ch)space, tab, new line
Character.toUpperCase(ch) / toLowerCase(converts, returns a char)

Two ways to loop over every character of a String:

String course = "Java";
for (int i = 0; i < course.length(); i++) {   // when you need the index
    char ch = course.charAt(i);
}
for (char ch : course.toCharArray()) {        // simplest when you only need the char
    System.out.print(ch);
}

4.4 Example04 — StringBuilder and the speed test

Example04_StringBuilderPerformance.javaStringBuilder sb = new StringBuilder("Spring");
sb.append(" Boot");                 // Spring Boot
sb.append(' ').append(3);           // Spring Boot 3   (chaining)
sb.insert(0, "I love ");            // I love Spring Boot 3
sb.replace(0, 6, "We like");        // We like Spring Boot 3
sb.delete(0, 8);                    // Spring Boot 3
sb.deleteCharAt(sb.length() - 1);   // "Spring Boot "  (the 3 is gone, the space stays)
sb.setCharAt(0, 's');               // "spring Boot "

Unlike String, these calls change the same object — we never write sb = sb.append(...). Then the program times 20,000 joins with + versus append using System.nanoTime() (a very precise stopwatch).

4.6 Example06 — interview programs

Example06_InterviewStringPrograms.javastatic boolean isAnagramByCounting(String first, String second) {
    String a = first.replace(" ", "").toLowerCase();
    String b = second.replace(" ", "").toLowerCase();
    if (a.length() != b.length()) {
        return false;
    }
    int[] counts = new int[26];                // one box per letter a..z
    for (int i = 0; i < a.length(); i++) {
        counts[a.charAt(i) - 'a']++;           // 'c' - 'a' = 2 -> box number 2
        counts[b.charAt(i) - 'a']--;
    }
    for (int c : counts) {
        if (c != 0) {
            return false;
        }
    }
    return true;
}

Each letter of the first word adds 1 to its box, each letter of the second word removes 1. If all 26 boxes end at 0, both words used exactly the same letters. This works in one pass — faster than sorting. (It assumes only the letters a–z.)

   isAnagram("Dormitory","Dirty room") = true

6. Common mistakes

❌ Mistake: comparing Strings with == if (password == "secret") compares object addresses, not text. It may work in a tiny test (pooled literals) and then fail with real input from a user or a database.
Fix: if ("secret".equals(password)).
⚠️ Mistake: forgetting that Strings are immutable name.trim(); on its own line does nothing useful — the result is thrown away.
Fix: name = name.trim(); — always save the returned value.
⚠️ Mistake: StringIndexOutOfBoundsException "Java".charAt(4) or "Java".substring(2, 10) crash because the last valid index is length() - 1 = 3.
Fix: loop with i < s.length() (not <=) and check indexes, e.g. if (at != -1) after indexOf.
⚠️ Mistake: calling a method on a null String String city = null; city.length(); throws NullPointerException.
Fix: check first: if (city != null && !city.isBlank()), or put the literal first in equals.
⚠️ Mistake: split(".") or split("|") These characters are special in regular expressions; "a.b".split(".") gives an empty array.
Fix: escape them: split("\\."), split("\\|").
⚠️ Mistake: + with numbers and text "Total: " + 10 + 5 prints Total: 105.
Fix: use brackets "Total: " + (10 + 5) or "Total: %d".formatted(10 + 5).
⚠️ Mistake: using + inside big loops Building a report of 100,000 lines with report = report + line can take seconds.
Fix: use a StringBuilder and call toString() once at the end.
⚠️ Mistake: mixing up 'A' and "A" char c = "A"; does not compile. 'A' + 'B' is the number 131, not "AB".
Fix: single quotes for one char, double quotes for a String. Use "" + 'A' + 'B' or String.valueOf if you need text.

7. Best practices

  • Always compare content with equals() (or equalsIgnoreCase()). Use == only for null checks.
  • Literal first: "ADMIN".equals(role) — null-safe. Or use Objects.equals(a, b) when both may be null.
  • Prefer isBlank() and strip() (Java 11+) for user input — they handle all kinds of whitespace.
  • Use StringBuilder in loops, plain + for one-line joins.
  • Use formatted() / String.format() for readable messages with many values.
  • Use text blocks for JSON, SQL, HTML or any multi-line text.
  • Never put secrets in Strings that get logged (passwords, tokens). In Topic 30 (Logging) you will learn what not to log.
  • Make text constants final and give them a name, e.g. static final String ADMIN_ROLE = "ADMIN"; instead of repeating the literal everywhere.
  • When you need a utility that Java doesn't have (e.g. "is this null or blank?"), write a small helper method once and reuse it. In Maven projects later, libraries like Apache Commons Lang (StringUtils) offer many of these.

8. Key takeaways

  • A String is an object holding a sequence of characters; indexes start at 0.
  • Strings are immutable: methods return a new String — always save the result.
  • Identical literals share one object in the String Pool; new String(...) creates a separate object.
  • == compares references, equals() compares text. Use equals() for Strings.
  • Know your toolbox: length, charAt, indexOf, substring, contains, replace, split, strip, isBlank, join, repeat.
  • String.format / formatted / printf use placeholders like %s %d %.2f %n.
  • Text blocks """ make multi-line text (JSON, SQL) clean and readable.
  • StringBuilder is a mutable, fast builder; StringBuffer is the thread-safe, slower version.
  • A char is a number underneath; the Character class answers "is it a digit/letter/upper case?".

Challenge

6. Compress a string. Write compress("aaabbcdddd") that returns "a3b2c1d4". If the compressed version is not shorter than the original, return the original (so compress("abc") returns "abc").

Hint / solution

Walk through the string, count how many times the current char repeats, append char + count when it changes.

public class Practice06 {
    static String compress(String s) {
        if (s == null || s.isEmpty()) {
            return s;
        }
        StringBuilder out = new StringBuilder();
        int count = 1;
        for (int i = 1; i <= s.length(); i++) {
            if (i < s.length() && s.charAt(i) == s.charAt(i - 1)) {
                count++;
            } else {
                out.append(s.charAt(i - 1)).append(count);
                count = 1;
            }
        }
        return out.length() < s.length() ? out.toString() : s;
    }

    public static void main(String[] args) {
        System.out.println(compress("aaabbcdddd"));   // a3b2c1d4
        System.out.println(compress("abc"));          // abc
    }
}

10. Interview questions

Q1. Why is String immutable in Java?

For security (Strings hold passwords, file paths, URLs; they cannot be changed after validation), to allow the String Pool (sharing one object is only safe if nobody can change it), for thread-safety (no locking needed to share it), and so the hash code can be cached, which makes Strings fast and reliable HashMap keys.

Q2. What is the difference between == and equals() for Strings?

== checks if two references point to the same object. equals() checks if the characters are the same. new String("a") == "a" is false, but new String("a").equals("a") is true. Always use equals() to compare text.

Q3. What is the String Pool? How many objects does String s = new String("hello"); create?

The String Pool is a special area of the heap where Java stores one shared copy of each string literal. new String("hello") creates up to two objects: the literal "hello" in the pool (only if it is not already there) and a new object on the heap that s points to. If the literal was already pooled, only one new object is created.

Q4. What does intern() do?

It returns the pooled copy of the String's text. If the pool does not have it yet, it adds it. After String d = new String("java").intern();, d == "java" is true.

Q5. String vs StringBuilder vs StringBuffer?

String is immutable. StringBuilder is mutable and not synchronized — the fastest choice for building text. StringBuffer is mutable and synchronized (thread-safe) but slower. Use StringBuilder by default; StringBuffer only when several threads must modify the same buffer.

Q6. Why is using + in a loop slow?

Each + creates a new String and copies all previous characters into it, so the total work grows roughly with the square of the number of iterations. StringBuilder.append adds to one internal buffer (it grows occasionally), so it is roughly linear. Outside loops the compiler already optimizes +, so one-line joins are fine.

Q7. Difference between trim() and strip()? isEmpty() and isBlank()?

trim() removes characters with code ≤ 32 (basic ASCII spaces); strip() (Java 11) removes all Unicode whitespace. isEmpty() is true only when the length is 0; isBlank() (Java 11) is true when the String is empty or contains only whitespace.

Q8. How do you check if two strings are anagrams?

Normalize them (remove spaces, lower case), check equal length, then either sort both char arrays and compare with Arrays.equals (O(n log n)), or count letters with an int[26] — increment for the first, decrement for the second, all zeros means anagram (O(n)).

Q9. Is String thread-safe? Can String be used as a HashMap key?

Yes, because it is immutable — no thread can change it. And yes, it is the most common key: its equals and hashCode are based on content and the hash never changes, so lookups are reliable.

Q10. What are text blocks and when were they added?

Text blocks (standard since Java 15) are multi-line String literals written between """ delimiters. They keep line breaks, remove common indentation and do not need escaping of double quotes. Ideal for JSON, SQL, HTML and long messages.
