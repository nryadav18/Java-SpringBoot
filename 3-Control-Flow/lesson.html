1. Why this matters

So far our programs ran straight from top to bottom, every line exactly once. Real programs are not like that. They must:

  • Decide: "If the password is wrong, show an error. Otherwise, log in." "If the cart total is above ₹500, delivery is free."
  • Repeat: "For every item in the cart, add its price." "Keep showing the menu until the user chooses Exit." "Retry the payment up to 3 times."

This is called control flow — controlling the order in which statements run. In Spring Boot applications you'll write things like "if the product doesn't exist, return 404 Not Found", "for each order item, reduce the stock", "switch on the order status to decide the next step". Control flow is the "brain" of every method you will ever write.

2. Real-life analogy

🚗 Driving with a GPS
  • if / else is a fork in the road: "If the highway is jammed, take the service road, else stay on the highway." You take exactly one path.
  • else if ladder is a series of signboards: you take the first exit that matches your destination.
  • switch is a roundabout with many numbered exits: you look at one value (your exit number) and go straight to it.
  • Loops are going around a race track: "Drive 10 laps" (for), "Keep driving while there's fuel" (while), "Drive at least one lap, then check if you want another" (do-while).
  • break is pulling into the pit stop and leaving the race; continue is skipping the rest of this lap and starting the next one.

3. Concepts step by step

3.1 The if statement

An if runs a block of code only when a condition is true. The condition must be a boolean expression (something that is true or false).

double cartTotal = 650.0;
if (cartTotal >= 500) {
    System.out.println("You get FREE delivery!");
}
System.out.println("This line always runs.");
cartTotal >= 500 ?→ true → print "FREE delivery"→ continue program
cartTotal >= 500 ?→ false → continue program

3.2 if / else

Add else for "otherwise". Exactly one of the two blocks runs — never both, never neither.

int age = 16;
if (age >= 18) {
    System.out.println("You can vote.");
} else {
    System.out.println("You cannot vote yet.");
}

3.3 The else if ladder

For more than two choices, chain conditions. Java checks them top to bottom and runs only the first block whose condition is true. Everything after it is skipped.

int marks = 82;
char grade;
if (marks >= 90) {
    grade = 'A';
} else if (marks >= 75) {   // reached only if marks < 90
    grade = 'B';
} else if (marks >= 60) {
    grade = 'C';
} else if (marks >= 40) {
    grade = 'D';
} else {                     // none of the above
    grade = 'F';
}
// marks 82 → 'B'
💡 Order mattersBecause only the first true branch runs, put the most specific / strictest condition first. If you wrote marks >= 40 first, everyone with 40+ would get 'D' — even a 95!

3.4 Nested if

An if inside another if. The inner one is checked only when the outer one is true.

if (applicantAge >= 21 && applicantAge <= 60) {
    if (monthlySalary >= 25000) {
        if (creditScore >= 700) {
            System.out.println("Loan APPROVED");
        } else {
            System.out.println("Loan rejected: credit score too low");
        }
    } else {
        System.out.println("Loan rejected: salary too low");
    }
} else {
    System.out.println("Loan rejected: age not in 21-60");
}

Nesting is useful when each level gives a different message. But deep nesting (3+ levels) becomes hard to read — the "arrow shape" problem. In Topic 4 you'll learn guard clauses (return early) to flatten it.

3.5 Curly braces and a classic trap

If a block has only one statement, Java lets you skip the braces. Don't.

if (balance < 0)
    System.out.println("Overdrawn!");
    System.out.println("Fee charged");   // ⚠️ NOT part of the if – ALWAYS runs (indentation lies!)

Only the first line belongs to the if. Always use braces, even for one line.

3.6 The ternary operator ? :

A compact if/else that produces a value:

// condition ? valueIfTrue : valueIfFalse
String status = stock > 0 ? "In stock" : "Out of stock";
int bigger   = (a > b) ? a : b;
System.out.println(items + (items == 1 ? " item" : " items"));

It's the same as:

String status;
if (stock > 0) {
    status = "In stock";
} else {
    status = "Out of stock";
}
💡 Use it for simple choices onlyGreat for picking between two values. Avoid nesting ternaries (a ? b : c ? d : e) — nobody can read them.

3.7 The classic switch statement

When you compare one value against many fixed options, switch is cleaner than a long else-if ladder.

int dayNumber = 3;
switch (dayNumber) {
    case 1:
        System.out.println("Monday");
        break;            // leave the switch
    case 2:
        System.out.println("Tuesday");
        break;
    case 3:
        System.out.println("Wednesday");
        break;
    default:              // no case matched
        System.out.println("Some other day");
}
  • The value in switch (...) can be int, char, byte, short (and their wrappers), String or an enum (Topic 15). Not long, double, float or boolean.
  • Case labels must be constants (fixed values), not conditions like case marks > 90. For ranges, use if/else.
  • default is optional but recommended.

3.8 Fall-through: the break you forgot

In a classic switch, once a case matches, Java runs every following line until it hits a break (or the end). This is called fall-through.

int level = 1;
switch (level) {
    case 1: System.out.print("Bronze ");   // no break
    case 2: System.out.print("Silver ");   // falls into here
    case 3: System.out.print("Gold ");     // and here
}
// prints: Bronze Silver Gold

Usually a bug. But it can be used on purpose to group cases:

switch (month) {
    case 4: case 6: case 9: case 11:
        daysInMonth = 30;
        break;
    case 2:
        daysInMonth = 28;
        break;
    default:
        daysInMonth = 31;
}

3.9 Modern switch: arrow labels (Java 14+)

Java 14 introduced case X ->. With arrows there is no fall-through, so you never need break. You can also list several values in one case with commas.

switch (paymentMethod) {
    case "CARD" -> System.out.println("Redirecting to card gateway...");
    case "UPI"  -> System.out.println("Showing UPI QR code...");
    case "COD"  -> System.out.println("Cash on delivery selected.");
    default     -> System.out.println("Unknown payment method");
}

For more than one statement, use a block { } after the arrow:

case 2 -> {
    System.out.print("Amount to deposit > ");
    double amount = scanner.nextDouble();
    balance += amount;
}

3.10 Switch expressions and yield

A switch can also produce a value that you store in a variable. This is a switch expression:

String season = switch (monthNumber) {
    case 12, 1, 2   -> "Winter";
    case 3, 4, 5    -> "Summer";
    case 6, 7, 8, 9 -> "Monsoon";
    case 10, 11     -> "Autumn";
    default         -> "Invalid month";
};   // ← semicolon: the whole switch is the right side of an assignment

If a case needs several statements before giving its value, use a block and yield ("this is the value of this case"):

int deliveryDays = switch (orderStatus) {
    case "PLACED"  -> 5;
    case "SHIPPED" -> {
        System.out.println("Checking courier...");
        int courierDays = 2;
        yield courierDays;          // the value of the switch
    }
    default -> -1;
};

A switch expression must be exhaustive: every possible input must produce a value. With int or String that means you need a default. The compiler checks this for you — a real safety net.

Fall-throughYes (need break)No

ℹ️ In newer JavaJava 21 adds pattern matching for switch (e.g. case Circle c -> ...). We use Java 17 in this course, so we won't use it in code — but you'll recognise it when you see it.

3.11 if/else vs switch — which one?

Use if / else if when…Use switch when…
Conditions are ranges (marks >= 90)You compare one value to fixed options
Conditions involve different variablesOptions are many (menu choices, status codes, commands)
You need && / || combinationsYou want the compiler to check you covered everything (switch expression)

3.12 Loops: why repeat?

Printing 1 to 1000 with 1000 println lines is silly. A loop repeats a block of code many times. Every loop has 3 ingredients:

  1. Start — a starting value (e.g. i = 1).
  2. Condition — keep going while this is true (e.g. i <= 1000).
  3. Update — move towards the end (e.g. i++). Forget this and the loop never ends — an infinite loop.

3.13 The for loop

Best when you know how many times to repeat.

for (int i = 1; i <= 5; i++) {
    System.out.print(i + " ");
}
// 1 2 3 4 5
① int i = 1
runs once→ ② i <= 5 ?→ true → ③ body→ ④ i++→ back to ②

When ② becomes false, the loop ends. Trace table for the example:

Roundii <= 5?Prints

55true5

Variations:

for (int i = 5; i >= 1; i--)     { ... }   // count down: 5 4 3 2 1
for (int i = 2; i <= 10; i += 2) { ... }   // step by 2: 2 4 6 8 10
for (int i = 0; i < 5; i++)      { ... }   // 0..4 – the usual style for arrays (Topic 4)

The variable i declared in the for only exists inside the loop. After the loop, i is gone.

3.14 The while loop

Best when you don't know in advance how many times — you repeat while something is true.

double savings = 10000;
int years = 0;
while (savings < 20000) {     // checked BEFORE every round
    savings = savings * 1.08;
    years++;
}
// years = 10

If the condition is false at the start, the body runs zero times.

3.15 The do-while loop

The body runs first, then the condition is checked. So it always runs at least once. Perfect for menus and "ask until valid input".

int choice;
do {
    showMenu();
    choice = scanner.nextInt();
    // handle choice...
} while (choice != 4);     // ← note the semicolon after while(...)

3.16 The enhanced for (for-each)

To visit every element of an array (or a collection, Topic 11) without counting indexes:

double[] prices = {120.0, 45.5, 300.0, 15.25};
double total = 0;
for (double price : prices) {    // read as: "for each price in prices"
    total += price;
}
// total = 480.75

It's simpler and safer (no index mistakes). Limitation: you don't get the index, and you can't replace elements through the loop variable. Arrays are explained fully in Topic 4 — here we just use them as "a list of values in curly braces".

3.17 break and continue

  • break — leave the loop immediately. Use it when you've found what you were looking for.
  • continue — skip the rest of the current round and jump to the next round.
for (int amount : orderAmounts) {
    if (amount > 1000) {
        System.out.println("Found big order: " + amount);
        break;                  // stop searching
    }
}

for (int i = 1; i <= 9; i++) {
    if (i % 2 == 0) {
        continue;               // skip even numbers
    }
    System.out.print(i + " ");  // 1 3 5 7 9
}

3.18 Labelled break and continue

A plain break only leaves the innermost loop. To leave an outer loop from inside an inner one, put a label (a name followed by a colon) before the outer loop:

search:                                         // label
for (int row = 0; row < seatTaken.length; row++) {
    for (int seat = 0; seat < seatTaken[row].length; seat++) {
        if (!seatTaken[row][seat]) {
            foundRow = row;
            foundSeat = seat;
            break search;                       // leaves BOTH loops
        }
    }
}

continue label; jumps to the next round of the labelled (outer) loop:

nextStudent:
for (int s = 0; s < marks.length; s++) {
    for (int m : marks[s]) {
        if (m < 40) {
            continue nextStudent;   // skip the "passed" message for this student
        }
    }
    System.out.println("Student " + s + " passed all subjects");
}
ℹ️ Use labels rarelyLabels are handy for searching in a grid, but if you need them often, the code is probably too complex — moving the inner loop into its own method and using return (Topic 4) is usually clearer.

3.19 Nested loops and patterns

A loop inside a loop. Think of a clock: the minute hand (inner loop) goes all the way round for every single step of the hour hand (outer loop). For patterns: outer loop = rows, inner loop = columns.

for (int row = 1; row <= 4; row++) {         // 4 rows
    for (int col = 1; col <= row; col++) {   // row 1 → 1 star, row 2 → 2 stars...
        System.out.print("* ");
    }
    System.out.println();                    // new line after each row
}
*
* *
* * *
* * * *

Recipe for any pattern: (1) how many rows? (2) for row number r, how many spaces and how many symbols? (3) write the outer loop for rows, one inner loop per "part" of the row. For a pyramid of height n, row r has n - r spaces and 2r - 1 stars.

If the outer loop runs n times and the inner loop runs n times, the body runs n × n times. With n = 1,000 that's a million — remember this when you meet performance topics later.

3.21 Infinite loops

A loop whose condition never becomes false runs forever. Sometimes on purpose (a server waiting for requests), usually by mistake:

int i = 1;
while (i <= 5) {
    System.out.println(i);
    // forgot i++  → prints 1 forever
}

If your program seems stuck, press Ctrl+C in the terminal to stop it. Intentional infinite loops are written while (true) { ... } with a break inside.

seatTaken is a 2D array (a table of rows and columns — Topic 4). The outer loop walks rows, the inner loop walks seats. As soon as a free seat is found, break search; exits both loops, so we get the first free seat (row 1, seat 1) and don't overwrite it with later ones.

4.5 Example06 — prime check, step by step

Example06_CommonLoopProblems.java (part)int candidate = 29;
boolean isPrime = candidate > 1;          // 0 and 1 are not prime
for (int d = 2; d * d <= candidate; d++) {
    if (candidate % d == 0) {
        isPrime = false;
        break;
    }
}
  • Flag pattern: assume prime (true), and switch to false if we find a divisor.
  • d * d <= candidate is the same as d <= √candidate: if 29 had a divisor bigger than √29 ≈ 5.4, it would also have a matching one smaller than it. So we only test 2, 3, 4, 5 instead of 2…28.
  • break: one divisor is enough.

4.6 Example07 — the ATM menu

Example07_AtmMenu.java (part)int attemptsLeft = MAX_PIN_ATTEMPTS;
while (attemptsLeft > 0) {
    System.out.print("Enter PIN > ");
    int pin = scanner.nextInt();
    if (pin == CORRECT_PIN) {
        authenticated = true;
        break;
    }
    attemptsLeft--;
    System.out.println("Wrong PIN. Attempts left: " + attemptsLeft);
}
if (!authenticated) {
    System.out.println("Card blocked. Please contact your bank.");
    return;                                   // ends main → ends the program
}

int choice;
do {
    // print menu ...
    choice = scanner.nextInt();
    switch (choice) {
        case 1 -> System.out.printf("Your balance is: %.2f%n", balance);
        case 2 -> { /* deposit with validation */ }
        case 3 -> {
            double amount = scanner.nextDouble();
            if (amount <= 0) { ... }
            else if (amount > DAILY_WITHDRAW_LIMIT) { ... }
            else if (amount > balance) { ... }
            else if (amount % 100 != 0) { ... }
            else { balance -= amount; ... }
        }
        case 4 -> System.out.println("Thank you for banking with us. Goodbye!");
        default -> System.out.println("Invalid option. Please choose 1-4.");
    }
} while (choice != 4);
  • while + break for limited retries.
  • do-while for the menu: always show it once, repeat until Exit.
  • arrow switch for menu choices — no forgotten break.
  • else-if ladder for validation: check every error first, do the real work in the final else. This "validate first" habit is exactly what you'll do in Spring services later.
  • choice is declared before the do so the while (choice != 4) condition can see it.

6. Common mistakes

❌ Mistake: semicolon after if or for 
if (balance < 0); {              // the ; ends the if – the block ALWAYS runs
    System.out.println("Overdrawn");
}
for (int i = 0; i < 5; i++); {   // loop does nothing 5 times, block runs once
    System.out.println(i);       // and this won't even compile: i is unknown here
}
Fix: never put ; right after if (...), for (...) or while (...). (The ; after do { } while (...) is correct.)
⚠️ Mistake: forgetting break in a classic switch Execution falls through into the next cases.
Fix: use the arrow form case X ->, which never falls through.
⚠️ Mistake: off-by-one errors for (int i = 1; i < 10; i++) runs 9 times, not 10. i <= 10 runs 10 times.
Fix: trace the first and last round on paper. For arrays, the standard is for (int i = 0; i < arr.length; i++).
⚠️ Mistake: infinite loop Forgot the update (i++), or updated in the wrong direction (i-- while checking i <= 10).
Fix: make sure every round moves closer to the end. Stop a stuck program with Ctrl+C.
⚠️ Mistake: wrong order in an else-if ladder if (i % 3 == 0) Fizz else if (i % 15 == 0) FizzBuzz — 15 prints "Fizz", the FizzBuzz branch is never reached.
Fix: put the most specific condition first.
⚠️ Mistake: comparing Strings with == in conditions if (command == "exit") may be false even when the user typed exit.
Fix: if (command.equals("exit")). (A switch on a String uses equals internally, so it is safe.)
⚠️ Mistake: missing default in a switch expression String s = switch (n) { case 1 -> "one"; }; → error: the switch expression does not cover all possible input values.
Fix: add default -> ....
⚠️ Mistake: using a loop variable outside the loop for (int i = 0; i < 5; i++) {...} System.out.println(i); → cannot find symbol.
Fix: declare the variable before the loop if you need it afterwards.
⚠️ Mistake: factorial overflow Using int for factorial: 13! = 6,227,020,800 doesn't fit in an int, and you get a wrong number silently.
Fix: use long (OK up to 20!) or BigInteger for bigger.

7. Best practices

  • Always use curly braces for if/else/loops, even for a single statement.
  • Prefer the arrow switch and switch expressions in new code; they are shorter and can't fall through.
  • Always handle the "else" / default case — even if just to report an error. Unexpected values happen in real systems.
  • Name complex conditions: boolean isEligible = age >= 21 && salary >= 25000; then if (isEligible).
  • Avoid deep nesting (more than 2–3 levels). Combine conditions with &&, or return early (Topic 4).
  • Choose the right loop: for for counting, enhanced for for "every element", while for "until", do-while for "at least once".
  • Keep loop bodies small. If a loop body grows big, move it into a method (Topic 4).
  • Don't change the loop counter inside a for loop body — it makes the loop very hard to follow.
  • Validate first, then act (like the ATM's withdraw): check all error cases before changing data.
  • Use break to stop searching early — no need to process the rest once you have your answer.

8. Key takeaways

  • if / else if / else runs the first matching branch only; order your conditions from most specific to least.
  • The ternary cond ? a : b picks one of two values in a single expression.
  • Classic switch falls through without break; arrow case X -> never falls through.
  • Switch expressions return a value, support case 1, 2 ->, use yield in blocks, and must be exhaustive.
  • for = known count; while = unknown count, may run 0 times; do-while = at least once; enhanced for = every element.
  • break exits a loop; continue skips to the next round; labels let them act on an outer loop.
  • Nested loops: outer = rows, inner = columns; work out spaces and symbols per row.
  • Key loop patterns: accumulator, flag + break, digit loop (%10, /10), rolling variables.

9. Practice exercises

Easy

1. Electricity bill. Given int units, calculate the bill: first 100 units ₹5/unit, next 100 units (101–200) ₹7/unit, above 200 ₹10/unit. For 250 units the bill is 100×5 + 100×7 + 50×10 = ₹1700.

Hint / solution
public class ElectricityBill {
    public static void main(String[] args) {
        int units = 250;
        double bill;
        if (units <= 100) {
            bill = units * 5;
        } else if (units <= 200) {

10. Interview questions

Q1. What is the difference between while and do-while?

while checks the condition before each iteration, so the body may run zero times. do-while checks after each iteration, so the body always runs at least once. do-while also needs a semicolon after while(...).

Q2. What is fall-through in a switch statement?

In a classic (colon) switch, once a case matches, execution continues into the following cases until a break or the end of the switch. It's useful for grouping cases but is a common bug. Arrow-style cases (case X ->) don't fall through.

Q3. What is a switch expression, and what is yield?

Since Java 14, switch can be an expression that returns a value: String s = switch (x) { case 1 -> "one"; default -> "other"; };. It must be exhaustive. When a case uses a block { }, yield value; provides the result of that case.

Q4. Which types can be used in a switch?

byte, short, char, int, their wrappers (Byte, Short, Character, Integer), String (Java 7+) and enums. Not long, float, double or boolean. (Java 21 adds pattern matching on any object type.)

Q5. What is the difference between break and continue?

break exits the loop (or switch) entirely. continue skips the remaining statements of the current iteration and moves to the next iteration. Both can take a label to act on an outer loop.

Q6. How do you exit from nested loops?

Use a labelled break (outer: for (...) { for (...) { break outer; } }), or put the loops into a method and return when done, or use a boolean flag checked by the outer loop. The method + return approach is usually the cleanest.

Q7. Write an efficient prime check.

Return false for n < 2; then test divisors from 2 while d * d <= n; if any divides n, it's not prime. This is O(√n) instead of O(n). Further optimisation: handle 2 separately and test only odd divisors.

Q8. Can you use a for loop without any of its three parts?

Yes. for (;;) { } is a valid infinite loop — all three parts are optional. The same as while (true) { }. You need a break or return inside to leave it.

Q9. What does this print? int i = 0; while (i++ < 3) System.out.print(i);

123. Each check compares the old value (0, 1, 2 → true; 3 → false) and then increments, so inside the body i is 1, 2, 3.

Q10. When would you choose the ternary operator over if/else?

When you need to choose between two values in a single, simple expression (e.g. assigning or printing). For actions (statements) or anything more complex, use if/else for readability. Avoid nested ternaries.
