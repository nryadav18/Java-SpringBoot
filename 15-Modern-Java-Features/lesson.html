1. Why this matters

Java has a reputation for being "wordy". For years, a simple class to hold a student's name and email needed 50+ lines: fields, a constructor, getters, equals, hashCode, toString. Between Java 9 (2017) and Java 17 (2021), the language changed a lot to fix this. Java 17 is a Long-Term Support (LTS) release, and Spring Boot 3 requires at least Java 17 — so these features are exactly what you will see in modern Spring projects:

  • Records are the standard way to write DTOs (request/response objects) in Spring REST APIs (topics 33+) and type-safe configuration (@ConfigurationProperties, topic 29).
  • Enums model statuses and roles: OrderStatus.SHIPPED, Role.ADMIN — and JPA can store them in the database (@Enumerated).
  • Text blocks make SQL in @Query and JSON in tests readable.
  • Switch expressions and pattern matching remove whole classes of bugs (forgotten break, wrong casts).
  • Helpful NPE messages save you hours of debugging.

2. Real-life analogy

🧾 Record = a printed receipt A shop receipt holds data — items, total, date. Once printed, nobody edits it. If two receipts show exactly the same data, they are "equal" for all practical purposes. You never need to write instructions for how to "print" or "compare" a receipt — every receipt works the same way. That is a record: pure, unchangeable data, with the boring parts done automatically.
🚦 Enum = traffic light colours A traffic light has exactly three states: RED, YELLOW, GREEN. Not "Red", "red", or "purple". An enum makes the compiler enforce that fixed list — and each state can carry information (how many seconds it lasts) and behaviour (what drivers should do).
🎟️ Sealed class = an exclusive guest list A wedding with a guest list: only the named people may enter. A sealed type is a class or interface with a guest list (permits): only the listed classes may extend it. Because the bouncer knows the full list, nobody unexpected can show up — and your code can safely handle "every possible guest".

3. Concepts step by step

3.1 var — local variable type inference (Java 10)

var lets the compiler work out the type of a local variable from the value on the right side.

var shopName = "FreshMart";                              // String
var cart = new ArrayList<String>();                      // ArrayList<String>
var marksByStudent = new HashMap<String, List<Integer>>(); // saves typing a long type twice
for (var entry : marksByStudent.entrySet()) { ... }      // Map.Entry<String, List<Integer>>

Important: var is not like JavaScript's var. Java is still statically typed: the type is fixed at compile time. shopName = 10; is a compile error.

✅ Allowed❌ Not allowed
Local variables with an initializerFields: private var count = 0;
for / for-each loop variablesMethod parameters and return types
try-with-resources variablesNo initializer: var x;
Lambda parameters (Java 11): (var a, var b) -> ...var y = null;, var arr = {1, 2};, var f = () -> 1;
💡 When to use var Use it when the type is obvious from the right side (var list = new ArrayList<Order>()). Avoid it when the right side hides the type: var result = service.process(data); — the reader has to go look up what process returns.

3.2 Text blocks (Java 15)

A text block is a multi-line string between triple quotes """. No more \n, \" and + everywhere.

// Before
String json = "{\n" +
        "  \"name\": \"Laptop\",\n" +
        "  \"price\": 55000\n" +
        "}";

// After
String json = """
        {
          "name": "Laptop",
          "price": 55000
        }""";

Rules to remember:

  • The opening """ must be followed by a new line; content starts on the next line.
  • Indentation: Java removes the common leading spaces. The left-most line (or the closing """ if it's further left) sets the margin. Relative indentation (like the nested <li>) is kept.
  • If the closing """ is on its own line, the string ends with a newline; if it's right after the last text, it doesn't.
  • \ at the end of a line joins it with the next line (no newline).
  • \s is a single space that is never stripped (trailing spaces are normally removed).
  • Use .formatted(...) to fill in %s/%d placeholders.
// You'll see this in Spring Data JPA (topic 39):
@Query("""
       SELECT p FROM Product p
       WHERE p.price > :minPrice
       ORDER BY p.price DESC
       """)
List<Product> findExpensive(@Param("minPrice") double minPrice);

3.3 Records (Java 16) — data classes in one line

Look at all the code a classic "data holder" class needs:

public final class Point {
    private final int x;
    private final int y;
    public Point(int x, int y) { this.x = x; this.y = y; }
    public int x() { return x; }
    public int y() { return y; }
    @Override public boolean equals(Object o) { ... 6 lines ... }
    @Override public int hashCode() { return Objects.hash(x, y); }
    @Override public String toString() { return "Point[x=" + x + ", y=" + y + "]"; }
}

With a record:

public record Point(int x, int y) { }

From that single line, Java generates:

GeneratedDetails
Fieldsprivate final int x; private final int y; — the record's components
Canonical constructornew Point(3, 4)
Accessorsp.x() and p.y() — no "get" prefix
equals / hashCodeBased on all components (value equality)
toStringPoint[x=3, y=4]

Rules of records:

  • Records are immutable — no setters, fields are final. To "change" one, create a new record (a wither method like withPrice(...)).
  • Records are implicitly final — nobody can extend them — and they cannot extend another class (they already extend java.lang.Record). They can implement interfaces.
  • You can add methods, static fields, static methods and extra constructors. You cannot add extra instance fields.
  • Immutability is shallow: record Cart(List<String> items) — someone could still modify the list itself. Use List.copyOf(items) in the compact constructor to protect it.

Compact constructor — where validation lives

record Product(String name, double price, int stock) {
    Product {                                  // no parameter list!
        if (price < 0) throw new IllegalArgumentException("Price cannot be negative");
        name = name.strip();                   // you may adjust parameters
    }                                          // fields are assigned automatically here
}

A compact constructor runs before the fields are assigned. It is the perfect place for validation, so an invalid record can never exist.

ℹ️ Records as DTOs in Spring A DTO (Data Transfer Object) is a simple object whose only job is to carry data between layers or over the network — for example the JSON body of a request. Records are ideal: short, immutable, with correct equals/toString. Spring's JSON library (Jackson) reads and writes records automatically: 
public record CreateProductRequest(@NotBlank String name, @Positive double price) { }

@PostMapping("/api/products")
public ProductResponse create(@RequestBody CreateProductRequest request) { ... }
You'll write exactly this in topics 32–35. Note: JPA entities (topic 38) can't be records, because JPA needs a no-args constructor and mutable fields. Records = DTOs; classes = entities.

3.4 Enums — a fixed set of named constants

An enum (enumeration) is a special class with a fixed set of instances. Instead of error-prone strings like "SHIPPED" or magic numbers like 3, you use type-safe constants:

enum Day { MONDAY, TUESDAY, WEDNESDAY, THURSDAY, FRIDAY, SATURDAY, SUNDAY }

Day today = Day.FRIDAY;
today.name();            // "FRIDAY"
today.ordinal();         // 4 (position, from 0) - don't store this in a database!
Day.valueOf("SUNDAY");   // String -> enum (IllegalArgumentException if no match)
Day.values();            // array of all constants
today == Day.FRIDAY      // compare with == (each constant exists exactly once)

Enums can have fields, a constructor and methods — they're real classes:

enum OrderStatus {
    PLACED("Order placed", false),
    SHIPPED("On the way", false),
    DELIVERED("Delivered to customer", true);

    private final String label;
    private final boolean finalState;

    OrderStatus(String label, boolean finalState) {   // always private
        this.label = label;
        this.finalState = finalState;
    }

    String getLabel() { return label; }
    boolean canCancel() { return this == PLACED; }
}

Constant-specific behaviour: declare an abstract method in the enum and let each constant implement it — a neat replacement for long if/else chains (this is the Strategy pattern in disguise):

enum DeliveryType {
    STANDARD { double charge(double v) { return v >= 500 ? 0 : 40; } },
    EXPRESS  { double charge(double v) { return 99; } };
    abstract double charge(double orderValue);
}

EnumMap and EnumSet are special, very fast collections for enum keys/values. They keep the declaration order.

💡 Enums in Spring JPA can store an enum in a column with @Enumerated(EnumType.STRING) (topic 38), and Jackson converts enums to/from JSON strings automatically ("status": "SHIPPED"). Roles in Spring Security are often enums too.

3.5 Switch expressions (Java 14)

The old switch statement had two problems: it "falls through" to the next case if you forget break, and it can't directly produce a value. The new form fixes both:

String type = switch (day) {
    case 1, 7 -> "Weekend";          // several labels, comma separated
    default   -> "Weekday";          // arrow: no fall-through, no break
};                                   // note the semicolon - it's an expression

double discount = switch (city) {
    case "Chennai" -> {
        double base = orderValue * 0.05;
        yield Math.min(base, 100);   // 'yield' returns a value from a block
    }
    case "Delhi" -> 50;
    default -> 0;
};
Old case X:New case X ->
Fall-throughYes, unless you write breakNever
Multiple labelsStacked case 1: case 7:case 1, 7 ->
Returns a valueNo (statement)Yes, when used as an expression
Must cover all casesNoYes, when used as an expression (exhaustive)

Exhaustiveness: a switch expression must handle every possible value. For a String or int you need default. For an enum, listing every constant is enough — and if someone later adds a new constant, the code stops compiling until you handle it. That's a compiler-checked to-do list!

3.6 Pattern matching for instanceof (Java 16)

// Before: test, then cast, then use
if (obj instanceof String) {
    String s = (String) obj;
    System.out.println(s.length());
}

// Now: test + cast + new variable in one step
if (obj instanceof String s) {
    System.out.println(s.length());
}

// The variable can be used straight away after && (only if the test passed)
if (obj instanceof String s && !s.isEmpty()) { ... }

The variable (s) is called a pattern variable. It only exists where Java is sure the test was true. A classic use is a short equals method:

public boolean equals(Object o) {
    return o instanceof Money other
            && amount == other.amount
            && currency.equals(other.currency);
}
ℹ️ In newer Java Java 21 adds pattern matching for switch (case CardPayment c -> ...) and record patterns (if (obj instanceof Point(int x, int y))). They are only previews in Java 17, so this course uses if/instanceof chains — but it's good to know they exist.

3.7 Sealed classes and interfaces (Java 17)

Normally, anyone can implement your interface or extend your (non-final) class. Sometimes you want a closed set: a payment can be Card, UPI or Wallet — nothing else.

sealed interface Payment permits CardPayment, UpiPayment, WalletPayment { }

record CardPayment(String cardNumber, double amount) implements Payment { }   // records are final
record UpiPayment(String upiId, double amount) implements Payment { }
non-sealed class WalletPayment implements Payment { ... }                    // open again

Every permitted subclass must say how it continues the hierarchy:

ModifierMeaning
finalThe hierarchy stops here. (Records and enums are final automatically.)
sealed ... permits ...It is closed too, with its own guest list.
non-sealedOpens it again: anybody may extend this subclass.
sealed Payment→ CardPayment (final) UpiPayment (final) WalletPayment (non-sealed)→PaytmWallet

Why bother? (1) Your domain model says exactly what is possible. (2) Code that handles "all payment types" can be sure it's complete. (3) With Java 21's switch patterns, the compiler even checks you handled every subtype. Permitted subclasses must be in the same package (or module) as the sealed type — in a single file, as in our example, that's automatic.

3.8 Helpful NullPointerExceptions (Java 14+)

Consider: order.getCustomer().getAddress().getCity().toUpperCase(); — four calls, any of which could hit a null. Before Java 14 the error said only java.lang.NullPointerException with a line number. Now it tells you precisely:

Cannot invoke "Address.getCity()" because the return value of "Customer.getAddress()" is null

Read it from the end: getAddress() returned null, so we could not call getCity() on it. Fix that link of the chain. (In Java 17 this is on by default — nothing to configure.)

6. Common mistakes

⚠️ Mistake: calling getName() on a record record Student(String name) has student.name(), not getName(). Fix: use the component name as the method name.
⚠️ Mistake: trying to add a field or setter to a record 
record Student(String name) {
    private int age;                          // ❌ instance fields not allowed
    void setName(String n) { this.name = n; } // ❌ name is final
}
Fix: add it as a component (record Student(String name, int age)) and use withers to "change" values. If you truly need mutability (e.g. a JPA entity), use a normal class.
⚠️ Mistake: assigning fields in a compact constructor Product { this.price = price; } doesn't compile — Java assigns fields automatically at the end. Fix: assign to the parameter instead (price = Math.max(0, price);) or just validate.
⚠️ Mistake: storing ordinal() or comparing enums with equals on strings If you add a constant in the middle, every ordinal shifts and stored data becomes wrong. Fix: store name() (JPA: EnumType.STRING), and compare with status == OrderStatus.SHIPPED.
⚠️ Mistake: valueOf with user input OrderStatus.valueOf("shipped") throws IllegalArgumentException (case-sensitive). Fix: valueOf(input.trim().toUpperCase()) inside a try/catch, with a friendly error message.
⚠️ Mistake: forgetting the semicolon or mixing : and -> A switch expression ends with };. And within one switch you must use either all case X: or all case X ->, not both.
⚠️ Mistake: using return instead of yield in a switch block Inside case "Chennai" -> { ... } of a switch expression, return would try to exit the whole method. Fix: yield value;.
⚠️ Mistake: modifying List.of(...) UnsupportedOperationException. Fix: new ArrayList<>(List.of(...)) when you need a modifiable list.
⚠️ Mistake: text block opening on the same line String s = """Hello"""; doesn't compile — the opening """ must be followed by a line break.

7. Best practices

  • Use records for DTOs, value objects, configuration properties and method results that just carry data. Use classes for things with identity and changing state (entities, services).
  • Validate in the compact constructor so invalid objects can't exist. Make collections inside records immutable with List.copyOf.
  • Prefer enums over String/int constants for fixed sets (statuses, roles, types). Put behaviour into the enum when it belongs to each constant.
  • Prefer switch expressions with ->; for enums, list all constants and skip default so the compiler warns you when a new constant is added.
  • Use var only when the type is obvious from the right-hand side. Never for public APIs (it isn't allowed there anyway).
  • Use text blocks for any multi-line SQL, JSON or HTML — especially JSON in tests.
  • Use sealed hierarchies to model closed sets of alternatives (payment types, API results like Success/Failure).
  • Use List.of/Map.of for constants and test data; return unmodifiable collections from methods to protect your data.
  • Prefer strip() and isBlank() over trim() and isEmpty() for user input.

8. Key takeaways

  • var infers local variable types; Java is still statically typed.
  • Text blocks (""") make multi-line strings readable; use formatted() to fill placeholders.
  • A record is an immutable data class: fields, constructor, accessors (name()), equals/hashCode/toString generated. Validate in the compact constructor.
  • Records are the go-to choice for DTOs in Spring; JPA entities stay normal classes.
  • Enums are full classes: fields, constructors, methods, per-constant behaviour; compare with ==; store by name.
  • Sealed types (sealed ... permits) restrict who can extend them; subclasses are final, sealed or non-sealed.
  • Switch expressions: ->, no fall-through, multiple labels, yield, must be exhaustive.
  • obj instanceof Type t tests and casts in one step.
  • Helpful NPE messages tell you exactly which value was null.
  • List.of/Set.of/Map.of create immutable, null-free collections.

3. Smart enum. Create enum Plan with constants FREE(0, 1), BASIC(199, 5), PREMIUM(499, 20) where the numbers are monthly price and max devices. Add yearlyPrice() (12 months, 2 months free for non-free plans) and print a table of all plans with values().

Hint / solution 
enum Plan {
    FREE(0, 1), BASIC(199, 5), PREMIUM(499, 20);

    private final int monthlyPrice;
    private final int maxDevices;

    Plan(int monthlyPrice, int maxDevices) {
        this.monthlyPrice = monthlyPrice;
        this.maxDevices = maxDevices;
    }

    int yearlyPrice() { return monthlyPrice * 10; }   // pay 10, get 12 (FREE stays 0)
    int maxDevices() { return maxDevices; }
}

for (Plan p : Plan.values()) {
    System.out.printf("%-8s devices=%-3d yearly=Rs.%d%n", p, p.maxDevices(), p.yearlyPrice());
}
// FREE     devices=1   yearly=Rs.0
// BASIC    devices=5   yearly=Rs.1990
// PREMIUM  devices=20  yearly=Rs.4990

4. Switch expression. Write static String grade(int marks) using a switch expression on marks / 10: 9–10 → "A", 8 → "B", 7 → "C", 5–6 → "D", anything else → "F". Then a second switch expression on a Plan (from exercise 3) returning a welcome message, with no default.

10. Interview questions

Q1. What is a record in Java? What does the compiler generate?

A record (Java 16) is a special, transparent, immutable data carrier class declared as record Name(components). The compiler generates private final fields, a canonical constructor, accessor methods named after the components, and equals, hashCode and toString based on all components. Records are implicitly final and extend java.lang.Record.

Q2. Can records have methods, static fields, or implement interfaces? Can they extend a class?

They can have instance and static methods, static fields, nested types, additional constructors (which must delegate to the canonical one) and can implement interfaces. They cannot declare extra instance fields and cannot extend any class (they implicitly extend Record). They can't be extended either (implicitly final).

Q3. What is a compact constructor?

A canonical constructor of a record written without the parameter list: Product { ... }. It's used for validation and normalisation of parameters; field assignment happens automatically at the end, so you must not assign this.x inside it.

Q4. Why are records good for DTOs but not for JPA entities?

DTOs are just data to transfer — records give immutability, concise code, and correct equals/toString, and Jackson supports them. JPA entities need a no-args constructor, mutable (non-final) fields for lazy loading/proxies (Hibernate creates subclasses), and identity-based lifecycle — all things records don't allow.

Q5. What are sealed classes and why use them?

A sealed class/interface (Java 17) restricts which classes may extend/implement it, listed with permits. Each permitted subclass must be final, sealed or non-sealed. Benefits: an explicit, closed domain model; the compiler (and readers) know all possible subtypes, enabling exhaustive handling (exhaustive pattern matching in switch from Java 21); prevents unexpected extensions of a library API.

Q6. What's the difference between a switch statement and a switch expression?

A switch expression produces a value (String s = switch (x) { ... };), must be exhaustive, and with arrow labels has no fall-through. Blocks use yield to return a value. A statement just executes code; the old colon form falls through unless break is used. The arrow form can also be used for statements.

Q7. Explain pattern matching for instanceof.

if (obj instanceof String s) tests the type, casts and binds the result to a new variable s in one step. The pattern variable is in scope only where the match is definitely true (e.g. after && or in the if-block). It removes redundant casts and ClassCastException risks.

Q8. Can enums have constructors? Why compare enums with ==?

Yes — enum constructors are implicitly private and run once per constant when the enum class loads. Each enum constant is a singleton, so == is correct, null-safe on the left side, and faster than equals. Enums can also implement interfaces and have abstract methods with constant-specific bodies.

Q9. What is the difference between List.of() and Arrays.asList()?

List.of returns a fully immutable list and rejects null elements. Arrays.asList returns a fixed-size list backed by the array: you can't add/remove, but you can set elements (which changes the array), and nulls are allowed.

Q10. What are some limitations of var?

Only for local variables with initializers, loop variables, try-with-resources and lambda parameters. Not for fields, method parameters or return types; not with null, array initializers or lambdas without a target type. Overuse hurts readability when the type isn't obvious; with diamond (var list = new ArrayList<>()) it infers ArrayList<Object>.
