37. Spring JDBC with JdbcTemplate

Talk to a real SQL database from Spring Boot with a fraction of the code raw JDBC needs — using JdbcTemplate, NamedParameterJdbcTemplate and the modern JdbcClient.

1. Why this matters

Until now our Spring Boot apps kept data in a Map — it vanished on every restart. Real applications store data in a database. In topic 19 you did this with plain JDBC and saw how much code one simple query needs.

Spring JDBC is the lightest way to use SQL from Spring: you still write the SQL, but Spring does all the plumbing. It is used a lot at work:

  • Reports and dashboards with complex SQL (joins, GROUP BY, window functions).
  • Batch jobs that insert or update thousands of rows fast.
  • Teams that prefer to control every SQL statement for performance.
  • Next to JPA in the same project: JPA for normal CRUD, JdbcTemplate for the tricky queries.

It also teaches you what really happens underneath JPA (topic 38) — and interviewers often ask "JdbcTemplate vs JPA?".

2. Real-life analogy

🚕 Driving yourself vs taking a taxi
  • Raw JDBC = driving your own old car: you unlock it, start the engine, drive, find parking, lock it, and if anything breaks on the way you deal with it — every single trip (open connection, prepare statement, loop the result set, close everything, handle SQLException).
  • JdbcTemplate = a taxi: you only say where to go (your SQL) and what to do on arrival (your RowMapper). The driver handles the car, the route and the parking (connections, statements, closing, errors).
  • The connection pool (HikariCP) = the taxi stand: a few cars are always waiting, so you don't have to buy a new car for every trip.
  • JPA (next topic) = a full travel agency: you say "I want to be in Goa" and they plan everything — convenient, but you see less of what happens.

3. Concepts step by step

3.1 Recap: the pain of raw JDBC

Finding one student by id with plain JDBC (topic 19):

❌ Raw JDBCpublic Optional<Student> findById(long id) {
    String sql = "SELECT id, name, email, course, marks, enrolled_on FROM student WHERE id = ?";
    try (Connection con = DriverManager.getConnection(URL, USER, PASSWORD);   // 1. connect
         PreparedStatement ps = con.prepareStatement(sql)) {                  // 2. prepare
        ps.setLong(1, id);                                                    // 3. parameters
        try (ResultSet rs = ps.executeQuery()) {                              // 4. execute
            if (rs.next()) {                                                  // 5. loop / read
                return Optional.of(new Student(rs.getLong("id"), rs.getString("name"), ...));
            }
            return Optional.empty();
        }
    } catch (SQLException e) {                                                // 6. checked exception
        throw new RuntimeException(e);                                        //    vendor-specific codes
    }                                                                         // 7. closing (try-with-resources)
}

And the same with JdbcClient:

✅ Spring JDBCpublic Optional<Student> findById(long id) {
    return jdbcClient.sql("SELECT id, name, email, course, marks, enrolled_on FROM student WHERE id = :id")
            .param("id", id)
            .query(Student.class)
            .optional();
}
JobRaw JDBCSpring JDBC
Open / close connectionYouSpring (from the pool)
Create PreparedStatement, set parametersYouSpring (you pass values)
Loop over ResultSetYouSpring (you map ONE row)
Close ResultSet/Statement, even on errorYouSpring
Checked SQLException with vendor codesYouTranslated to unchecked DataAccessException
Join Spring transactions (@Transactional)HardAutomatic
Write the SQLYouStill you ✅ (full control)

3.2 The DataSource and HikariCP — auto-configured

A DataSource is a Java interface (javax.sql.DataSource) that hands out database connections. Opening a real connection is slow (network, login, …), so production apps use a connection pool: a set of already-open connections that are borrowed and returned.

JdbcTemplate→ borrow → HikariCP pool
10 open connections→ H2 / MySQL / PostgreSQL… then connection returned to the pool

Add spring-boot-starter-jdbc + a database driver, and Spring Boot creates everything automatically:

pom.xml<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-jdbc</artifactId>   <!-- spring-jdbc + HikariCP -->
</dependency>
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>                          <!-- the database (driver + engine) -->
    <scope>runtime</scope>
</dependency>
application.propertiesspring.datasource.url=jdbc:h2:mem:studentdb;DB_CLOSE_DELAY=-1
spring.datasource.username=sa
spring.datasource.password=
spring.datasource.hikari.maximum-pool-size=10
spring.datasource.hikari.pool-name=StudentPool
Bean Spring Boot createsType
dataSourceHikariDataSource (the pool)
jdbcTemplateJdbcTemplate
namedParameterJdbcTemplateNamedParameterJdbcTemplate
jdbcClientJdbcClient (Boot 3.2+)
transactionManagerDataSourceTransactionManager (for @Transactional, topic 42)
ℹ️ No URL at all? If H2 is on the classpath and you set no spring.datasource.url, Boot creates an embedded in-memory database with a random name. We set the URL so the H2 console can find it by name. For MySQL (topic 43) you'd just change the URL, username, password and driver dependency — the Java code stays the same.

Useful Hikari settings: maximum-pool-size (default 10), minimum-idle, connection-timeout (how long to wait for a free connection, default 30 s), idle-timeout, max-lifetime. The defaults are good for most apps.

3.3 schema.sql and data.sql

At startup Spring Boot looks for two files in src/main/resources:

  • schema.sql — DDL: CREATE TABLE… (runs first)
  • data.sql — DML: INSERT sample rows (runs second)
schema.sqlDROP TABLE IF EXISTS student;

    id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,   -- DB generates ids
    name        VARCHAR(100) NOT NULL,
    email       VARCHAR(150) NOT NULL UNIQUE,
    course      VARCHAR(50)  NOT NULL,
    marks       INT          NOT NULL CHECK (marks BETWEEN 0 AND 100),
    enrolled_on DATE         NOT NULL
);
data.sqlINSERT INTO student (name, email, course, marks, enrolled_on)
VALUES ('Asha Rao', 'asha@college.edu', 'Java', 92, DATE '2026-06-01');
-- ... 4 more rows
spring.sql.init.modeMeaning
embedded (default)Run the scripts only for embedded databases (H2, HSQL, Derby)

⚠️ Not for production schema changes These scripts run on every start. Real projects manage schema changes with a migration tool like Flyway (topic 43), which runs each change exactly once and keeps a history. Also: when you use JPA (topic 38) with ddl-auto, set spring.jpa.defer-datasource-initialization=true if you want data.sql to run after Hibernate creates the tables.

3.5 JdbcTemplate — the core methods

MethodUse forReturns
query(sql, rowMapper, args...)SELECT many rowsList<T> (empty list if none)
queryForObject(sql, rowMapper, args...)SELECT exactly one rowT — throws EmptyResultDataAccessException if 0 rows, IncorrectResultSizeDataAccessException if 2+
queryForObject(sql, Long.class, args...)One row, one column (COUNT, MAX, a name)Long, String…
queryForList(sql, args...)Quick look without a mapperList<Map<String, Object>>
update(sql, args...)INSERT, UPDATE, DELETEint = number of affected rows
update(PreparedStatementCreator, keyHolder)INSERT and get the generated idrows; id goes into the KeyHolder
batchUpdate(sql, List<Object[]>)Many INSERT/UPDATEs at once (fast)int[]
execute(sql)DDL (CREATE TABLE…)void
// many rows
List<Student> javaStudents = jdbcTemplate.query(
        "SELECT * FROM student WHERE course = ?", StudentRowMapper.INSTANCE, "Java");

// one value
Long count = jdbcTemplate.queryForObject("SELECT COUNT(*) FROM student", Long.class);

// change data
int rows = jdbcTemplate.update("UPDATE student SET marks = ? WHERE id = ?", 95, 1L);   // rows == 1

Each ? is a placeholder filled by the arguments in order. Spring uses a PreparedStatement, so values are sent separately from the SQL — safe from SQL injection (topic 19).

3.6 RowMapper — "how one row becomes one object"

RowMapper<T> is a functional interface with one method: T mapRow(ResultSet rs, int rowNum). JdbcTemplate runs the loop and calls it once per row.

repository/StudentRowMapper.javapublic class StudentRowMapper implements RowMapper<Student> {
    public static final StudentRowMapper INSTANCE = new StudentRowMapper();

    @Override
    public Student mapRow(ResultSet rs, int rowNum) throws SQLException {
        return new Student(
                rs.getLong("id"),
                rs.getString("name"),
                rs.getString("email"),
                rs.getString("course"),
                rs.getInt("marks"),
                rs.getObject("enrolled_on", LocalDate.class));   // DATE -> LocalDate
    }
}

Because it is a functional interface, small mappers can be lambdas (topic 13):

jdbcTemplate.query("SELECT course, COUNT(*) AS students FROM student GROUP BY course",
        (rs, rowNum) -> new CourseCount(rs.getString("course"), rs.getLong("students")));

Ready-made mappers: DataClassRowMapper (records/constructors) and BeanPropertyRowMapper (classes with setters) map columns to properties by name — and they understand that enrolled_on means enrolledOn.

3.7 NamedParameterJdbcTemplate — names instead of question marks

With many parameters, ? becomes error-prone: was marks the 4th or the 5th? Named parameters fix this:

// JdbcTemplate: position matters
jdbcTemplate.update("UPDATE student SET name = ?, email = ?, course = ?, marks = ? WHERE id = ?",
        s.name(), s.email(), s.course(), s.marks(), s.id());

// NamedParameterJdbcTemplate: names, any order
namedJdbc.update("UPDATE student SET name = :name, email = :email, course = :course, marks = :marks WHERE id = :id",
        new MapSqlParameterSource()
                .addValue("id", s.id())
                .addValue("name", s.name())
                .addValue("email", s.email())
                .addValue("course", s.course())
                .addValue("marks", s.marks()));

// simple cases: a Map works too
namedJdbc.query("SELECT * FROM student WHERE id = :id", Map.of("id", 1L), StudentRowMapper.INSTANCE);

Bonus: you can pass a list for IN clauses: "WHERE id IN (:ids)" with Map.of("ids", List.of(1, 2, 3)) — it expands automatically. BeanPropertySqlParameterSource(object) reads parameter values from an object's getters.

3.8 KeyHolder — getting the generated id

The database generates the id when inserting. To return it to the client (for the Location header), ask JDBC to hand it back via a KeyHolder:

KeyHolder keyHolder = new GeneratedKeyHolder();
jdbcTemplate.update(connection -> {
    PreparedStatement ps = connection.prepareStatement(sql, new String[]{"id"});   // "return the id column"
    ps.setString(1, s.name());
    // ... other parameters
    return ps;
}, keyHolder);
long newId = keyHolder.getKey().longValue();

The plain update(sql, args...) can't return keys, so here we build the PreparedStatement ourselves with a lambda (a PreparedStatementCreator). Named and JdbcClient versions are shorter: namedJdbc.update(sql, params, keyHolder, new String[]{"id"}) and jdbcClient.sql(sql)...update(keyHolder, "id").

ℹ️ SimpleJdbcInsert Spring also offers SimpleJdbcInsert, which builds the INSERT for you from the table metadata: new SimpleJdbcInsert(dataSource).withTableName("student").usingGeneratedKeyColumns("id").executeAndReturnKey(params).

3.9 JdbcClient — the modern fluent API (Spring 6.1+)

JdbcClient combines the best of both templates in one readable chain:

.sql("…")→ .param(…) / .params(…) / .paramSource(obj)→ .query(Type.class or RowMapper)→ .list() / .single() / .optional() / .set()
.sql("INSERT/UPDATE/DELETE …")→ .param(…)→ .update() or .update(keyHolder, "id") 
List<Student> all = jdbcClient.sql("SELECT * FROM student ORDER BY id")
        .query(Student.class)          // automatic mapping to the record, no RowMapper
        .list();

Optional<Student> one = jdbcClient.sql("SELECT * FROM student WHERE id = :id")
        .param("id", 3)
        .query(Student.class)
        .optional();                   // no exception for 0 rows

long count = jdbcClient.sql("SELECT COUNT(*) FROM student").query(Long.class).single();

int rows = jdbcClient.sql("UPDATE student SET name = :name, marks = :marks WHERE id = :id")
        .paramSource(student)          // takes :name, :marks, :id from the record's accessors
        .update();
  • Supports both ? (positional, .param(value)) and :name (named) parameters.
  • query(Student.class) maps columns to record components/properties by name (snake_case ⇄ camelCase).
  • It is built on top of JdbcTemplate/NamedParameterJdbcTemplate — same safety, same transactions.
💡 Which one should I use? For new code in Spring Boot 3.2+, JdbcClient is the most pleasant. You'll still see JdbcTemplate and NamedParameterJdbcTemplate in many existing projects (and they're needed for some features like batchUpdate), so you should know all three.

3.10 DataAccessException — one exception family for all databases

Spring translates SQLException (checked, with database-specific error codes) into an unchecked hierarchy that is the same for every database:

ExceptionTypical cause
DuplicateKeyExceptionUNIQUE / primary key violation (our duplicate email → 409)
DataIntegrityViolationExceptionNOT NULL, CHECK, foreign key violation
EmptyResultDataAccessExceptionqueryForObject found no row
BadSqlGrammarExceptionTypo in SQL, unknown table/column
CannotGetJdbcConnectionExceptionDatabase down / wrong URL or password

So your code can say catch (DuplicateKeyException e) and it works on H2, MySQL and PostgreSQL alike. This is also why @Repository exists as a separate stereotype (topic 23): it enables this translation for your repository classes.

3.11 JDBC vs JPA — when to use which?

Spring JDBC (JdbcTemplate / JdbcClient)Spring Data JPA (topic 38)
You writeAll SQL + row mappingEntity classes; most SQL is generated
Control / transparencyFull — you see every statementLess — Hibernate decides (can surprise you: N+1, lazy loading)
Simple CRUDMore codeAlmost no code (save, findById…)
Complex reports, bulk updatesExcellentPossible, but often awkward
Relationships (orders ↔ items)Manual joins and mappingMapped with annotations
Learning curveLow (if you know SQL)Higher (entity states, caching, fetching)
PerformanceVery predictableGood, but needs care

Rule of thumb: JPA for a typical domain-heavy CRUD app; JDBC for reporting, batch, and performance-critical SQL. Mixing both in one app is common and perfectly fine. (There is also Spring Data JDBC, a simpler, non-Hibernate middle ground.)

@Repository
@ConditionalOnProperty(name = "app.repository.type", havingValue = "jdbc-client")
public class JdbcClientStudentRepository implements StudentRepository { ... }

This is the @Conditional idea from topic 26 — the same trick Spring Boot auto-configuration uses. Exactly one bean exists, and StudentService receives it through the interface.

4.2 JdbcTemplate implementation (key parts)

repository/JdbcTemplateStudentRepository.java@Override
public Optional<Student> findById(long id) {
    try {
        Student student = jdbcTemplate.queryForObject(
                SELECT_ALL + " WHERE id = ?", StudentRowMapper.INSTANCE, id);
        return Optional.ofNullable(student);
    } catch (EmptyResultDataAccessException e) {      // 0 rows
        return Optional.empty();
    }
}

@Override
public boolean update(Student s) {
    int rows = jdbcTemplate.update(
            "UPDATE student SET name = ?, email = ?, course = ?, marks = ?, enrolled_on = ? WHERE id = ?",
            s.name(), s.email(), s.course(), s.marks(), s.enrolledOn(), s.id());
    return rows == 1;                                  // 0 means: no student with that id
}

@Override
public List<CourseStats> courseStatistics() {
    return jdbcTemplate.query("""
                    SELECT course, COUNT(*) AS students, AVG(CAST(marks AS DOUBLE)) AS avg_marks
                    FROM student
                    GROUP BY course
                    ORDER BY course
                    """,
            (rs, rowNum) -> new CourseStats(rs.getString("course"), rs.getLong("students"),
                    Math.round(rs.getDouble("avg_marks") * 10) / 10.0));
}
  • Using the affected row count from update is a neat way to detect "not found" without an extra SELECT.
  • Text blocks (""", topic 15) keep longer SQL readable.
  • LocalDate can be passed directly as a parameter — the H2 and MySQL drivers understand java.time types.

4.3 JdbcClient implementation (key parts)

repository/JdbcClientStudentRepository.java@Override
public Student save(Student s) {
    KeyHolder keyHolder = new GeneratedKeyHolder();
    jdbcClient.sql("""
                    INSERT INTO student (name, email, course, marks, enrolled_on)
                    VALUES (:name, :email, :course, :marks, :enrolledOn)
                    """)
            .param("name", s.name())
            .param("email", s.email())
            .param("course", s.course())
            .param("marks", s.marks())
            .param("enrolledOn", s.enrolledOn())
            .update(keyHolder, "id");
    return s.withId(keyHolder.getKey().longValue());
}

@Override
public List<Student> findByCourse(String course) {
    return jdbcClient.sql(SELECT_ALL + " WHERE LOWER(course) = LOWER(?) ORDER BY marks DESC")
            .param(course)                        // positional parameter
            .query(StudentRowMapper.INSTANCE)     // your own RowMapper also works
            .list();
}

4.4 The contract test

src/test/java/.../JdbcClientStudentRepositoryTest.java@JdbcTest(properties = "app.repository.type=jdbc-client")   // only the DB part of Spring Boot
@Import(JdbcClientStudentRepository.class)                    // + our repository
class JdbcClientStudentRepositoryTest extends StudentRepositoryContractTest { }
StudentRepositoryContractTest.java (part)@Transactional          // each test is rolled back -> always the same 5 students
abstract class StudentRepositoryContractTest {

    @Autowired
    protected StudentRepository repository;

    @Test
    void duplicateEmailIsTranslatedToDuplicateKeyException() {
        Student duplicate = new Student(null, "Copy", "asha@college.edu", "Java", 50, LocalDate.of(2026, 7, 1));
        assertThatThrownBy(() -> repository.save(duplicate)).isInstanceOf(DuplicateKeyException.class);
    }
}

@JdbcTest starts an embedded database, runs schema.sql/data.sql, and makes each test transactional (rolled back at the end). Note the explicit @Transactional on the abstract class: Spring looks for it on the class that declares the test methods, so without it changes from one test would leak into the next — we hit exactly that bug while writing this lesson!

6. Common mistakes

🛑 Mistake: building SQL with string concatenation "SELECT * FROM student WHERE name = '" + name + "'" — SQL injection (topic 19).
Fix: Always use ? or :name parameters. For dynamic ORDER BY columns, which can't be parameters, use a whitelist of allowed column names.
⚠️ Mistake: queryForObject when there may be no row Throws EmptyResultDataAccessException → 500.
Fix: Catch it and return Optional.empty(), use query(...) + stream().findFirst(), or JdbcClient's .optional().
⚠️ Mistake: column name typos in the RowMapper rs.getString("enrolledOn") when the column is enrolled_on → SQLException: Column not found.
Fix: Use the SQL column names (or aliases with AS) in RowMappers; avoid SELECT * so the column list is explicit.
⚠️ Mistake: forgetting the driver or starter "Failed to determine a suitable driver class" or no JdbcTemplate bean.
Fix: Add spring-boot-starter-jdbc and the database driver (H2 / mysql-connector-j), and set spring.datasource.url for non-embedded databases.
⚠️ Mistake: H2 console says "Database not found" Using the default URL jdbc:h2:~/test in the login form.
Fix: Type exactly the URL from application.properties: jdbc:h2:mem:studentdb.
⚠️ Mistake: data.sql fails with "Table not found" Script order or, with JPA, Hibernate creates tables after data.sql ran.
Fix: Create tables in schema.sql; with JPA set spring.jpa.defer-datasource-initialization=true.
⚠️ Mistake: creating new JdbcTemplate(...) or DriverManager connections yourself Bypasses the pool and Spring transactions.
Fix: Inject the auto-configured JdbcTemplate/JdbcClient bean.
⚠️ Mistake: returning database error messages to clients ex.getMessage() of a DuplicateKeyException contains the full SQL and constraint names.
Fix: Map to a friendly message in the exception handler (as ApiExceptionHandler does) and log the details.

7. Best practices

  • Keep all SQL in repository classes behind an interface; services never see SQL.
  • Always use parameters (?, :name) — never concatenate user input.
  • Prefer JdbcClient for new code; named parameters for statements with many values.
  • List columns explicitly instead of SELECT *: clearer, faster, safer when columns are added.
  • Make RowMappers stateless and reusable (a constant like StudentRowMapper.INSTANCE).
  • Return Optional for "maybe one row"; use the affected-row count of update to detect "not found".
  • Use batchUpdate for bulk inserts/updates instead of one call per row.
  • Let the database protect integrity too: NOT NULL, UNIQUE, CHECK, foreign keys — then translate DataAccessExceptions into proper HTTP errors.
  • Use Flyway (topic 43) instead of schema.sql for real schemas; disable the H2 console outside development.
  • Leave HikariCP defaults unless you have measurements; a bigger pool is not automatically faster.
  • Wrap multi-statement operations in @Transactional service methods (topic 42).

8. Key takeaways

  • Raw JDBC needs lots of boilerplate; Spring JDBC handles connections, statements, loops, closing and exception translation — you keep writing SQL.
  • spring-boot-starter-jdbc + a driver → Boot auto-configures a HikariCP DataSource, JdbcTemplate, NamedParameterJdbcTemplate, JdbcClient and a transaction manager.
  • schema.sql and data.sql initialise the database (controlled by spring.sql.init.mode).
  • The H2 console (spring.h2.console.enabled=true) lets you inspect the in-memory DB — dev only.
  • JdbcTemplate: query (list), queryForObject (exactly one), update (insert/update/delete → row count).
  • A RowMapper converts one row into one object; it can be a class or a lambda.
  • NamedParameterJdbcTemplate uses :name parameters; KeyHolder returns generated ids.
  • JdbcClient (Spring 6.1) is a fluent API with automatic mapping and .list()/.single()/.optional().
  • JDBC = full SQL control (reports, batch); JPA = less code for domain CRUD. Both can live in one app.

Medium

Search with optional filters. Add GET /api/students/search?course=Java&minMarks=80 where both parameters are optional. Use NamedParameterJdbcTemplate or JdbcClient and build the WHERE clause safely.

Hint / solution 
public List<Student> search(String course, Integer minMarks) {
    StringBuilder sql = new StringBuilder(SELECT_ALL + " WHERE 1 = 1");
    MapSqlParameterSource params = new MapSqlParameterSource();
    if (course != null) {
        sql.append(" AND LOWER(course) = LOWER(:course)");
        params.addValue("course", course);
    }
    if (minMarks != null) {
        sql.append(" AND marks >= :minMarks");
        params.addValue("minMarks", minMarks);
    }
    sql.append(" ORDER BY marks DESC");
    return jdbc.query(sql.toString(), params, StudentRowMapper.INSTANCE);
}

We only append fixed SQL fragments; user values always go through parameters, so this stays injection-safe.

Medium

Bulk import with batchUpdate. Add POST /api/students/bulk that accepts a JSON array of StudentRequest and inserts them all with one jdbcTemplate.batchUpdate call. Return how many rows were inserted.

Hint / solution 
public int saveAll(List<Student> students) {
    List<Object[]> rows = students.stream()
            .map(s -> new Object[]{s.name(), s.email(), s.course(), s.marks(), s.enrolledOn()})
            .toList();
    int[] counts = jdbcTemplate.batchUpdate(
            "INSERT INTO student (name, email, course, marks, enrolled_on) VALUES (?, ?, ?, ?, ?)", rows);
    return Arrays.stream(counts).sum();
}

In the controller use @RequestBody List<@Valid StudentRequest> requests. Batching sends many statements in one round trip — much faster for large imports. Put it in a @Transactional service method so a failure rolls back everything (topic 42).

10. Interview questions

Q1. What problems does JdbcTemplate solve compared with plain JDBC?

It removes boilerplate: acquiring and releasing connections, creating statements and setting parameters, iterating result sets, closing resources in all cases, and converting checked SQLExceptions into Spring's unchecked, database-independent DataAccessException hierarchy. It also participates automatically in Spring-managed transactions. You still write the SQL.

Q2. What is a RowMapper?

A functional interface RowMapper<T> with T mapRow(ResultSet rs, int rowNum) that converts the current row into an object. JdbcTemplate iterates the result set and calls it once per row. It can be a class, a lambda, or a ready-made BeanPropertyRowMapper/DataClassRowMapper.

Q3. Difference between query, queryForObject and queryForList?

query returns a List<T> using a RowMapper (empty list for no rows). queryForObject expects exactly one row and throws EmptyResultDataAccessException for zero or IncorrectResultSizeDataAccessException for more; it can map to a simple type like Long.class. queryForList returns List<Map<String, Object>> (or a list of a simple type) without a mapper.

Q4. What is NamedParameterJdbcTemplate and why use it?

A wrapper around JdbcTemplate that supports named parameters (:email) instead of positional ?. It improves readability, avoids ordering mistakes, allows reusing a parameter several times, and expands collections for IN (:ids). Parameters are supplied via a Map, MapSqlParameterSource or BeanPropertySqlParameterSource.

Q5. How do you get an auto-generated primary key after an insert?

Use a KeyHolder (GeneratedKeyHolder): jdbcTemplate.update(PreparedStatementCreator, keyHolder) where the statement is created with prepareStatement(sql, new String[]{"id"}), or namedJdbc.update(sql, params, keyHolder, keyColumns), or jdbcClient...update(keyHolder, "id"). Alternatively SimpleJdbcInsert.executeAndReturnKey.

Q6. What is JdbcClient?

A fluent JDBC API added in Spring Framework 6.1 (auto-configured in Spring Boot 3.2+). It unifies positional and named parameters, offers automatic mapping to records/beans (query(Type.class)), and terminal operations like list(), single(), optional() and update(). It delegates to JdbcTemplate/NamedParameterJdbcTemplate internally.

Q7. What is HikariCP and why do we need a connection pool?

HikariCP is a fast JDBC connection pool and Spring Boot's default DataSource. Creating a database connection is expensive (network handshake, authentication); a pool keeps a set of open connections and lends them out per operation, which greatly improves throughput and limits the load on the database (max pool size).

Q8. What are schema.sql and data.sql?

SQL scripts in src/main/resources that Spring Boot runs at startup to create the schema and insert data. By default they run only for embedded databases; spring.sql.init.mode=always runs them for any database. They're great for demos and tests; production schemas should use a migration tool like Flyway or Liquibase.

Q9. What is DataAccessException?

The root of Spring's unchecked data access exception hierarchy. Spring translates vendor-specific SQLExceptions (using error codes/SQL states) into meaningful subclasses such as DuplicateKeyException, DataIntegrityViolationException, EmptyResultDataAccessException or BadSqlGrammarException, so code is independent of the database vendor.

Q10. When would you choose JdbcTemplate over JPA?

When you need full control over SQL and performance: reporting and analytics queries, bulk/batch operations, database-specific features, simple apps with few tables, or teams strong in SQL. JPA is better for rich domain models with relationships and lots of standard CRUD. Many applications combine both.
