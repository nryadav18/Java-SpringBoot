18. Annotations & Reflection

Understand the "@ labels" you will see everywhere in Spring, write your own, read them with reflection — and build a tiny Spring-like container so Spring never feels like magic.

1. Why this matters

Look at a typical piece of Spring Boot code you will write in a few weeks:

@RestController
@RequestMapping("/api/products")
public class ProductController {

    @Autowired
    private ProductService service;

    @GetMapping("/{id}")
    public Product getOne(@PathVariable Long id) { ... }
}

Almost every line has an @Something. These are annotations. You never write new ProductController(), you never write code that connects the URL /api/products/5 to this method — and yet it works. How?

The answer is reflection: when your app starts, Spring looks at your classes while the program runs, finds these annotations, creates the objects, fills the fields, and remembers which method handles which URL.

  • Spring uses annotations + reflection for beans, injection, web endpoints, transactions, security.
  • Hibernate/JPA uses @Entity, @Id, @Column to map classes to tables.
  • Jackson uses reflection to turn objects into JSON and back.
  • JUnit finds your @Test methods with reflection and calls them (Topic 21).

You will rarely write reflection code at work. But understanding it turns Spring from "magic" into "oh, it's just doing this". That makes you far better at debugging Spring errors — and it is a favourite interview topic.

2. Real-life analogy

🧳 Luggage tags at the airport
  • An annotation is like a tag stuck on a suitcase: "FRAGILE", "PRIORITY", "Destination: DEL". The tag doesn't move the bag by itself. It is just information.
  • The airport staff and the conveyor system read the tags and act: fragile bags are handled gently, priority bags come out first. In Java, the "staff" are the compiler, Spring, JUnit, Hibernate.
  • Reflection is the X-ray scanner: it can look inside any bag (any class) while it travels — see what's inside (fields, methods), and even open a locked pocket (private fields).
  • Some tags are torn off after check-in (annotations with SOURCE retention: only the compiler sees them). Others stay on until the end of the trip (RUNTIME retention: frameworks can read them while the program runs).

3. Concepts step by step

3.1 What is an annotation?

An annotation is a label with an @ sign that you put on a class, method, field, parameter, etc. It adds metadata — information about the code — without changing what the code does.

@Override                         // on a method
public String toString() { ... }

@Deprecated(since = "2.0")         // with elements (like named parameters)
public void oldMethod() { ... }

@SuppressWarnings("unchecked")    // with a single 'value'
List list = ...;

Key idea: an annotation alone does nothing. Something must read it:

Who reads it?When?Example
The compiler (javac)While compiling@Override, @FunctionalInterface
Annotation processors (code generators)While compilingLombok's @Getter, MapStruct
Frameworks via reflectionWhile the program runsSpring's @Component, JUnit's @Test, JPA's @Entity

3.2 Built-in annotations

AnnotationMeaningWhy use it
@Override"This method overrides a parent/interface method"If you misspell the name or get the parameters wrong, the compiler gives an error instead of silently creating a new method.
@Deprecated"Don't use this any more"Callers get a warning (VS Code shows a strike-through). since and forRemoval give more info.
@FunctionalInterface"This interface has exactly one abstract method"Compile error if someone adds a second one, which would break all lambdas using it.
@SuppressWarnings("...")"Hide this compiler warning here"For warnings you've checked and accept, e.g. "unchecked", "rawtypes", "deprecation", "removal".
@SafeVarargs"My generic varargs method is safe"Removes a generics warning (rarely needed).
class Dog extends Animal {
    @Override
    String sund() { return "Woof"; }   // typo!
}
// javac: error: method does not override or implement a method from a supertype
💡 Always write @Override It costs nothing and catches real bugs. Without it, the typo above would compile, and Animal.sound() would be called instead of yours — a silent bug.

3.3 Writing your own annotation

You declare an annotation with @interface (an "annotation interface"):

import java.lang.annotation.*;

@Retention(RetentionPolicy.RUNTIME)          // keep it until runtime
@Target({ElementType.METHOD, ElementType.TYPE}) // allowed on methods and classes
public @interface Role {
    String value();                // an element (required, because no default)
    int priority() default 1;      // an optional element with a default
}

Using it:

@Role(value = "MANAGER", priority = 3)   // all elements named
public void printReport() { ... }

@Role("ADMIN")                           // shortcut: only 'value' given, name can be skipped
public void deleteOrders() { ... }

Rules for elements:

  • They look like methods with no body and no parameters.
  • Allowed types: primitives, String, Class, enums, other annotations, and arrays of these. (Not Integer, not List, not your own objects.)
  • Values must be constants known at compile time.
  • An element named value is special: if it's the only one you set, you can write @Role("ADMIN").
  • An annotation with no elements is a marker annotation, e.g. @RunMe.

3.4 Meta-annotations: @Retention and @Target

Meta-annotations are annotations you put on annotation declarations. The two most important:

@Retention — how long the annotation "lives":

RetentionPolicyKept in .javaKept in .classVisible to reflection at runtimeExample
SOURCE✅❌❌@Override, Lombok
CLASS (default!)✅✅❌Bytecode tools
RUNTIME✅✅✅Spring, JPA, JUnit annotations
🚫 The classic trap If you forget @Retention(RetentionPolicy.RUNTIME), the default is CLASS, and isAnnotationPresent(...) will always return false. No error, it just "doesn't work". This is the #1 custom-annotation bug.

@Target — where the annotation may be placed:

ElementTypeWhereSpring example
TYPEclass, interface, enum, record@Service, @Entity
METHODmethods@GetMapping, @Bean, @Transactional
FIELDfields@Autowired, @Column, @Id
PARAMETERmethod parameters@PathVariable, @RequestBody
CONSTRUCTORconstructors@Autowired on a constructor
ANNOTATION_TYPEother annotationsused to build "composed" annotations

Other meta-annotations: @Documented (show in Javadoc), @Inherited (subclasses inherit a class-level annotation), @Repeatable (can be used several times on the same element).

ℹ️ Composed annotations — a Spring favourite Spring puts annotations on annotations. For example @RestController is itself annotated with @Controller and @ResponseBody, and @Service is annotated with @Component. That's why Spring treats a @Service class as a component. @SpringBootApplication combines three annotations into one (Topic 28).

3.5 Reflection — looking at classes while the program runs

Normally your code knows the classes it uses when you write it: new Student("Asha", 88). Reflection lets code work with classes it does not know in advance — given only a Class object or even just a class name as a String.

Everything starts with a Class object — the JVM's description of a class. There is exactly one per loaded class.

Class<?> c1 = Student.class;                     // 1. from the type
Class<?> c2 = someStudent.getClass();            // 2. from an object
Class<?> c3 = Class.forName("com.shop.Student");  // 3. from a String (full name)

(Class<?> means "a Class of some type" — the ? wildcard from Topic 12.)

Reflection classRepresentsCommon methods
Classa class / interfacegetSimpleName(), getDeclaredFields(), getDeclaredMethods(), getDeclaredConstructor(...), getAnnotation(...), isAnnotationPresent(...), getInterfaces(), getSuperclass(), isAssignableFrom(...)
Fielda fieldgetName(), getType(), get(obj), set(obj, value), setAccessible(true)
Methoda methodgetName(), getParameterTypes(), getReturnType(), invoke(obj, args...)
Constructora constructornewInstance(args...)
ModifierhelperModifier.toString(field.getModifiers()) → "private static final"
💡 getXxx vs getDeclaredXxx getMethods() / getFields() → only public members, including inherited ones.
getDeclaredMethods() / getDeclaredFields() → all members (private too), but only those declared in this class, not inherited.

3.6 Doing things with reflection

Create an object without writing new:

Constructor<?> ctor = clazz.getDeclaredConstructor(String.class, int.class);
Object student = ctor.newInstance("Asha", 88);      // = new Student("Asha", 88)

Object empty = clazz.getDeclaredConstructor().newInstance();  // no-arg constructor

Call a method by its name:

Method addBonus = clazz.getMethod("addBonus", int.class);  // name + parameter types
addBonus.invoke(student, 5);                                // = student.addBonus(5)

Read/write a private field:

Field name = clazz.getDeclaredField("name");
name.setAccessible(true);           // turn off the 'private' check
System.out.println(name.get(student));
name.set(student, "Asha Rao");      // change it!
⚠️ "Isn't that breaking encapsulation?" Yes! setAccessible(true) bypasses private. That's why it is meant for frameworks and tools, not for normal business code. Since Java 9 the module system also restricts deep reflection into JDK internals (e.g. you can't freely open private fields of java.lang.String) — you'd see an InaccessibleObjectException.

3.7 Reading annotations with reflection

Every reflection object (Class, Method, Field, ...) can tell you its annotations:

for (Method m : clazz.getDeclaredMethods()) {
    if (m.isAnnotationPresent(RunMe.class)) {       // is the label there?
        Role role = m.getAnnotation(Role.class);    // get it (or null)
        if (role != null) {
            System.out.println("Needs role " + role.value());   // read its elements
        }
        m.invoke(object);                           // act on it
    }
}

This tiny loop is exactly how JUnit works: find every method with @Test and invoke it. And it's how Spring finds @GetMapping methods to register URL routes.

3.8 How Spring uses this: the DI container idea

When a Spring app starts, the container roughly does:

1. Scan classes→ 2. Keep those with @Component→ 3. Create one object each (reflection)→ 4. Inject @Autowired dependencies (reflection)→ 5. App ready

The created objects are called beans, and the place that holds them is the container (or application context). Giving an object the other objects it needs, instead of letting it create them with new, is called Dependency Injection (DI). You will study it properly in Topics 22–24 — but in Example04 you build a mini version of it yourself!

Our mini container (Example04)Real Spring
@MyComponent@Component, @Service, @Repository, @Controller
@MyAutowired on fields@Autowired (constructor injection preferred)
A List of classes to scan@ComponentScan scans packages on disk/classpath
Map<Class, Object> beansThe ApplicationContext bean registry
getBean(OrderController.class)context.getBean(OrderController.class)
Fails if no bean foundNoSuchBeanDefinitionException / "required a bean of type ... that could not be found"
Takes the first matching beanFails with NoUniqueBeanDefinitionException if there are 2+ → fix with @Primary / @Qualifier (Topic 24)

3.9 Downsides of reflection

  • Slower than direct calls (frameworks cache reflection results, so it's mostly a startup cost).
  • No compile-time safety: a typo in getMethod("adBonus") compiles fine and fails at runtime with NoSuchMethodException.
  • Breaks encapsulation with setAccessible.
  • Lots of checked exceptions (NoSuchMethodException, IllegalAccessException, InvocationTargetException...).

So: understand it, let frameworks use it, and use it yourself only for tools and generic code.

Example04 — the mini DI container ⭐

The application classes never create their dependencies:

Example04_MiniDIContainer.java (application code)@MyComponent
static class OrderService {
    @MyAutowired
    private OrderRepository repository;   // who sets this? the container!

    @MyAutowired
    private Notifier notifier;            // an INTERFACE - container finds EmailSender

    void placeOrder(int id, String item) {
        repository.save(id, item);
        notifier.notifyCustomer("Your order " + id + " for " + item + " is confirmed");
    }
}

The container does the work in its constructor:

Example04_MiniDIContainer.java (the container)// Step 1 + 2: SCAN and CREATE
for (Class<?> clazz : classesToScan) {
    if (clazz.isAnnotationPresent(MyComponent.class)) {
        Object bean = clazz.getDeclaredConstructor().newInstance();
        beans.put(clazz, bean);
    }
}

// Step 3: INJECT
for (Object bean : beans.values()) {
    for (Field field : bean.getClass().getDeclaredFields()) {
        if (field.isAnnotationPresent(MyAutowired.class)) {
            Object dependency = findBeanOfType(field.getType());
            field.setAccessible(true);
            field.set(bean, dependency);
        }
    }
}

private Object findBeanOfType(Class<?> type) {
    for (Object bean : beans.values()) {
        if (type.isAssignableFrom(bean.getClass())) {   // "can a bean of this class go into this type?"
            return bean;
        }
    }
    throw new IllegalStateException("No bean found for type " + type.getSimpleName());
}

Line by line:

  • isAnnotationPresent(MyComponent.class) — only labelled classes become beans; HelperNotABean is skipped.
  • getDeclaredConstructor().newInstance() — creates the object using its no-arg constructor.
  • We create all beans first, then inject. That way the order of the list doesn't matter.
  • type.isAssignableFrom(bean.getClass()) — "is the bean's class the same as, a subclass of, or an implementation of type?" This is why the Notifier field receives the EmailSender bean.
  • field.set(bean, dependency) — the moment of injection.
  • Asking getBean twice returns the same object — beans are singletons, like Spring's default.
💡 Try it Remove @MyComponent from EmailSender and run again. You get IllegalStateException: No bean found for type Notifier. Spring gives the same kind of error: "Parameter 0 of constructor in OrderService required a bean of type 'Notifier' that could not be found." Now you know what it means!

6. Common mistakes

🚫 Mistake: forgetting @Retention(RUNTIME) Your custom annotation is "invisible": isAnnotationPresent returns false, getAnnotation returns null.
Fix: add @Retention(RetentionPolicy.RUNTIME) to every annotation you want to read at runtime.
⚠️ Mistake: using getMethods()/getFields() to find private members They only return public members.
Fix: use getDeclaredMethods()/getDeclaredFields() and setAccessible(true).
⚠️ Mistake: IllegalAccessException when reading a private field
Fix: call field.setAccessible(true) before get/set.
⚠️ Mistake: NoSuchMethodException with the right name getMethod("addBonus") fails because the method takes an int.
Fix: pass parameter types: getMethod("addBonus", int.class). Note int.class ≠ Integer.class.
⚠️ Mistake: confusing InvocationTargetException If the method you invoke throws an exception, reflection wraps it in InvocationTargetException.
Fix: look at e.getCause() to see the real exception. (You will see this inside long Spring stack traces too.)
⚠️ Mistake: no no-arg constructor getDeclaredConstructor().newInstance() throws NoSuchMethodException if the class only has constructors with parameters. JPA entities need a no-arg constructor for exactly this reason (Topic 38).
⚠️ Mistake: putting a wrong type in an annotation element Integer count(); or List<String> names(); do not compile.
Fix: use int, String[], enums, Class.

7. Best practices

  • Always use @Override when overriding — it's free safety.
  • Use @SuppressWarnings as narrowly as possible (on one method or variable, not a whole class), and only after you understand the warning.
  • When deprecating, add since, a Javadoc @deprecated tag that points to the replacement, and forRemoval = true if it will be deleted.
  • Give custom annotations a clear @Target so they can't be misused, and sensible defaults.
  • Prefer normal code over reflection in business logic. Reflection is for frameworks, libraries, tests and tools.
  • Cache reflection lookups (Method, Field objects) if you use them repeatedly — frameworks do this.
  • In Spring, prefer constructor injection over field injection (@Autowired on fields, like our mini container). You will see why in Topic 24 — the short version: dependencies become final, required and easy to pass in tests.

8. Key takeaways

  • Annotations are metadata labels; they do nothing until a compiler, tool or framework reads them.
  • Built-ins: @Override, @Deprecated, @FunctionalInterface, @SuppressWarnings.
  • Declare your own with @interface; elements look like methods and can have default values.
  • @Retention(RUNTIME) is required to read an annotation with reflection; @Target controls where it can be used.
  • Reflection works from a Class object: inspect and use Field, Method, Constructor at runtime.
  • getDeclaredXxx gives all members of this class; setAccessible(true) opens private ones.
  • Spring = scan for @Component → create beans with reflection → inject @Autowired dependencies → ready. You built that in Example04.
  • Reflection is powerful but slower, unchecked at compile time, and breaks encapsulation — leave it to frameworks.

Medium

Mini JUnit. Create @MyTest. Write a class CalculatorChecks with three @MyTest methods; one of them throws an exception. Your runner must call every test method, catch failures, and print PASS/FAIL for each and a summary like 2 passed, 1 failed.

Hint / solution
int passed = 0, failed = 0;
Object instance = CalculatorChecks.class.getDeclaredConstructor().newInstance();
for (Method m : CalculatorChecks.class.getDeclaredMethods()) {
    if (!m.isAnnotationPresent(MyTest.class)) continue;
    try {
        m.invoke(instance);
        System.out.println("PASS " + m.getName());
        passed++;
    } catch (InvocationTargetException e) {          // the test itself threw
        System.out.println("FAIL " + m.getName() + ": " + e.getCause());
        failed++;
    }
}
System.out.println(passed + " passed, " + failed + " failed");

That's essentially what JUnit does — plus a lot of polish (Topic 21).

Medium

Object to "JSON". Write toJson(Object obj) that uses reflection to produce {"name":"Asha","marks":88} from any object's declared fields (skip static fields). Add a @JsonIgnore annotation that hides a field. (This is what Jackson does!)

Hint / solution
static String toJson(Object obj) throws IllegalAccessException {
    StringJoiner json = new StringJoiner(",", "{", "}");
    for (Field f : obj.getClass().getDeclaredFields()) {
        if (Modifier.isStatic(f.getModifiers())) continue;
        if (f.isAnnotationPresent(JsonIgnore.class)) continue;
        f.setAccessible(true);
        Object v = f.get(obj);
        String value = (v instanceof String) ? "\"" + v + "\"" : String.valueOf(v);
        json.add("\"" + f.getName() + "\":" + value);
    }
    return json.toString();
}
Challenge

Constructor injection in the mini container. Change Example04 so OrderService has final fields and a constructor OrderService(OrderRepository repo, Notifier notifier). Make the container create beans by finding the constructor, resolving each parameter type to a bean (creating it first if needed), then calling newInstance(args).

Hint / solution
private final Map<Class<?>, Object> beans = new HashMap<>();
private final List<Class<?>> componentClasses;   // the @MyComponent classes

Object getOrCreate(Class<?> type) throws Exception {
    // 1. already created?
    for (Object b : beans.values()) if (type.isAssignableFrom(b.getClass())) return b;
    // 2. find the component class that fits the type
    Class<?> impl = componentClasses.stream()
            .filter(type::isAssignableFrom).findFirst()
            .orElseThrow(() -> new IllegalStateException("No bean for " + type));
    // 3. use its (single) constructor, resolving parameters recursively
    Constructor<?> ctor = impl.getDeclaredConstructors()[0];
    Object[] args = new Object[ctor.getParameterCount()];
    Class<?>[] paramTypes = ctor.getParameterTypes();
    for (int i = 0; i < args.length; i++) {
        args[i] = getOrCreate(paramTypes[i]);       // dependencies first
    }
    ctor.setAccessible(true);
    Object bean = ctor.newInstance(args);
    beans.put(impl, bean);
    return bean;
}

Bonus question: what happens if A needs B and B needs A? (Infinite recursion — a circular dependency, which Spring also reports as an error. Topic 24.)

10. Interview questions

Q1. What is an annotation in Java?

A form of metadata attached to program elements (classes, methods, fields, parameters...). It doesn't change the code's behaviour by itself; it's processed by the compiler, annotation processors at compile time, or frameworks via reflection at runtime.

Q2. What are the retention policies and what is the default?

SOURCE (discarded by the compiler), CLASS (stored in the .class file but not available at runtime — this is the default), and RUNTIME (stored and readable via reflection). Frameworks like Spring need RUNTIME.

Q3. What is the purpose of @Override if the code works without it?

It asks the compiler to verify that the method really overrides a superclass or interface method. It turns mistakes like a misspelled name or wrong parameter type into compile errors instead of silent bugs, and documents intent.

Q4. What is reflection? Give real uses.

Reflection is the ability of a program to inspect and manipulate classes, methods, fields and constructors at runtime, even ones not known at compile time. Uses: dependency injection (Spring), ORM mapping (Hibernate), JSON serialization (Jackson), test frameworks (JUnit finding @Test methods), IDE tools, and mocking libraries.

Q5. Difference between getMethods() and getDeclaredMethods()?

getMethods() returns all public methods including inherited ones. getDeclaredMethods() returns all methods declared in that class (any access modifier) but not inherited ones.

Q6. What are the drawbacks of reflection?

Performance overhead, loss of compile-time type checking (errors appear at runtime), breaking encapsulation via setAccessible, verbose checked exceptions, and restrictions under the module system. It's best kept to frameworks and infrastructure code.

Q7. How does Spring use annotations and reflection to perform dependency injection?

At startup, Spring scans the configured packages for classes annotated with stereotypes like @Component (or registered via @Bean), creates bean definitions, instantiates beans via reflection (constructors), resolves dependencies by type (and qualifiers), and injects them through constructors, setters or fields (using reflection). It stores beans in the ApplicationContext and may wrap them in proxies for features like transactions.

Q8. What is a meta-annotation? Give an example from Spring.

An annotation applied to another annotation. Java's @Retention and @Target are meta-annotations. Spring uses meta-annotations to compose annotations: @Service is meta-annotated with @Component; @RestController combines @Controller and @ResponseBody.

Q9. What types can annotation elements have?

Primitives, String, Class, enums, other annotations, and one-dimensional arrays of those. Values must be compile-time constants and can't be null.
