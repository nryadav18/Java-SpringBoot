1. Why this matters

Until now, all our code lived inside main. That's fine for 30 lines, but real applications have hundreds of thousands of lines. Imagine calculating GST in 50 different places by copy-pasting the formula — and then the tax rate changes. You'd have to find and fix all 50. Miss one, and customers are charged wrongly.

Methods solve this: write the logic once, give it a name (calculateGst), and call it from anywhere. In Spring Boot, almost everything you write is a method: a controller method handles a web request, a service method contains business logic (placeOrder, transferMoney), a repository method fetches data (findById).

Arrays solve a second problem: storing many values. You can't create mark1, mark2, … mark500 variables for 500 students. An array holds them all under one name. Arrays are also the foundation of the collections (ArrayList, Topic 11) that you'll use every day in Spring apps — ArrayList literally uses an array inside.

2. Real-life analogy

☕ A coffee machine and an egg tray

A method is like a coffee machine. You don't need to know how it works inside. You give it inputs (coffee beans, milk, the button "cappuccino") and it gives you an output (a cup of cappuccino). You can use it again and again. In Java terms:

  • The button name = the method name (makeCoffee).
  • The slots for beans and milk = the parameters (String type, int sugar).
  • The actual beans and milk you put in today = the arguments ("Cappuccino", 2).
  • The cup that comes out = the return value. A machine that only cleans itself and gives you nothing back is a void method.
  • Two buttons with the same label "Coffee" — one for a small cup, one where you also choose the size — is overloading.

An array is like an egg tray. It has a fixed number of slots, all for the same type of thing (eggs only, no apples), and every slot has a number. Java starts numbering at 0: the first egg is in slot 0. A 12-egg tray has slots 0 to 11 — asking for slot 12 is an error. A 2D array is a stack of trays, or a cinema seating chart with rows and seats.

3. Concepts step by step

3.1 What is a method and why use one?

A method is a named block of code that performs one task. You define it once and call (run) it whenever you need it. Benefits:

BenefitMeaning
Reuse (DRY — Don't Repeat Yourself)Write the GST formula once, use it 50 times.
Readabilityif (isEligibleForFreeDelivery(total)) reads like English.
Easy changesFix a bug or change a rule in one place.
TestingSmall methods can be tested one by one (Topic 21).
Divide and conquerA big problem becomes several small, named steps.

You've already used methods: main is one, System.out.println(...) calls one, Math.max(a, b) calls one. Now you'll write your own.

3.2 Method syntax

static double calculateGst(double amount) {
//│     │      │            │
//│     │      │            └─ parameter list: (type name, type name, ...)
//│     │      └─ method name: camelCase verb ("calculate", "print", "is...")
//│     └─ return type: what kind of value comes back (or void = nothing)
//└─ modifier: static = can be called directly from main (Topic 6 & 9 explain more)
    double gst = amount * 0.18;     // body
    return gst;                     // send the value back
}

The method signature is the name + the parameter types: calculateGst(double). Java uses the signature to tell methods apart.

ℹ️ Why static for now?main is static, so it can directly call only other static methods of the same class (without creating an object). In Topic 6 you'll learn to create objects and write normal (instance) methods — that's what Spring uses everywhere. For this topic, every method is static.

3.3 Calling a method — and what happens

public static void main(String[] args) {
    double gst = calculateGst(1000);   // 1. jump into calculateGst with amount = 1000
                                       // 2. run its body
                                       // 3. return 180.0 and come back here
    System.out.println(gst);           // 180.0
}
main: calculateGst(1000)→ amount = 1000 → calculateGst body runs→ return 180.0 → main continues with gst = 180.0

Arguments must match parameters in number, order and type. lineTotal(double unitPrice, int quantity) must be called as lineTotal(12.5, 4), not lineTotal(4, 12.5) (that won't even compile: 12.5 is not an int).

3.5 Return types and void

  • void: the method does something (prints, changes data) but gives nothing back. You call it as a statement: printWelcomeBanner();
  • Any type (int, double, boolean, String, int[]…): the method calculates something and must return a value of that type on every path.
static boolean isEligibleForFreeDelivery(double cartTotal) {
    return cartTotal >= 500;          // return the result of the comparison directly
}

static String withdraw(double balance, double amount) {
    if (amount <= 0) {
        return "Rejected: amount must be positive";   // return ends the method immediately
    }
    if (amount > balance) {
        return "Rejected: insufficient balance";
    }
    return "Approved: new balance " + (balance - amount);
}

That second method uses guard clauses (early returns): handle bad cases first and leave, so the "happy path" is at the end, not buried in nested if/else. You'll see this style in professional Spring code all the time. A void method can also use a bare return; to leave early.

⚠️ Every path must return 
static String grade(int marks) {
    if (marks >= 40) {
        return "Pass";
    }
}   // ❌ error: missing return statement (what if marks < 40?)

3.6 Method overloading

Overloading = several methods with the same name but different parameter lists (number of parameters, their types, or their order). Java picks the right one by looking at your arguments.

static double area(double side)                 { return side * side; }          // square
static double area(double length, double width) { return length * width; }       // rectangle
static double area(int radius)                  { return Math.PI * radius * radius; } // circle

area(4.0);       // → area(double)          = 16.0
area(4.0, 5.0);  // → area(double, double)  = 20.0
area(2);         // → area(int)             = 12.57  (exact type match wins)

Changing only the return type is NOT overloading — it's a compile error, because the call area(4.0) would be ambiguous. You use overloading all the time: System.out.println has overloads for int, double, String, char, boolean…, and Math.max has overloads for int, long, double.

💡 Compile-time polymorphismOverloading is also called compile-time (static) polymorphism — "one name, many forms", decided by the compiler. You'll meet runtime polymorphism in Topic 8.

3.7 Varargs — any number of arguments

Sometimes you don't know how many values will be passed. Write type... name and Java collects all arguments into an array:

static int sum(int... numbers) {      // numbers is an int[] inside the method
    int total = 0;
    for (int n : numbers) total += n;
    return total;
}

sum();               // 0       (empty array)
sum(5);              // 5
sum(1, 2, 3, 4);     // 10
sum(new int[]{10, 20, 30});  // 60 – an existing array works too

Rules: only one varargs parameter per method, and it must be the last one: printTags(String productName, String... tags). You already used one: printf(String format, Object... args).

3.8 Pass-by-value — Java's most misunderstood rule

Java is always pass-by-value: a method receives a copy of what you pass. But what is copied depends on the type:

  • Primitive (int, double…) — the value is copied. The method changes its own copy; the caller's variable is untouched.
  • Reference type (arrays, objects) — the reference (the address of the object) is copied. Both copies point to the same object, so changes to the object's contents are visible to the caller. But pointing the parameter to a new object does not affect the caller.
static void addBonus(int salary)        { salary = salary + 5000; }    // changes the copy only
static void applyDiscount(double[] p)   { p[0] = p[0] * 0.9; }         // changes the SHARED array
static void replaceArray(double[] p)    { p = new double[]{1, 1, 1}; } // re-points the copy only

int salary = 30000;           addBonus(salary);          // salary still 30000
double[] cart = {100, 250};   applyDiscount(cart);       // cart is now [90.0, 250.0]
                              replaceArray(cart);        // cart is still [90.0, 250.0]

To "change" a primitive through a method, return the new value: salary = withBonus(salary);

3.9 Recursion — a method that calls itself

Recursion solves a problem by solving a smaller version of the same problem. Every recursive method has two parts:

  1. Base case — the simplest situation, answered directly, where the recursion stops.
  2. Recursive case — call the same method with a smaller input, and use its answer.

Factorial: 5! = 5 × 4!, and 4! = 4 × 3! … down to 1! = 1.

static long factorial(int n) {
    if (n <= 1) {                  // base case
        return 1;
    }
    return n * factorial(n - 1);   // recursive case – smaller problem
}

Each call waits for the one below it. The JVM keeps track of the waiting calls on the call stack — like a stack of plates: each new call is a plate on top; when a call returns, its plate is removed.

factorial(4)
waits: 4 × ?→ factorial(3)
waits: 3 × ?→ factorial(2)
waits: 2 × ?→ factorial(1)
base case = 1
returns 1→ 2 × 1 = 2→ 3 × 2 = 6→ 4 × 6 = 24 ✔

Fibonacci: fib(n) = fib(n-1) + fib(n-2), with fib(0) = 0 and fib(1) = 1:

static long fibonacci(int n) {
    if (n <= 1) return n;                          // two base cases
    return fibonacci(n - 1) + fibonacci(n - 2);    // TWO recursive calls
}

Beautiful, but slow: fib(5) calls fib(3) twice, fib(2) three times… the work doubles at every level. fibonacci(30) makes 2.7 million calls! A simple loop does it in 29 steps. (Storing already-computed answers — called memoization — fixes recursion's speed, but that's for later.)

🚫 No base case = StackOverflowErrorIf the base case is missing or never reached (e.g. factorial(n + 1) by mistake), the method calls itself forever, the call stack fills up, and the program crashes with java.lang.StackOverflowError.
RecursionLoop (iteration)
StyleElegant for problems that are naturally "self-similar" (trees, folders inside folders, divide-and-conquer)Straightforward for counting and repeating
MemoryOne stack frame per call; very deep recursion can overflowConstant memory
SpeedMethod calls have overhead; naive versions may repeat workUsually faster
Use forTree traversal, file system walk, quicksort/merge sortMost everyday tasks

3.10 Scope — where a variable lives

The scope of a variable is the part of the code where you can use it. Rule of thumb: a variable lives from where it's declared to the closing } of the block that contains it.

KindDeclaredVisibleDefault value?
Class-level field (static int totalVisitors)Inside the class, outside methodsAll methods of the classYes (0, false, null)
ParameterIn the method's bracketsThe whole methodGets the argument's value
Local variableInside a methodFrom declaration to end of the methodNo — must initialise
Block variableInside { } of if/loopOnly inside that blockNo
Loop variablefor (int i = ...)Only inside the loop—
int discount = 10;
if (discount > 5) {
    int bonusPoints = 50;          // born here
    System.out.println(bonusPoints);
}                                  // bonusPoints dies here
// System.out.println(bonusPoints);  ❌ cannot find symbol

Shadowing: a local variable with the same name as a field "hides" the field inside that method. It compiles, but it's confusing — avoid it (except in constructors with this, Topic 6).

3.11 Arrays — many values under one name

An array is a fixed-size, ordered container of elements that all have the same type. Each element has an index starting at 0.

3.12 Declaring, creating and initialising

// A) Size first, fill later – elements start with default values
int[] marks = new int[5];        // [0, 0, 0, 0, 0]
marks[0] = 78;
marks[1] = 91;

// B) Initializer list – size comes from the values
String[] cities = {"Delhi", "Mumbai", "Chennai", "Kolkata"};

// C) new + values – needed when not in a declaration (e.g. reassigning, or as an argument)
double[] prices;
prices = new double[] {99.5, 250.0, 15.75};
printAll(new String[] {"a", "b"});
  • int[] marks is the preferred style. int marks[] also works (C style) but avoid it.
  • Size is fixed once created. To "grow", you create a bigger array and copy (Arrays.copyOf). This limitation is why we'll prefer ArrayList in Topic 11.
  • The size can be a variable: new int[studentCount].

3.13 Accessing elements, length and looping

cities[0]                     // "Delhi"   – first
cities[cities.length - 1]     // "Kolkata" – last
cities.length                 // 4  – a FIELD, no brackets (unlike String's length())

for (int i = 0; i < prices.length; i++) {     // classic for: you have the index
    System.out.println("Item " + (i + 1) + " costs " + prices[i]);
}
for (double price : prices) {                    // for-each: just the values
    total += price;
}

Use the classic for when you need the index (to print positions, compare neighbours, or change elements). Use for-each when you just read each value.

🚫 ArrayIndexOutOfBoundsExceptioncities[4] on a 4-element array crashes: Index 4 out of bounds for length 4. Valid indexes are 0 to length - 1. Negative indexes are invalid too. The classic cause: i <= arr.length instead of i < arr.length.

3.15 Arrays are reference types

An array variable holds a reference to the array, not the elements themselves. So:

int[] original = {1, 2, 3};
int[] alias = original;          // copies the reference – ONE array, two names
alias[0] = 100;                  // original is now [100, 2, 3] too!

int[] copy = Arrays.copyOf(original, original.length);   // a real, independent copy
System.out.println(original);                   // [I@1b6d3586  (type code + hash – not useful)
System.out.println(Arrays.toString(original));  // [100, 2, 3]
original == copy                                // false – different arrays
Arrays.equals(original, copy)                   // true  – same contents

3.16 Two-dimensional arrays

A 2D array is an array of arrays — a table of rows and columns. Use grid[row][column].

int[][] marks = {
    {78, 85, 62, 90},   // row 0 = student 0
    {92, 88, 79, 84},   // row 1
    {55, 67, 71, 60}    // row 2
};
marks.length       // 3  – number of rows
marks[0].length    // 4  – columns in row 0
marks[1][2]        // 79 – row 1, column 2

int[][] grid = new int[3][4];   // 3 rows × 4 columns, all 0

for (int row = 0; row < marks.length; row++) {           // walk rows
    for (int col = 0; col < marks[row].length; col++) {  // walk columns of THIS row
        System.out.print(marks[row][col] + " ");
    }
    System.out.println();
}

Jagged arrays: because each row is its own array, rows can have different lengths:

int[][] ordersPerAgent = new int[3][];       // rows decided later
ordersPerAgent[0] = new int[] {5, 7};
ordersPerAgent[1] = new int[] {3, 4, 6, 2};
ordersPerAgent[2] = new int[] {8};

That's why we always loop with marks[row].length, not a fixed number. To print a 2D array, use Arrays.deepToString(grid).

3.18 Classic array algorithms

Find the maximum — start with the first element as "best so far":

int best = numbers[0];                 // NOT 0: what if all numbers are negative?
for (int i = 1; i < numbers.length; i++) {
    if (numbers[i] > best) best = numbers[i];
}

Reverse in place — two pointers moving towards each other, swapping:

int left = 0, right = numbers.length - 1;
while (left < right) {
    int temp = numbers[left];          // the classic 3-step swap
    numbers[left] = numbers[right];
    numbers[right] = temp;
    left++;
    right--;
}

Linear search — check one by one. Works on any array. Up to n checks.

Binary search — only on a sorted array. Look at the middle element; if the target is bigger, throw away the left half, otherwise the right half. Repeat. Like finding a word in a dictionary. For 1,000,000 elements: at most ~20 checks instead of 1,000,000!

[11 12 22 25 64]
mid = 22 ✔ found | search 25: mid 22 < 25
→ go right→ [25 64], mid 25
✔ found at index 3

Bubble sort — walk through the array swapping neighbours that are in the wrong order; after each pass the largest remaining value "bubbles" to the end. Simple to understand, but slow for big arrays (about n² comparisons). In real code, always use Arrays.sort; learn bubble sort for interviews and understanding.

4.1 Example01 — methods that call methods

Example01_MethodBasics.java (part)static double lineTotal(double unitPrice, int quantity) {
    return unitPrice * quantity;
}

static double finalAmount(double unitPrice, int quantity) {
    double subtotal = lineTotal(unitPrice, quantity);
    return subtotal + calculateGst(subtotal);
}
// finalAmount(250, 2) → subtotal 500.0 → GST 90.0 → 590.0

Notice how finalAmount reads like a recipe: get the subtotal, add GST. Each small method does one thing and is named after it. This is how big programs stay understandable. Also note finalAmount(250, 2): the int 250 is automatically widened to the double parameter (Topic 2).

4.2 Example03 — seeing pass-by-value

Example03_PassByValue.java (part)int salary = 30000;
addBonus(salary);              // inside: 35000
// salary is still 30000 here

double[] cartPrices = {100.0, 250.0, 40.0};
applyDiscount(cartPrices);     // writes prices[i] = prices[i] * 0.9
// cartPrices is now [90.0, 225.0, 36.0]

replaceArray(cartPrices);      // inside: prices = new double[]{1, 1, 1}
// cartPrices is STILL [90.0, 225.0, 36.0]

The last case is the one that proves Java is pass-by-value even for arrays: if Java passed the variable itself (pass-by-reference), replaceArray would have changed cartPrices. It didn't — it only changed its own copy of the address.

4.3 Example04 — watching recursion

Example04_Recursion.java (part)static long factorialTraced(int n, String indent) {
    System.out.println(indent + "factorial(" + n + ") called");
    if (n <= 1) {
        System.out.println(indent + "factorial(" + n + ") returns 1   <- base case");
        return 1;
    }
    long result = n * factorialTraced(n - 1, indent + "   ");
    System.out.println(indent + "factorial(" + n + ") returns " + result);
    return result;
}

Each deeper call gets 3 more spaces of indentation, so the output literally draws the call stack: calls go down and to the right, returns come back up and to the left. Also look at callCount: fibonacci(30) needs 2,692,537 calls, which is why we compare it with the loop version.

4.4 Example09 — bubble sort with early exit

Example09_ArrayAlgorithms.java (part)for (int pass = 0; pass < n - 1; pass++) {
    boolean swapped = false;
    for (int i = 0; i < n - 1 - pass; i++) {
        if (numbers[i] > numbers[i + 1]) {
            int temp = numbers[i];
            numbers[i] = numbers[i + 1];
            numbers[i + 1] = temp;
            swapped = true;
        }
    }
    if (!swapped) break;    // already sorted → stop
}
  • i < n - 1 - pass: we compare numbers[i] with numbers[i + 1], so i must stop one before the end (otherwise i + 1 is out of bounds). And after each pass the last pass elements are already in their final place — no need to check them again.
  • The swapped flag makes an already-sorted array finish after one pass.

Also in this file: int mid = low + (high - low) / 2; in binary search. It equals (low + high) / 2, but can't overflow when low + high is bigger than Integer.MAX_VALUE (a real bug that existed in the JDK for years!).

6. Common mistakes

❌ Mistake: off-by-one with arrays for (int i = 0; i <= arr.length; i++) → ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 5.
Fix: use i < arr.length. The last index is length - 1.
⚠️ Mistake: length vs length() Arrays: arr.length (a field). Strings: name.length() (a method). Mixing them up → cannot find symbol.
⚠️ Mistake: printing an array directly System.out.println(marks) prints something like [I@1b6d3586.
Fix: Arrays.toString(marks) (or Arrays.deepToString for 2D).
⚠️ Mistake: comparing arrays with == a == b checks "same array object?", not "same contents?".
Fix: Arrays.equals(a, b).
⚠️ Mistake: thinking b = a copies an array It copies the reference; changing b changes a.
Fix: int[] b = Arrays.copyOf(a, a.length); or a.clone().
⚠️ Mistake: expecting a method to change a primitive argument addBonus(salary); does nothing to salary in the caller.
Fix: return the new value: salary = withBonus(salary);
⚠️ Mistake: ignoring a return value calculateGst(1000); compiles, but the result is thrown away.
Fix: store or use it: double gst = calculateGst(1000);
⚠️ Mistake: missing return / unreachable code "missing return statement" — some path doesn't return. "unreachable statement" — code written after a return.
Fix: make sure every path returns; don't put code after return in the same block.
❌ Mistake: recursion without a (reachable) base case → java.lang.StackOverflowError.
Fix: write the base case first, and make sure each call moves towards it (n - 1, not n + 1).
⚠️ Mistake: binarySearch on an unsorted array The result is undefined (often wrong, no error!).
Fix: Arrays.sort(arr) first, or use linear search.
⚠️ Mistake: starting max at 0 For {-5, -2, -9} you'd get 0, which isn't even in the array.
Fix: start with numbers[0] (or Integer.MIN_VALUE).

7. Best practices

  • One method = one job. If you need "and" to describe it ("calculates the total and prints the bill"), split it.
  • Keep methods short — ideally they fit on one screen (~20–30 lines).
  • Name methods with verbs (calculateTotal, printReport, findMax); boolean methods as questions (isValid, hasPassed).
  • Few parameters — more than 3–4 is a sign you need an object to group them (Topic 6).
  • Prefer returning values over printing inside calculation methods. Calculate in one place, display in another.
  • Use guard clauses (early return) instead of deep nesting.
  • Don't reassign parameters; create a new local variable instead — it avoids confusion.
  • Use the JDK: Arrays.sort, Arrays.toString, Arrays.copyOf are tested and fast. Write algorithms by hand only to learn.
  • Prefer loops over recursion for simple repetition; use recursion when the problem is naturally recursive (trees, nested folders).
  • Prefer collections (List) over arrays in application code when the size can change (Topic 11). Arrays shine for fixed-size data and performance-critical code.
  • Avoid parallel arrays — group related data into a class (Topic 6).

8. Key takeaways

  • A method = modifiers + return type + name + parameters + body. void returns nothing; other types must return a value on every path.
  • Parameters are the placeholders in the definition; arguments are the actual values in the call.
  • Overloading = same name, different parameter lists (not just a different return type). Varargs type... = any number of arguments, received as an array, must be last.
  • Java is always pass-by-value: primitives are copied; for arrays/objects the reference is copied, so the contents can change but the caller's variable can't be re-pointed.
  • Recursion needs a base case and a smaller recursive step; missing base case → StackOverflowError.
  • A variable lives from its declaration to the end of its enclosing block.
  • Arrays: fixed size, same type, index 0 to length - 1, default values 0/false/null, reference type.
  • 2D arrays are arrays of arrays: grid[row][col], rows can differ in length (jagged).
  • Arrays: toString, sort, fill, copyOf, copyOfRange, binarySearch (sorted only), equals, deepToString.

Easy

2. Overload max. Write three overloads: max(int a, int b), max(int a, int b, int c) (reuse the first one!) and max(double a, double b). Then write max(int... numbers) — what happens to a call like max(1, 2) now?

Hint / solution
static int max(int a, int b) { return a > b ? a : b; }
static int max(int a, int b, int c) { return max(max(a, b), c); }
static double max(double a, double b) { return a > b ? a : b; }
static int max(int... numbers) {
    int best = numbers[0];
    for (int n : numbers) if (n > best) best = n;
    return best;
}
// max(1, 2)       → max(int, int)        – fixed-arity overloads are preferred over varargs
// max(1, 2, 3, 4) → max(int...)          – only the varargs version fits

Java prefers exact matches, then widening, then boxing, and varargs last.

Medium

3. Array statistics. Write static int[] minMax(int[] values) that returns a 2-element array {min, max}, and static int countOccurrences(int[] values, int target). Test with {4, 9, 2, 9, 7, 9} → [2, 9] and 9 occurs 3 times.

Hint / solution
import java.util.Arrays;

public class ArrayStats {
    static int[] minMax(int[] values) {
        int min = values[0], max = values[0];
        for (int v : values) {
            if (v < min) min = v;
            if (v > max) max = v;
        }
        return new int[] {min, max};     // a method can return an array
    }

    static int countOccurrences(int[] values, int target) {
        int count = 0;
        for (int v : values) if (v == target) count++;
        return count;
    }

    public static void main(String[] args) {
        int[] data = {4, 9, 2, 9, 7, 9};
        System.out.println(Arrays.toString(minMax(data)));   // [2, 9]
        System.out.println(countOccurrences(data, 9));      // 3
    }
}
Medium

4. Recursive power and palindrome. Write static long power(int base, int exp) recursively (base case: exp == 0 → 1). Then write static boolean isPalindrome(int[] a, int left, int right) recursively: an array is a palindrome if the outer elements are equal and the inside is a palindrome. Test power(2, 10) → 1024 and {1, 2, 3, 2, 1} → true.

Hint / solution
static long power(int base, int exp) {
    if (exp == 0) return 1;
    return base * power(base, exp - 1);
}

static boolean isPalindrome(int[] a, int left, int right) {
    if (left >= right) return true;            // 0 or 1 element left: palindrome
    if (a[left] != a[right]) return false;
    return isPalindrome(a, left + 1, right - 1);
}

// power(2, 10)                                → 1024
// isPalindrome(new int[]{1,2,3,2,1}, 0, 4)    → true
Challenge

5. Selection sort + remove duplicates. (a) Implement selection sort: for each position i, find the smallest element in i..end and swap it into position i. (b) Write static int[] removeDuplicates(int[] sorted) that returns a new array without duplicates from a sorted array: {1,1,2,3,3,3,4} → [1, 2, 3, 4].

Hint / solution
static void selectionSort(int[] a) {
    for (int i = 0; i < a.length - 1; i++) {
        int minIndex = i;
        for (int j = i + 1; j < a.length; j++) {
            if (a[j] < a[minIndex]) minIndex = j;
        }
        int temp = a[i];
        a[i] = a[minIndex];
        a[minIndex] = temp;
    }
}

static int[] removeDuplicates(int[] sorted) {
    if (sorted.length == 0) return sorted;
    int[] result = new int[sorted.length];   // big enough for the worst case
    int count = 0;
    result[count++] = sorted[0];
    for (int i = 1; i < sorted.length; i++) {
        if (sorted[i] != sorted[i - 1]) {    // new value (duplicates are neighbours)
            result[count++] = sorted[i];
        }
    }
    return Arrays.copyOf(result, count);     // trim to the real size
}

result[count++] = x stores at count, then increments it (postfix, Topic 2).

Challenge

6. Tic-tac-toe winner. Given a char[][] board (3×3 with 'X', 'O' or '.'), write static char winner(char[][] board) returning 'X', 'O' or '-' for no winner. Check all rows, columns and both diagonals.

Hint / solution
static boolean same(char a, char b, char c) {
    return a != '.' && a == b && b == c;
}

static char winner(char[][] b) {
    for (int i = 0; i < 3; i++) {
        if (same(b[i][0], b[i][1], b[i][2])) return b[i][0];   // row i
        if (same(b[0][i], b[1][i], b[2][i])) return b[0][i];   // column i
    }
    if (same(b[0][0], b[1][1], b[2][2])) return b[0][0];       // main diagonal
    if (same(b[0][2], b[1][1], b[2][0])) return b[0][2];       // other diagonal
    return '-';
}

// char[][] board = { {'X','O','X'}, {'O','X','O'}, {'.','.','X'} };
// winner(board) → 'X' (main diagonal)

10. Interview questions

Q1. Is Java pass-by-value or pass-by-reference?

Always pass-by-value. For primitives the value is copied. For objects and arrays, the reference is copied — so the method can modify the object's state through it, but reassigning the parameter to a new object does not affect the caller's variable. That last point is what proves it isn't pass-by-reference.

Q2. What is method overloading? Can we overload by return type only?

Overloading means multiple methods in the same class with the same name but different parameter lists (number, type or order). It's resolved at compile time. You cannot overload by return type alone — the compiler couldn't tell which method a call refers to.

Q3. Can we overload the main method?

Yes, you can write other methods named main with different parameters, but the JVM only uses public static void main(String[] args) as the entry point. The other overloads are ordinary methods.

Q4. What are varargs and what are their rules?

Varargs (type... name) let a method accept zero or more arguments of a type; inside the method they're an array. Only one varargs parameter is allowed and it must be the last parameter. Overload resolution considers varargs methods last.

Q5. What is recursion? What are its risks?

A method calling itself on a smaller sub-problem, with a base case to stop. Risks: missing/unreachable base case → StackOverflowError; very deep recursion can overflow the stack even when correct; naive recursion can repeat work exponentially (e.g. Fibonacci) — fix with memoization or iteration.

Q6. What is the default value of array elements?

0 for numeric types, '\u0000' (code 0) for char, false for boolean, and null for object references. Local variables, in contrast, have no default.

Q7. What is the difference between length, length() and size()?

length is a final field of arrays; length() is a method of String; size() is a method of collections like ArrayList (Topic 11).

Q8. How do you copy an array? Is b = a a copy?

b = a only copies the reference — both names point to the same array. Real copies: Arrays.copyOf(a, a.length), a.clone(), System.arraycopy(src, srcPos, dest, destPos, length), or a manual loop. For 2D arrays these are shallow copies (rows are shared) — copy each row for a deep copy.

Q9. Linear search vs binary search?

Linear search checks each element: O(n), works on unsorted data. Binary search halves the search range each step: O(log n), but requires sorted data. Arrays.binarySearch returns a negative value (-(insertionPoint) - 1) if the key isn't found.

Q10. Explain bubble sort and its time complexity.

Repeatedly compare adjacent elements and swap if out of order; after each pass the largest unsorted element reaches its final position. Worst/average O(n²), best O(n) with the "no swaps → stop" optimisation, O(1) extra memory, stable. In practice use Arrays.sort (O(n log n)).
