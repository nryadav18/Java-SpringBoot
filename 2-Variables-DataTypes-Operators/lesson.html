1. Why this matters

Every application is about data. A shopping app stores prices and quantities. A bank stores balances. A college system stores marks and names. Before you can do anything clever, you must be able to store data and calculate with it.

Later in this course, when you write a Spring Boot Product entity, it will have fields like Long id, String name, double price, int stock. When you calculate an order total, you will use operators. When a bug says "the total is 0", it will often be integer division — which you will understand after today. This topic is small in ideas but used on every single line of code you will ever write.

2. Real-life analogy

📦 Labelled boxes in a kitchen

Imagine your kitchen shelf full of labelled containers: "Sugar", "Rice", "Salt". Each container:

  • has a label — that's the variable's name (sugar),
  • is made for one kind of thing and has a fixed size — that's the data type (a tiny spice jar vs a big rice drum = byte vs long),
  • holds contents that can change — that's the value (you use some sugar, you refill it).

You can't pour a 10 kg rice bag into a spice jar — it overflows. That's narrowing. Pouring the spice jar into the rice drum is always fine — that's widening. And a container marked "DO NOT REFILL" is a constant (final).

Operators are your kitchen tools: the measuring cup (+, -), the scale that compares two things (>, ==), and the recipe rule "only bake if you have flour and eggs" (&&).

3. Concepts step by step

3.1 What is a variable?

A variable is a named place in memory that holds a value. In Java, every variable has a type that decides what kind of value it can hold.

int age = 25;
// │    │    │
// │    │    └── value       (what's inside the box)
// │    └─────── name        (the label)
// └──────────── type        (what kind of box)

Three things you can do with a variable:

int studentCount;          // 1. DECLARE  – create the box (type + name)
studentCount = 30;         // 2. ASSIGN   – put a value in (= means "store", not "equals")
int books = 1200;          //    declare + assign in one go (called INITIALISING)
books = books + 50;        // 3. CHANGE   – read the old value, add 50, store it back → 1250
ℹ️ = is not "equals"In maths, x = x + 1 is impossible. In Java, = means "take the value on the right and store it in the variable on the left". So x = x + 1 means "add one to x". To compare, Java uses == (two equals signs).

A local variable (declared inside a method like main) must be given a value before you read it — Java will not guess:

int total;
System.out.println(total);   // ❌ error: variable total might not have been initialized

Literals are values written directly in code. A few rules:

  • A whole number like 500 is an int by default. For a long bigger than int's range add L: 8_000_000_000L.
  • A decimal like 4.5 is a double by default. For float add f: 4.5f.
  • Underscores make big numbers readable: 1_000_000 is the same as 1000000.
  • char uses single quotes 'A'; String uses double quotes "A".
  • You can also write numbers in hex (0xFF = 255) or binary (0b1010 = 10).
⚠️ Decimals are not exactdouble stores numbers in binary, and 0.1 cannot be written exactly in binary (just like 1/3 = 0.3333… in decimal). So 0.1 + 0.2 prints 0.30000000000000004. For money in real banking/e-commerce code, professionals use java.math.BigDecimal (you'll meet it later in the course). For learning, double is fine.

3.4 Meet String (a first look)

String holds text. It is not a primitive — it's a class (notice the capital S). But Java gives it special treatment so you can create it with just quotes:

String customerName = "Meera";
System.out.println(customerName.length());       // 5
System.out.println(customerName.toUpperCase());  // MEERA
System.out.println("Hi " + customerName);        // Hi Meera  (+ joins text)

The .length() part calls a method (an ability) of the String. Primitives don't have methods; objects do. Topic 5 is entirely about Strings.

3.6 Type casting — converting between types

Widening (implicit / automatic): from a smaller type to a bigger one. Always safe, so Java does it for you.

int itemsSold = 150;
long bigTotal = itemsSold;     // 150      (int → long)
double asDecimal = itemsSold;  // 150.0    (int → double)
byte→short→int→long→float→double   and  char→int

Narrowing (explicit / manual cast): from a bigger type to a smaller one. Data may be lost, so Java insists you write the target type in brackets — the cast operator (type):

double price = 99.99;
int whole = (int) price;            // 99   – decimal part is CUT OFF, not rounded!
long huge = 3_000_000_000L;
int squeezed = (int) huge;          // -1294967296 – doesn't fit, wraps around (garbage!)
long rounded = Math.round(price);   // 100  – use Math.round for real rounding

Overflow: if a calculation goes past the maximum, it silently wraps around to the minimum — like a car's odometer going from 999999 back to 000000:

int max = Integer.MAX_VALUE;   //  2147483647
int oops = max + 1;            // -2147483648   (no error, just wrong!)

Automatic promotion in expressions: when you mix types in maths, Java converts the smaller one to the bigger one first. And byte, short, char are always promoted to at least int:

int qty = 3;
double price = 2.5;
double total = qty * price;   // qty is promoted to 3.0 → 7.5

byte a = 10, b = 20;
// byte c = a + b;            // ❌ error: a + b is an int!
byte c = (byte) (a + b);      // ✔ 30

char ↔ int: a char is stored as a number (its Unicode code):

char letter = 'A';
int code = letter;               // 65
char next = (char) (code + 1);   // 'B'

Text ↔ number is not casting — you use helper methods:

int qty = Integer.parseInt("42");          // "42" → 42
double amt = Double.parseDouble("19.5");   // "19.5" → 19.5
String text = String.valueOf(42);          // 42 → "42"
String text2 = "" + 42;                    // also works (quick trick)
// int bad = (int) "42";                   // ❌ error: you cannot cast a String to int

3.7 var — let the compiler figure out the type (Java 10+)

For local variables you can write var instead of the type, if you give a value immediately. The compiler looks at the value and decides the type.

var city = "Pune";      // String
var year = 2026;        // int
var temp = 31.5;        // double
// city = 10;           // ❌ error – city is a String forever. var is NOT "any type".
// var x;               // ❌ error – needs a value so the compiler can infer the type
// var y = null;        // ❌ error – null tells the compiler nothing
💡 When to use varUse it when the type is obvious from the right side (var list = new ArrayList<String>();). Avoid it when it hides the type (var result = calculate(); — what type is result?). var works only for local variables — not for fields, method parameters or return types.

3.8 Constants with final

A variable marked final can be assigned only once. After that, it can never change. Use it for values that shouldn't change, like tax rates or limits.

public class Billing {
    static final double GST_RATE = 0.18;     // class-level constant (UPPER_SNAKE_CASE)

    public static void main(String[] args) {
        final int daysInWeek = 7;            // local constant
        // daysInWeek = 8;                   // ❌ error: cannot assign a value to final variable
        System.out.println(1000 * GST_RATE); // 180.0
    }
}

static final together at class level is how Java defines "true" constants. (You'll understand static fully in Topic 9; for now: "one shared value for the whole class".) Why constants? No magic numbers: price * GST_RATE explains itself; price * 0.18 doesn't. And if the rate changes, you change one line.

3.10 Integer division and modulo — the two tricks

Integer division: when both sides of / are whole numbers, the result is a whole number. The decimal part is simply thrown away (not rounded).

17 / 5          // 3
7 / 2           // 3
1 / 2           // 0     ← a very common bug!
17 / 5.0        // 3.4   ← one side is decimal → decimal result
(double) 17 / 5 // 3.4   ← cast BEFORE dividing
(double) (17/5) // 3.0   ← too late: division already happened

Modulo % gives the remainder. Think of sharing 17 sweets among 5 kids: each gets 3 (17 / 5) and 2 are left over (17 % 5).

TaskCodeExample
Is a number even?n % 2 == 014 % 2 → 0 → even
Last digitn % 104728 % 10 → 8
Remove last digitn / 104728 / 10 → 472
Minutes → hours + minutesm / 60, m % 60135 → 2 h 15 min
Is n divisible by k?n % k == 021 % 7 → 0 → yes
Wrap around (clock)(hour + x) % 24(22 + 5) % 24 → 3
⚠️ Divide by zero10 / 0 with ints crashes the program with ArithmeticException: / by zero. But 10.0 / 0 with doubles gives Infinity (and 0.0 / 0 gives NaN = "Not a Number"). No crash, but a useless result.

3.12 Increment and decrement: ++ and --

count++ adds 1; count-- subtracts 1. Used everywhere in loops (Topic 3). The tricky part is prefix vs postfix when used inside a bigger expression:

int x = 10;
int y = x++;   // POSTFIX: y gets OLD value (10), then x becomes 11
int p = 10;
int q = ++p;   // PREFIX:  p becomes 11 first, then q gets 11
FormNameStep 1Step 2
x++post-incrementuse the valuethen add 1
++xpre-incrementadd 1then use the value
💡 Keep it simpleOn its own line (count++;) prefix and postfix are identical. Avoid using ++ inside bigger expressions in real code — it confuses readers. But know the difference: it's a favourite interview trick.

3.14 Logical operators

They combine booleans:

truetruetruetruefalse

falsetruefalsetruetrue

  • AND &&: "Can board the plane if they have a ticket and an ID" — both must be true.
  • OR ||: "Free delivery if you're a member or the order is over ₹500" — one is enough.
  • NOT !: flips the value. !isLoggedIn = "not logged in".

Short-circuit evaluation: && stops as soon as it finds a false (the answer can't become true anymore), and || stops at the first true. This is useful to guard dangerous checks:

int items = 0;
boolean ok = items > 0 && (500 / items) > 100;  // right side never runs → no divide-by-zero crash

(There are also single & and |, which always evaluate both sides, and ^ (XOR, "exactly one is true"). You'll rarely need them for booleans.)

3.17 Wrapper classes and autoboxing

Each primitive has a matching wrapper class — an object version of it:

Primitivebyteshortintlongfloatdoublecharboolean
WrapperByteShortIntegerLongFloatDoubleCharacterBoolean

Why do we need them?

  1. Collections like List (Topic 11) can only store objects: List<Integer> works, List<int> does not.
  2. null: a wrapper can be null, meaning "no value". In a database, a missing value is NULL — so in Spring entities you'll often see Long id (null until saved) instead of long id.
  3. Helper methods: Integer.parseInt("42"), Integer.MAX_VALUE, Character.isDigit('7').

Autoboxing = Java automatically wraps a primitive into its wrapper. Unboxing = automatically unwraps it back.

Integer boxed = 30;        // autoboxing:  int → Integer
int plain = boxed;         // unboxing:    Integer → int
Integer missing = null;
int crash = missing;       // 💥 NullPointerException – can't unbox nothing!
🚫 Comparing wrappers with == 
Integer a = 100, b = 100;
System.out.println(a == b);       // true  (Java caches small values -128..127)
Integer c = 1000, d = 1000;
System.out.println(c == d);       // false (!) – two different objects
System.out.println(c.equals(d));  // true  – compares the values
Always compare wrapper objects with .equals().

4.2 Example03 — narrowing loses data

Example03_TypeCastingVarAndConstants.java (part)double price = 99.99;
int roundedDown = (int) price;      // 99  (cut off)
long hugeNumber = 3_000_000_000L;
int squeezed = (int) hugeNumber;    // -1294967296  (wrapped around)
int overflowed = Integer.MAX_VALUE + 1;  // -2147483648

Why the strange negative numbers? An int has only 32 bits. When the value needs more, the extra bits are chopped off and what remains is read as a (negative) number. Java does not warn you at runtime — that's why choosing the right type matters. (If you ever need a guaranteed error instead of a silent overflow, Math.addExact(a, b) throws an exception.)

4.3 Example04 — the division traps

Example04_Operators.java (part)int a = 17, b = 5;
System.out.println("a / b = " + (a / b));                        // 3
System.out.println("(double) a / b = " + ((double) a / b));      // 3.4
System.out.println("(double) (a / b) = " + ((double) (a / b)));  // 3.0
int totalMinutes = 135;
System.out.println(totalMinutes + " minutes = " + (totalMinutes / 60) + " h "
        + (totalMinutes % 60) + " min");                          // 2 h 15 min

Look closely at the two casts: the cast operator has higher priority than /, so (double) a / b converts a first, then divides as decimals. In (double) (a / b) the brackets force the integer division first — the 0.4 is already lost.

4.4 Example05 — wrapper surprises

Example05_MathAndWrapperClasses.java (part)Integer big1 = 1000, big2 = 1000;
System.out.println(big1 == big2);        // false
System.out.println(big1.equals(big2));   // true

== on objects compares addresses ("same box?"), equals compares contents ("same value?"). For values -128 to 127, Java reuses cached Integer objects, so == accidentally works — which makes the bug sneaky.

6. Common mistakes

⚠️ Mistake: integer division double avg = total / count; where both are int → the decimals are lost before the value reaches avg.
Fix: double avg = (double) total / count; or use 5.0 instead of 5 in formulas.
⚠️ Mistake: forgetting L or f long big = 9000000000; → error: integer number too large. float r = 4.5; → error: incompatible types: possible lossy conversion from double to float.
Fix: 9000000000L and 4.5f.
⚠️ Mistake: "possible lossy conversion" int x = 9.99; → error: incompatible types: possible lossy conversion from double to int.
Fix: decide what you want: (int) 9.99 (cut off → 9) or (int) Math.round(9.99) (round → 10), or just keep it a double.
⚠️ Mistake: = instead of == Writing if (age = 18) → error: incompatible types: int cannot be converted to boolean. Java protects you here, but remember: = stores, == compares.
⚠️ Mistake: using an uninitialised local variable int total; total++; → error: variable total might not have been initialized.
Fix: give it a starting value: int total = 0;
⚠️ Mistake: silent overflow int millis = 30 * 24 * 60 * 60 * 1000; (30 days in ms) → -1702967296! The maths is done in int and overflows before it is stored.
Fix: make the first number a long: 30L * 24 * 60 * 60 * 1000.
🚫 Mistake: unboxing null Integer discount = null; int d = discount; → NullPointerException at runtime.
Fix: check for null first, or use a primitive if "no value" is not possible.
⚠️ Mistake: comparing wrappers or Strings with == Works for small numbers by luck, fails for larger ones.
Fix: a.equals(b).
⚠️ Mistake: special characters in source files On Windows with Java 17, javac may read files using the old Windows encoding, so characters like ₹ or é typed directly into a .java file can produce illegal character or garbled output.
Fix: use a Unicode escape (backslash + u20B9, as in Example02), or compile with javac -encoding UTF-8. (From Java 18 the default is UTF-8. Maven projects set the encoding in pom.xml — Topic 20.)

7. Best practices

  • Default to int and double. Use long for IDs, counts that may grow huge and timestamps. Rarely use byte, short, float.
  • Use BigDecimal for money in real applications (banking, payments). double rounding errors can cost real money.
  • Meaningful camelCase names: totalAmount, not ta or x1. Booleans read like questions: isActive, hasDiscount.
  • No magic numbers: put fixed values in static final constants with clear names.
  • Declare variables close to where they're used, and give them a value immediately.
  • Prefer final for local variables that shouldn't change — it prevents accidental changes and documents your intention.
  • Use brackets to make precedence obvious; don't make readers remember the table.
  • Use var only when the type is obvious from the right-hand side.
  • Avoid ++/-- inside bigger expressions — use them as standalone statements.
  • Primitives for calculations, wrappers when you need null or collections. In JPA entities (Topic 38), IDs are usually Long because a new, unsaved entity has no ID yet (null).

8. Key takeaways

  • A variable = type + name + value. = stores; == compares.
  • 8 primitives: byte, short, int, long, float, double, char, boolean. Defaults to use: int, double, boolean.
  • String is a class (reference type), not a primitive.
  • Widening is automatic and safe; narrowing needs a cast (int) and may lose data. Overflow wraps around silently.
  • int / int gives an int (decimals dropped). % gives the remainder — great for even/odd, digits and time.
  • x++ uses then increments; ++x increments then uses.
  • && and || short-circuit. Precedence: brackets → * / % → + - → comparisons → && → || → assignment.
  • var infers the type of local variables; final makes a value unchangeable.
  • Wrappers (Integer, Double…) allow null and collections; autoboxing converts automatically; compare them with equals.

10. Interview questions

Q1. What are the primitive data types in Java? Give their sizes.

Eight: byte (1 byte), short (2), int (4), long (8), float (4), double (8), char (2, unsigned Unicode), boolean (true/false; size is JVM-dependent). Everything else is a reference type.

Q2. What is the difference between widening and narrowing conversion?

Widening converts a smaller type to a larger one (e.g. int → long/double). It's automatic and safe. Narrowing converts larger to smaller (e.g. double → int); it requires an explicit cast and can lose data (decimal truncation, overflow).

Q3. What is the output of int x = 5; int y = x++ + ++x;?

y = 12, x = 7. x++ contributes 5 (then x becomes 6), ++x makes x 7 and contributes 7. 5 + 7 = 12.

Q4. What is autoboxing and unboxing?

Autoboxing is the automatic conversion of a primitive to its wrapper (int → Integer) by the compiler; unboxing is the reverse. It lets you put primitives in collections. Danger: unboxing a null wrapper throws NullPointerException.

Q5. Why does Integer a = 127, b = 127; a == b give true but with 128 gives false?

Integer.valueOf (used by autoboxing) caches Integer objects for -128 to 127. Within that range both variables point to the same cached object, so == (reference comparison) is true. Outside it, new objects are created, so == is false. Always use equals() for wrapper values.

Q6. What is the difference between && and &?

&& is the logical AND with short-circuiting: if the left side is false, the right side is not evaluated. & evaluates both sides always (and is also the bitwise AND for integers). Same idea for || vs |.

Q7. What does var do? Is Java dynamically typed now?

var (Java 10) is local variable type inference: the compiler infers the static type from the initializer. The type is fixed at compile time — Java remains statically typed. It works only for local variables with an initializer (not fields, parameters or return types).

Q8. Why shouldn't you use double for money?

Floating-point types use binary fractions and can't represent many decimal values exactly (0.1 + 0.2 = 0.30000000000000004). Rounding errors add up. Use BigDecimal (or store amounts in the smallest unit, like paise, as a long).

Q9. What is the result of Integer.MAX_VALUE + 1?

Integer.MIN_VALUE (-2147483648). Integer arithmetic overflows silently by wrapping around (two's complement). Use long, or Math.addExact to get an exception on overflow.

Q10. What is the difference between final and a constant?

final means a variable can be assigned only once. A "constant" in Java convention is a static final field with a fixed value, named in UPPER_SNAKE_CASE (e.g. static final double GST_RATE = 0.18;) — shared by the class and never changing.
