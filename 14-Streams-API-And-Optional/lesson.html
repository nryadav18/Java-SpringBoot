14. Streams API & Optional

Process lists of data like a pro — filter, transform, group and summarise in a few readable lines — and handle "maybe there is no value" safely with Optional.

🎯 What you will learn
  • What a stream is and the 3-part pipeline: source → intermediate operations → terminal operation.
  • Laziness, short-circuiting and the "use once" rule.
  • Intermediate operations: filter, map, flatMap, sorted, distinct, limit, skip, peek.
  • Terminal operations: forEach, collect, reduce, count, min/max, anyMatch/allMatch/noneMatch, findFirst/findAny.
  • Collectors: toList, toSet, toMap, groupingBy, partitioningBy, joining, counting, averagingDouble and friends.
  • Primitive streams (IntStream, range) and parallel streams (and why to be careful).
  • Optional: of, ofNullable, orElse, orElseThrow, map, ifPresent — and why Spring Data's findById returns it.
📋 Before you start — you should know: Topic 13 · Lambdas & Functional Interfaces (very important — every stream step takes a lambda) and Topic 11 · Collections.

1. Why this matters

Business software is mostly about lists of things: orders, employees, products, transactions. And most tasks are the same few patterns: keep some, change each one, sort, group, add up.

With plain loops you write the "how" every time: create an empty list, loop, check with if, add, keep a counter… With streams you write the "what":

// "Names of IT employees earning more than 75,000, sorted"
List<String> names = employees.stream()
        .filter(e -> e.getDepartment().equals("IT"))
        .filter(e -> e.getSalary() > 75000)
        .map(Employee::getName)
        .sorted()
        .toList();

It reads almost like the sentence in the comment. In real Spring Boot projects you will use streams every day:

  • Converting database entities to DTOs: products.stream().map(mapper::toDto).toList()
  • Building reports and dashboards (totals per category, top 5 customers).
  • Validating input (anyMatch, allMatch).
  • Handling "not found" with Optional: repository.findById(id).orElseThrow(...)

Streams are also a very common interview topic — "group employees by department and find the average salary" is a classic question.

2. Real-life analogy

🏭 A factory conveyor belt Picture a juice factory.
  • Source: a truck tips oranges onto a conveyor belt (your List).
  • Intermediate stations: one worker throws away bad oranges (filter), the next machine squeezes each orange into juice (map), another station puts bottles in order (sorted), another lets only the first 100 through (limit).
  • Terminal station: at the end, bottles are packed into a box (collect), or simply counted (count).
Two important facts about this belt:
  1. The belt doesn't move until someone is waiting at the end. Setting up stations does nothing by itself — that is laziness.
  2. The oranges in the truck are not changed. The belt produces new things (juice); the original list stays the same.
🎁 Optional = a gift box that may be empty You order something online. The courier hands you a box. Before you use the item, you check the box. If it's empty you call customer care (orElseThrow) or use something you already have (orElse). null is like the courier not even giving you a box — you reach for the item and grab air (NullPointerException!).

3. Concepts step by step

3.1 What is a stream?

A stream (java.util.stream.Stream<T>) is a sequence of elements that flows through a series of operations. It is not a collection:

Collection (List, Set…)Stream
Stores data in memoryDoes not store anything — data flows through it
You can loop over it many timesCan be used only once
You add/remove elementsNever changes the source; produces a new result
Eager: elements exist right nowLazy: work happens only when a result is asked for
You write the loop (external iteration)The stream loops for you (internal iteration)
⚠️ Not the same as "I/O streams" InputStream/OutputStream (topic 16) are about reading bytes from files. They are a totally different thing that happens to share the word "stream".

3.2 The pipeline: source → intermediate → terminal

PartWhat it isExamples
SourceWhere elements come fromlist.stream(), Stream.of(a, b, c), Arrays.stream(array), IntStream.range(1, 10), Files.lines(path)
IntermediateReturns a new Stream; lazy; can be chainedfilter, map, flatMap, sorted, distinct, limit, skip, peek
TerminalProduces a result or side effect; triggers the processing; ends the streamcollect, toList, forEach, count, reduce, min, max, anyMatch, findFirst

3.3 Laziness and short-circuiting

Intermediate operations only describe work. Nothing runs until the terminal operation is called. And elements travel one by one through the whole pipeline — not "filter everything, then map everything".

String firstLong = names.stream()                      // Ravi, Asha, John, Meena, Arjun, Bala
        .peek(n -> System.out.println("looking at " + n))
        .filter(n -> n.length() > 4)
        .findFirst()                                   // terminal: start!
        .orElse("none");
// looking at Ravi
// looking at Asha
// looking at John
// looking at Meena      <- found it, STOP. Arjun and Bala are never touched.

Operations that can stop early — findFirst, findAny, anyMatch, allMatch, noneMatch, limit — are called short-circuiting. This makes streams efficient: they do the minimum work needed.

3.4 Creating streams

List<String> list = List.of("a", "b");
Stream<String> s1 = list.stream();                 // from any Collection
Stream<String> s2 = Stream.of("Pen", "Book");      // from values
IntStream s3 = Arrays.stream(new int[]{1, 2, 3});  // from an array
IntStream s4 = IntStream.rangeClosed(1, 100);      // numbers 1..100
Stream<Integer> s5 = Stream.iterate(1, n -> n * 2).limit(10);  // 1,2,4,8...
Stream<String> s6 = Stream.generate(() -> "hi").limit(3);       // hi,hi,hi
Map<String, Integer> map = Map.of("x", 1);
Stream<Map.Entry<String, Integer>> s7 = map.entrySet().stream(); // maps: stream the entries

map vs flatMap — the most confusing pair, explained. Each employee has a list of skills.

employees.stream().map(Employee::getSkills)                  // Stream<List<String>>
// [[Java, Spring], [Excel], [Java, Docker, AWS], ...]   <- a stream of LISTS

employees.stream().flatMap(e -> e.getSkills().stream())      // Stream<String>
// [Java, Spring, Excel, Java, Docker, AWS, ...]         <- one flat stream of skills
[A, B][C][D, E] → flatMap → ABCDE

Rule: use flatMap whenever each element "contains many" things (order → items, department → employees, sentence → words) and you want to work with the inner things directly.

skip + limit = pagination. Page p with page size s is .skip((p - 1) * s).limit(s). Spring Data does pagination in the database (topic 41), but the idea is the same.

reduce — folding many values into one. Think of rolling a snowball: start with an identity (an empty snowball, e.g. 0 for sum, 1 for product, "" for text), then combine each element into it.

int total = Stream.of(10, 20, 30).reduce(0, (sum, x) -> sum + x);
// step 1: 0  + 10 = 10
// step 2: 10 + 20 = 30
// step 3: 30 + 30 = 60   -> total = 60
ℹ️ collect(Collectors.toList()) vs .toList() Both give you a List. .toList() (Java 16+) is shorter and returns an unmodifiable list — calling add on it throws UnsupportedOperationException. Collectors.toList() currently returns an ArrayList but does not promise it. If you need a list you will modify, use Collectors.toCollection(ArrayList::new).

3.7 Collectors — the "GROUP BY" of Java

collect(...) takes a Collector — a recipe for building the result. The class java.util.stream.Collectors has ready-made recipes. If you know SQL, groupingBy is GROUP BY, and counting/averagingDouble/summingDouble are COUNT/AVG/SUM.

CollectorResultExample result
toList(), toSet()List / Set[Asha, Ravi]
toCollection(TreeSet::new)any collection you choosesorted set
toMap(keyFn, valueFn)Map{101=1200.0, 102=450.0}
toMap(keyFn, valueFn, mergeFn)Map, duplicates mergeddept → max salary
groupingBy(classifier)Map<K, List<T>>{HR=[Ravi, Bala], IT=[Asha, John]}
groupingBy(classifier, downstream)Map<K, X>{HR=2, IT=3} with counting()

counting()Long6

summingDouble(fn) / summingIntDouble / Integer395000.0
summarizingDouble(fn)DoubleSummaryStatistics (count, sum, min, avg, max)all at once

The "downstream" collector is the second argument of groupingBy: it says what to do with each group's members (count them, average them, list just their names…).

// SQL:  SELECT department, AVG(salary) FROM employee GROUP BY department
Map<String, Double> avgByDept = employees.stream()
        .collect(Collectors.groupingBy(
                Employee::getDepartment,                        // GROUP BY department
                Collectors.averagingDouble(Employee::getSalary) // AVG(salary)
        ));
💡 Predictable order of map keys groupingBy returns a HashMap by default, whose order is not guaranteed. To get sorted keys, pass a map factory as the middle argument: groupingBy(Employee::getDepartment, TreeMap::new, Collectors.counting()). The examples in this folder do this so the output is always the same.
⚠️ toMap and duplicate keys Collectors.toMap(Employee::getDepartment, Employee::getSalary) throws IllegalStateException: Duplicate key IT because three employees are in IT. Give a merge function telling Java what to do with duplicates: toMap(..., ..., (a, b) -> Math.max(a, b)).

3.8 Primitive streams: IntStream, LongStream, DoubleStream

Stream<Integer> stores boxed Integer objects. For numbers, Java has special streams that work directly with int/long/double — faster, and they have handy maths methods: sum(), average(), max(), summaryStatistics().

IntStream.range(1, 5)          // 1, 2, 3, 4      (end EXCLUSIVE)
IntStream.rangeClosed(1, 5)    // 1, 2, 3, 4, 5   (end INCLUSIVE)
IntStream.rangeClosed(1, 100).sum()                 // 5050
IntStream.of(78, 92, 65).average().getAsDouble()     // OptionalDouble -> 78.33...
employees.stream().mapToDouble(Employee::getSalary).sum()   // object -> primitive stream
IntStream.range(0, 3).boxed().toList()               // primitive -> Stream<Integer> -> [0, 1, 2]
IntStream.rangeClosed(1, 5).mapToObj(i -> "Row " + i)   // primitive -> objects

IntStream.range is a neat replacement for the classic counting for loop when you want to produce or collect values.

3.9 Parallel streams — use with caution

Call .parallelStream() on a collection (or .parallel() on a stream) and Java splits the work across your CPU cores using a shared thread pool (the common ForkJoinPool).

long sum = LongStream.rangeClosed(1, 1_000_000).parallel().sum();   // same answer, maybe faster
🚫 Why "caution"?
  • Often slower for small lists — splitting and joining work has a cost. Use it only for large data with CPU-heavy work, and measure.
  • Order is lost with forEach (use forEachOrdered if order matters).
  • Race conditions if your lambdas change shared state, e.g. parallelStream().forEach(x -> sharedArrayList.add(x)) can lose elements or crash, because ArrayList is not thread-safe. Use collect(...) instead.
  • In a web server (Spring Boot), every request already runs on its own thread. Parallel streams all share one common pool, so a few heavy requests can slow down everyone. In Spring apps, normally don't use parallel streams.

3.10 Optional — no more surprise nulls

Look at this method: Product findById(long id). What does it return if the product doesn't exist? Probably null. Nothing in the method signature warns you, and when you call product.getName(), the program crashes with a NullPointerException — the most common bug in Java.

Optional<T> (in java.util) is a container that holds either one value or nothing. When a method returns Optional<Product>, the signature itself says: "there may be no product — deal with it".

ℹ️ orElse vs orElseGet orElse(createDefault()) always calls createDefault() — even when the value is present — because Java evaluates the argument before calling the method. orElseGet(() -> createDefault()) calls it only if empty. Use orElseGet when the default is expensive (database call, new object).

3.11 Why Optional matters in Spring Data

In topic 38 you will create repositories like interface ProductRepository extends JpaRepository<Product, Long>. Spring Data gives you findById for free, and it returns Optional<Product>. The pattern you will write in almost every service class is:

public ProductDto getProduct(Long id) {
    Product product = productRepository.findById(id)
            .orElseThrow(() -> new ResourceNotFoundException("Product " + id + " not found"));
    return mapper.toDto(product);
}

And a global exception handler (topic 35) turns ResourceNotFoundException into an HTTP 404 Not Found. Example06 in this folder builds a tiny fake repository so you can practise this exact pattern today.

6. Common mistakes

⚠️ Mistake: forgetting the terminal operation 
names.stream().filter(n -> n.startsWith("A")).map(String::toUpperCase);   // does NOTHING
Fix: end with a terminal operation: .toList(), .forEach(...), .count()…
⚠️ Mistake: reusing a stream 
Stream<String> s = names.stream();
long c = s.count();
List<String> l = s.toList();   // IllegalStateException: stream has already been operated upon or closed
Fix: create a new stream each time: names.stream() is cheap.
⚠️ Mistake: modifying the source or outside state inside the stream 
List<String> result = new ArrayList<>();
names.stream().filter(...).forEach(n -> result.add(n));   // works, but not the stream way
names.stream().forEach(n -> names.remove(n));             // ConcurrentModificationException!
Fix: let the stream build the result: List<String> result = names.stream().filter(...).toList(); To remove items from a list, use list.removeIf(predicate).
⚠️ Mistake: toMap with duplicate keys Throws IllegalStateException: Duplicate key. Fix: add a merge function, or use groupingBy if you actually want lists.
⚠️ Mistake: trying to add to the result of .toList() stream.toList().add(x) throws UnsupportedOperationException because the list is unmodifiable. Fix: collect(Collectors.toCollection(ArrayList::new)).
🚫 Mistake: calling optional.get() without checking repo.findById(99).get() throws NoSuchElementException — you just swapped a NullPointerException for another crash. Fix: orElseThrow(() -> new ProductNotFoundException(id)), orElse(...), or map(...).
⚠️ Mistake: misusing Optional
  • if (opt.isPresent()) { x = opt.get(); } else { x = "default"; } — just write opt.orElse("default").
  • Using Optional for fields, method parameters or collections (Optional<List<…>>). Optional is designed for return types. For collections return an empty list instead.
  • Returning null from a method declared to return Optional — return Optional.empty().
⚠️ Mistake: infinite streams without limit Stream.iterate(1, n -> n + 1).forEach(System.out::println) never stops. Fix: add .limit(10) or use the 3-argument iterate(seed, hasNext, next).

7. Best practices

  • One operation per line in a pipeline — easy to read, easy to debug.
  • Keep lambdas pure: filter and map should not change anything outside; they just compute.
  • Filter early: put filter before expensive map/sorted steps so less data flows through.
  • Use method references (Employee::getName) and Comparator.comparing for readability.
  • Don't force streams everywhere: a simple loop with break, or code that changes several variables, is often clearer as a loop.
  • Use primitive streams (mapToInt, mapToDouble) for numeric work.
  • Avoid parallel streams in web apps unless you have measured a real benefit.
  • Return Optional from "find" methods that may find nothing; never return null from them. Return empty collections instead of null or Optional for lists.
  • In Spring: filter, sort and paginate in the database (queries, Pageable) — not by loading all rows and streaming them in Java. Use streams for mapping and small in-memory work.
  • For money, real projects use BigDecimal rather than double (we use double here for simplicity).

8. Key takeaways

  • A stream is a pipeline: source → intermediate ops → one terminal op.
  • Streams are lazy (nothing runs until the terminal op), single-use, and don't modify the source.
  • filter keeps, map transforms, flatMap flattens, sorted/distinct/limit/skip shape the flow.
  • collect with Collectors builds lists, sets, maps, strings and grouped reports (groupingBy, partitioningBy, joining…).
  • reduce folds all elements into one value; count, min, max, anyMatch, findFirst answer questions.
  • Use IntStream/range for numbers; be careful with parallel streams.
  • Optional means "maybe a value". Use orElse, orElseGet, orElseThrow, map, ifPresent — avoid get().
  • Spring Data's findById returns Optional; the pattern findById(id).orElseThrow(...) will be everywhere in your services.

10. Interview questions

Q1. What is a stream? How is it different from a collection?

A stream is a sequence of elements supporting functional-style aggregate operations in a pipeline. Unlike a collection it doesn't store data, is lazily evaluated, can be consumed only once, uses internal iteration and never modifies its source. Collections are about storing data; streams are about computing with it.

Q2. Difference between intermediate and terminal operations?

Intermediate operations (filter, map, sorted…) return a new stream and are lazy — they don't execute until a terminal operation is invoked. Terminal operations (collect, forEach, reduce, count…) produce a result or side effect, trigger the whole pipeline and close the stream. Stateless intermediate ops (filter, map) process each element independently; stateful ones (sorted, distinct) need to see other elements.

Q3. map vs flatMap?

map transforms each element to exactly one element (Stream<T> → Stream<R>). flatMap transforms each element into a stream of zero or more elements and flattens all those streams into one (Stream<List<T>> → Stream<T>). Example: orders → all order items.

Q4. What does "lazy evaluation" mean in streams? Give an example of short-circuiting.

Intermediate operations are not executed when declared; the pipeline runs only when a terminal operation needs results, and elements flow one at a time through all stages. Short-circuiting operations can finish without processing all elements, e.g. filter(...).findFirst() stops at the first match, anyMatch stops at the first true, limit(n) stops after n elements — allowing even infinite streams to finish.

Q5. How do you group employees by department and get the average salary?

employees.stream().collect(Collectors.groupingBy(Employee::getDepartment, Collectors.averagingDouble(Employee::getSalary))) — returns Map<String, Double>. Use counting(), summingDouble(), mapping(), maxBy() as other downstream collectors.

Q6. groupingBy vs partitioningBy?

partitioningBy takes a Predicate and always produces a Map<Boolean, …> with exactly two keys, true and false (both present even if empty). groupingBy takes a classifier function and produces as many keys as there are distinct classifier values.

Q7. When should you NOT use parallel streams?

For small datasets (overhead dominates), when operations have side effects or use shared mutable state, when order matters, for I/O-bound tasks (blocking calls tie up the common ForkJoinPool), and generally inside web servers where requests are already concurrent and the common pool is shared by the whole JVM. Measure before using them.

Q8. What is Optional and why was it introduced?

Optional<T> is a container that may or may not hold a non-null value. It makes "no result" explicit in a method's return type, forcing callers to handle the empty case and reducing NullPointerExceptions. It is intended mainly as a return type — not for fields, parameters or collections.

Q9. orElse vs orElseGet vs orElseThrow?

orElse(value) returns the value or the given default; the default expression is always evaluated. orElseGet(supplier) calls the supplier only if empty — better for expensive defaults. orElseThrow() throws NoSuchElementException if empty; orElseThrow(supplier) throws your custom exception — the usual choice in Spring services (e.g. ResourceNotFoundException → 404).

Q10. Why does Spring Data JPA's findById return Optional?

Because an entity with that id might not exist. Returning Optional<T> instead of null documents this in the API and forces the service layer to decide what "not found" means — usually findById(id).orElseThrow(() -> new ResourceNotFoundException(...)) which a @RestControllerAdvice maps to HTTP 404.
