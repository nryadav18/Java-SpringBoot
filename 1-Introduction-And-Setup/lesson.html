1. Why this matters

Welcome! 👋 You are starting a journey that ends with you building real, enterprise-style backend applications with Java and Spring Boot — the same kind of software that runs banks, online shops, airline booking systems and food delivery apps.

Java is one of the most used programming languages in the world, and it has been for more than 25 years. Some places you will find it:

  • Banks and insurance companies — most of their backend systems are written in Java.
  • E-commerce — order systems, payment services, inventory services.
  • Android apps — Android was built on Java (Kotlin is also used now).
  • Big data tools — Hadoop, Kafka, Elasticsearch are written in Java (or run on the JVM).
  • Microservices — Spring Boot (the second half of this course) is the most popular way to build them in Java.

This first topic is about getting comfortable. Before you can build a house, you need to know your tools and where to stand. By the end of this page, you will have run three Java programs yourself and you will understand what really happens when you press "Run". Many developers with years of experience cannot explain that clearly — you will.

2. Real-life analogy

🍳 A recipe, a cook, and a translator

Think of a program as a recipe: a list of exact steps, in order. "Boil water. Add pasta. Wait 10 minutes." The computer is the cook. It is very fast and never gets tired, but it is not smart — it does exactly what the recipe says, nothing more.

There is one problem: the cook only understands its own machine language (zeros and ones), and every kitchen (Windows, Mac, Linux) has a slightly different cook. So Java uses a clever trick:

  • You write the recipe in Java (an English-like language).
  • The compiler (javac) translates it into a universal "kitchen language" called bytecode.
  • Every kitchen has a JVM — a translator standing next to the cook — who reads the bytecode and tells that cook what to do.

So you write the recipe once, and it can be cooked in any kitchen that has a JVM translator. That is the famous Java slogan: "Write once, run anywhere."

3. Concepts step by step

3.1 What is programming?

Programming means writing instructions that a computer can follow. These instructions are called code, and a complete set of instructions that does a job is called a program (or an application, or software).

Computers are fast, but they are literal. If you tell a person "get me some milk", they understand. A computer needs: "Walk to the fridge. Open the door. Find the bottle labelled milk. Pick it up. Close the door. Walk back." Programming is the skill of breaking a problem into small, exact steps.

A programming language is a language designed for writing those steps. It is stricter than English: one missing semicolon and the computer refuses to understand. Do not worry — you get used to it quickly, and the tools help you a lot.

3.2 What is Java?

Java is a programming language created by James Gosling and his team at Sun Microsystems, released in 1995. Today it is maintained by Oracle and the open-source community (OpenJDK). Key features:

FeatureWhat it means in simple words
Platform independentThe same compiled program runs on Windows, Mac and Linux.
Object-orientedYou model your program as "objects" like Customer, Order, BankAccount (Topics 6–8).
Strongly typedEvery variable has a fixed type (number, text…). Many mistakes are caught before the program runs.
Automatic memory managementA "garbage collector" cleans up memory you no longer use. You do not free memory by hand.
Huge ecosystemThousands of free libraries and frameworks (like Spring) so you do not reinvent the wheel.
Backward compatibleCode written 15 years ago usually still runs on new Java versions. Companies love this.
ℹ️ Java versionsJava gets a new version every 6 months. Every 2 years one version is marked LTS (Long-Term Support): 8, 11, 17, 21, 25. Companies mostly use LTS versions. In this course we use Java 17 (LTS) — very common in real jobs and fully supported by Spring Boot 3.

3.3 JDK vs JRE vs JVM

These three words confuse almost every beginner. Let's make them simple.

  • JVM — Java Virtual Machine. The "translator" that runs bytecode on your computer. It also manages memory and the garbage collector. There is a different JVM for each operating system — that's how the same bytecode works everywhere.
  • JRE — Java Runtime Environment. JVM + the standard library (ready-made classes like String, Scanner, Math). Everything you need to run a Java program.
  • JDK — Java Development Kit. JRE + developer tools: the compiler javac, the jar tool, the debugger and more. Everything you need to write and build Java programs. Developers install the JDK.
JVMJREJDK
Full nameJava Virtual MachineJava Runtime EnvironmentJava Development Kit

ℹ️ Good to knowSince Java 11, Oracle and most vendors no longer ship a separate JRE download — you simply install the JDK. But the concept is still asked in interviews, so learn the difference.

3.4 How Java code runs: source → bytecode → JVM

Here is the full journey of your code:

HelloWorld.java
source code (you write)→ javac
compiler→ HelloWorld.class
bytecode→ JVM
loads & runs→ Output
on screen
  1. You write source code in a file ending with .java. It is plain text — humans can read it.
  2. The compiler javac checks your code for mistakes (like grammar checking). If everything is fine, it creates a .class file.
  3. The .class file contains bytecode — instructions for the JVM, not for any specific computer. You cannot read it easily, and you do not need to.
  4. The JVM loads the bytecode, checks it is safe, and runs it. Frequently used parts are turned into fast machine code by the JIT (Just-In-Time) compiler while the program runs. That is why Java is both portable and fast.
💡 Compiled vs interpretedLanguages like C are compiled straight to machine code for one operating system. Languages like Python are read line by line by an interpreter. Java does both: compile once to bytecode, then the JVM interprets and JIT-compiles it. Best of both worlds.

3.6 JAVA_HOME and PATH on Windows (what they are)

When you type java in a terminal, how does Windows know where the program java.exe is? It uses environment variables — named settings that every program on your computer can read.

  • PATH — a list of folders. When you type a command, Windows searches these folders, one by one, for a matching program. The JDK's bin folder (which contains java.exe and javac.exe) must be on the PATH.
  • JAVA_HOME — points to the JDK's main folder (the one above bin). Tools like Maven, Spring Boot and VS Code read it to find "which Java should I use?".

Check them in PowerShell:

echo $env:JAVA_HOME
where.exe java
$env:Path -split ';' | Select-String -Pattern 'jdk|maven'

Typical output:

C:\Program Files\Eclipse Adoptium\jdk-17.0.19.10-hotspot\
C:\Program Files\Eclipse Adoptium\jdk-17.0.19.10-hotspot\bin\java.exe
C:\Program Files\Eclipse Adoptium\jdk-17.0.19.10-hotspot\bin
C:\tools\apache-maven-3.9.11\bin
ℹ️ If you ever need to set them (for a new computer)
  1. Press Win, type "environment variables", open Edit the system environment variables → Environment Variables…
  2. Under User variables click New…: name JAVA_HOME, value = your JDK folder, e.g. C:\Program Files\Eclipse Adoptium\jdk-17.0.19.10-hotspot
  3. Select Path → Edit → New → type %JAVA_HOME%\bin. Do the same for Maven's bin folder.
  4. Click OK everywhere and close and reopen every terminal and VS Code. Old windows keep the old values!
The Temurin installer usually does steps 2–3 for you if you tick "Set JAVA_HOME variable" during installation.

3.9 Two ways to run a Java program

Way 1 — the classic two-step way (compile, then run). This is what really happens under the hood:

javac Example01_HelloWorld.java      # step 1: compile → creates Example01_HelloWorld.class
java Example01_HelloWorld            # step 2: run the class (NO .java, NO .class at the end!)

Notice: javac takes a file name (with .java), but java takes a class name (without any extension).

To keep your folder clean, you can ask javac to put the .class files in another folder with -d, and tell java where to find them with -cp (class path):

javac -d out Example01_HelloWorld.java
java -cp out Example01_HelloWorld

Way 2 — single-file source launch (Java 11+). For a program in a single file, you can skip the compile step:

java Example01_HelloWorld.java

Java compiles the file in memory and runs it immediately. No .class file is created. This is perfect for learning, and it's the way we run all examples in Topics 1–18.

3.12 Reading input from the keyboard (Scanner)

Programs become interesting when they react to the user. Java's Scanner class reads what the user types.

import java.util.Scanner;              // 1. bring the Scanner class in

Scanner scanner = new Scanner(System.in); // 2. create a Scanner that listens to the keyboard
String name = scanner.nextLine();         // 3. read a whole line of text
int age = scanner.nextInt();              //    read a whole number
double price = scanner.nextDouble();      //    read a decimal number
scanner.close();                          // 4. close it when done
  • import — Java's standard library is organised in packages (like folders). Scanner lives in java.util. The import line says "I want to use it here". (Some classes, like String and System, are in java.lang, which is imported automatically.)
  • new Scanner(System.in) — creates a new Scanner object. System.in is the keyboard input (the opposite of System.out).
  • The program pauses at each next...() call and waits for the user to type and press Enter.
MethodReadsExample input

4.2 Example02_PrintingAndComments.java

The most interesting part is how + behaves:

Example02_PrintingAndComments.java (part)System.out.println("Sum: " + 2 + 3);      // Sum: 23
System.out.println("Sum: " + (2 + 3));    // Sum: 5
System.out.println(2 + 3 + " is the sum"); // 5 is the sum

Java reads + from left to right:

  • Line 1: "Sum: " + 2 → text + number = text "Sum: 2". Then "Sum: 2" + 3 → "Sum: 23". Surprise!
  • Line 2: brackets are calculated first: 2 + 3 = 5, then "Sum: " + 5 → "Sum: 5".
  • Line 3: 2 + 3 are both numbers → 5. Then 5 + " is the sum" → text.

Rule to remember: once a String joins the party, + means "glue", not "add". Use brackets when you want maths.

Example02_PrintingAndComments.java (part)System.out.printf("Student: %s, Age: %d, Fee: %.2f%n", "Asha", 21, 1500.5);

The placeholders are filled in order: %s ← "Asha", %d ← 21, %.2f ← 1500.5 shown as 1500.50. %n ends the line.

6. Common mistakes

❌ Mistake: 'java' is not recognized as an internal or external command Windows cannot find Java because the JDK's bin folder is not on the PATH.
Fix: Set JAVA_HOME and add %JAVA_HOME%\bin to Path (section 3.6), then close and reopen the terminal / VS Code.
⚠️ Mistake: class name does not match file name File Hello.java contains public class HelloWorld → error: class HelloWorld is public, should be declared in a file named HelloWorld.java.
Fix: Make them identical, including capital letters.
⚠️ Mistake: missing semicolon System.out.println("Hi") → error: ';' expected.
Fix: End every statement with ;. The error message shows the line number — go there.
⚠️ Mistake: wrong capital letters system.out.println or System.out.Println → error: package system does not exist / cannot find symbol.
Fix: Java is case-sensitive. It's System.out.println.
⚠️ Mistake: running with the wrong name java Example01_HelloWorld.class → Could not find or load main class Example01_HelloWorld.class.
Fix: After javac, run with the class name only: java Example01_HelloWorld. Or use single-file mode with .java.
⚠️ Mistake: misspelled main method public static void Main(String[] args) compiles, but running says error: can't find main(String[]) method in class.
Fix: Copy the main line exactly: public static void main(String[] args).
⚠️ Mistake: InputMismatchException with Scanner You typed twenty when nextInt() expected a number, or 1,62 instead of 1.62.
Fix: Type the right kind of value. (Topic 10 teaches you how to handle these errors gracefully.)
⚠️ Mistake: nextLine() after nextInt() returns empty text nextInt() reads the number but leaves the Enter key ("new line") behind. A following nextLine() reads that leftover empty line.
Fix: Call an extra scanner.nextLine(); after nextInt() to consume the leftover, or read everything with nextLine() and convert (Integer.parseInt(...), Topic 2). That's why our example asks for the name first.
⚠️ Mistake: smart quotes Copying code from Word or a chat app can turn " into “ ”. Java reports illegal character: '\u201c'.
Fix: Retype the quotes in VS Code.

7. Best practices

  • Use an LTS Java version (17 or 21) for real projects. Companies rarely use non-LTS versions.
  • Class names in PascalCase (HelloWorld, BankAccount): each word starts with a capital letter, no spaces.
  • Indent consistently with 4 spaces per level. Let VS Code format for you (Shift+Alt+F).
  • Comment the "why", not the obvious. i = i + 1; // add 1 to i is noise.
  • Read error messages from the top. The first error is usually the real one; later errors are often side effects.
  • Keep the build output separate from the source (javac -d out). Maven does this automatically with a target/ folder.
  • Close resources you open (like Scanner). Topic 10 shows the modern way: try-with-resources.
  • In real applications, don't use System.out for messages — use a logging library. You will learn this in Topic 30. For learning, println is perfect.

8. Key takeaways

  • A program is a list of exact instructions; Java is a popular, object-oriented, strongly-typed language created in 1995.
  • JVM runs bytecode; JRE = JVM + libraries; JDK = JRE + tools like javac. Developers install the JDK.
  • Flow: .java → javac → .class (bytecode) → JVM → output. Bytecode runs on any OS with a JVM: "write once, run anywhere".
  • java -version, javac -version, mvn -v check your setup; JAVA_HOME and PATH tell tools where Java is.
  • Every program needs a class and a public static void main(String[] args) method; the public class name must match the file name.
  • Run with java File.java (quick) or javac + java ClassName (classic).
  • print stays on the line, println ends it, printf formats; + with a String means "glue".
  • Three comment types: //, /* */, /** */ (Javadoc).
  • Scanner reads keyboard input: nextLine(), nextInt(), nextDouble().

10. Interview questions

Q1. What is the difference between JDK, JRE and JVM?

The JVM is the virtual machine that executes bytecode and manages memory (garbage collection, JIT compilation). The JRE is the JVM plus the standard class libraries — everything needed to run Java programs. The JDK is the JRE plus development tools like the compiler javac, jar, javadoc and the debugger — everything needed to develop Java programs. JDK ⊃ JRE ⊃ JVM.

Q2. Why is Java called platform independent?

Java source is compiled to bytecode, not to machine code for a specific OS. Each platform has its own JVM that understands the same bytecode. So the same .class file runs on Windows, Linux or macOS — "write once, run anywhere". Note: the JVM itself is platform-dependent; the bytecode is not.

Q3. What is bytecode?

Bytecode is the intermediate, platform-neutral instruction set produced by javac and stored in .class files. The JVM interprets it and the JIT compiler converts hot parts into native machine code at runtime for speed.

Q4. What is the JIT compiler?

The Just-In-Time compiler is part of the JVM. While the program runs, it detects frequently executed code ("hot spots") and compiles it into native machine code, so later executions are much faster than interpretation.

Q5. Explain public static void main(String[] args).

public so the JVM can access it from outside the class; static so it can be called without creating an object; void because it returns nothing; main is the name the JVM looks for as the entry point; String[] args holds command-line arguments.

Q6. Can we have more than one class in a single .java file?

Yes, but at most one of them can be public, and that public class's name must match the file name. Each class still compiles to its own .class file.

Q7. What happens if the main method is not static?

It compiles, but the classic launcher reports an error like "main method is not static". The JVM needs to call main without an instance of the class, so it must be static. (Java 21+ has preview features that relax this, but in Java 17 it is required.)

Q8. What is the purpose of JAVA_HOME and PATH?

PATH lets the operating system find executables like java and javac when you type them. JAVA_HOME points to the JDK installation folder; build tools (Maven, Gradle), IDEs and servers use it to locate the JDK.

Q9. Is Java compiled or interpreted?

Both. It is first compiled by javac into bytecode, and then the JVM interprets that bytecode and JIT-compiles hot code into native code at runtime.
